권수현님 commit 시점엔 `.vite-hooks/_/` 자동 생성 폴더가 미생성 → hook 미발동 → keycloak.py 위반 master 진입. 본인은 `pnpm install` 시 prepare script로 활성화 → 사후 발견. **개발자 ↔ 개발자 drift의 교과서적 케이스.** CI lint job이 유일한 강제 게이트.

### 환경 표준화 도구의 가치 — corepack
`package.json`의 `packageManager` 필드 + `corepack enable`로 모든 개발자가 동일 pnpm 버전 자동 사용. Node 16.10+ 표준 포함. 글로벌 설치 불필요. drift 차단의 핵심.

### PostgreSQL 트랜잭션 abort 함정 — 단위 테스트로 못 잡는 영역
Phase 2 1단계 후 dept-objects 500 디버그 중 발견. PostgreSQL은 한 번 SQL 에러 나면 같은 세션의 후속 쿼리를 모두 거부 (`InFailedSqlTransaction`). SQLAlchemy `try/except` fallback 사용 시 **except 첫 줄에 `db.session.rollback()` 필수**.
- 잠복 패턴: 단일 쿼리 service에선 rollback 누락해도 안 발현. **여러 쿼리 순차 호출** 또는 **except 안 fallback SQL** 시도 시 발현.
- 단위 테스트 mock 환경에선 트랜잭션 시뮬레이션 안 됨 → **통합 테스트로만 잡힘**.
- → **검증 도구는 결함 유형별로 다르다** (5/4 Generator-Evaluator 원칙 재확인). 단위 테스트만으론 안전 보장 안 됨.
- 갱신: H-DASH-04 보강 (rollback 명시), conventions.md Fallback 패턴 섹션 신설, [[4. 지식노트/PostgreSQL - InFailedSqlTransaction과 SQLAlchemy fallback 패턴]] 신규.

### Mock fixture는 idempotent SQL이 정답 (ON CONFLICT 패턴)
RBAC mock 1차 실행 시 dify 자동 ownership과 UNIQUE 충돌 → 트랜잭션 ROLLBACK. 원인:
- 본인이 5/6 오전 앱 11개 만들 때 권대리님 RBAC 코드 hook이 자동 INSERT (`owner=본인`, `visibility=private`)
- 우리 mock SQL과 같은 (tenant_id, resource_type, resource_id) UNIQUE 위반

해결: DELETE 후 재INSERT + ON CONFLICT 추가. 학습:
- **외부 영역 자동 동작 + 우리 mock 충돌 패턴**은 흔함 (다른 분 RBAC/audit 영역도 비슷할 수 있음)
- INSERT문 모두 ON CONFLICT DO UPDATE/NOTHING 박으면 idempotent → 재실행 안전
- DELETE 명령은 본인 tenant 한정 안전 (다른 워크스페이스 영향 0)

### PowerShell vs Bash redirect 차이
`<` (stdin redirect)는 PowerShell 5.1 미지원 (예약어). 대안:
- `Get-Content file.sql -Encoding UTF8 | docker compose exec -T ... psql` (한글 파일은 Encoding 명시 필수)
- `docker cp file.sql container:/tmp/ && docker exec ... psql -f /tmp/file.sql` (cross-platform 권장)
- `cmd /c "... < file.sql"` (bash 문법 그대로)

→ Cross-platform 스크립트는 docker cp + `-f` 패턴이 가장 안전. 이걸 README에 박는 게 표준.

## 배운 것

### 사이드바 구조 결정 과정 — D → G → α
- 처음엔 "관리 그룹 신설"(D) 가닥 → "Workspace 흡수 + Monitor sub-group"(G) → "통계·감사 별도 top-level"(α) 진화
- 핵심 통찰: **설정 도메인(워크스페이스) vs 조회 도메인(모니터링·통계·감사)**이 멘탈 모델상 분리되어야 자연
- "워크스페이스 단위" 같은 scope 라벨이 sub-group 이름으로 직관적이지 않음 — 별도 top-level이 명확

### "분석본 ROI 점검"의 가치
- B2(Monitor Analysis 분석) 원래 클러스터 계획에 있었지만 Option α로 grouping 변경 후 필요성 ↓
- C1(Get Started) 분석본도 매트릭스 비고가 이미 구체적이라 minimal로 충분
- → **계획 단계 산출물이 후속 결정으로 oversized가 될 수 있음**. 시점마다 ROI 재고 필요

### `<Card href>` 절대경로 강제 — 빌드 검증 우회 발견
- C1 작성 중 `Card.jsx` 래퍼가 raw `<a>` 렌더 → **Docusaurus broken link 검사 우회**
- "빌드 통과 = 링크 정상" 가정 깨짐 — 절대경로(`/use-spx-agent/...`)로 통일
- 마크다운 링크는 상대경로 OK (검증됨)
- → 빌드 통과가 모든 검증의 대용품은 아님. 컴포넌트별 동작 확인 필요

### i18n 파일 = UI 라벨 권위 출처
- 표준 한국어 번역 ≠ UI 실제 라벨 (예: "변수 인스펙터" vs UI "변수 검사")
- `web/i18n/ko-KR/*.json`이 권위 출처 — 챕터 작성 전 i18n grep으로 검증
- 글로서리는 i18n 검증 결과를 기록·재사용하는 사전 역할
- 충돌 시 **i18n 승** (글로서리 갱신)

### "데이터셋" vs "지식" — code label vs UI display의 layer 차이
- DB 테이블 `datasets` + 코드명 `dataset` (내부) → UI 표시명 "Knowledge"/"지식" (사용자)
- audit-meta.ts 작성자가 액션명을 그대로 한국어화하면서 layer 충돌 발생
- 옵션 (가) 매뉴얼 본문 혼용 안내로 절충 — 코드 수정(옵션 나)은 향후 작업

### "동시 작업 환경의 정합성 관리"
- 옵시디언(이 세션) + VSCode(Debug) + 터미널(분석본 갱신) 3곳 동시 작업
- `sidebars.js` 같은 공유 자원이 충돌 지점 → 분담·순차로 회피
- CLAUDE.md 같은 세션 시작 파일에 최신 사이드바 구조 박제하면 fresh 세션이 헷갈리지 않음

## 메모
- saas 사용자들 대상으로 dify가 만들어진 거니 폐쇄망 안에서 사용하는 관점이라 생각하기
- 마켓플레이스 없애기 : 들어있는 플러그인을 기업 환경에서 쓸 필요가 없음, 고객이 필요하다면 미리 소스를 심어둘 예정, 모델 제공자 설치도 사실상 필요 없음 (설치하는 인터넷이 외부 인터넷임, 그걸 불가능하다 보고 회사에서 쓸 수 있는 올라마나 vllm 정도 등으로 로컬 모델 사용한다는 배경이란 걸 가정), 그러나 고객이 어떤 모델 환경을 사용하는지 모르기 때문에 (상용 모델을 쓰는지, vllm 같은 로컬 서빙 환경인지) 모델 제공자 설치는 우선 냅두고 마켓플레이스/플러그인만 제거, 필요한 것만 미리 설치 받아서 내장 시킬 예정
- 외부 연결 다 빼기 (지식 생성에 있는 노션/웹 크롤링 연동, 앱 성능 추적시에 사용 되는 랭퓨즈 등)
- mcp는 사내/사외 관계없이 연동할 수 있으니 냅두기
- ci/cd는 개발 환경에만 있음 (이건 spx-agent를 개발/운영 환경 두 개를 띄울 때 개발 환경에서 만든 앱 등을 운영 환경으로 넘기는 ci/cd를 의미함, 아직 spx-agent에 있진 않음, 현재 다른 분이 작업 중)
- 문서는 개발/운영 환경 구분 없이 전체 사용자 대상으로 작성하기 (ci/cd처럼 개발 환경에만 있는 건 따로 표시)
- 사용자 관리는 spx-agent 기능으로 얘기하는데 키클록은 언급하지 않고 '사용자 관리나 부서 관리는 외부 시스템(예, 키클록)으로 관리한다 ', '사용자의 계정 관리는 관리 시스템에서 수행한다.' 등으로 간단하게 언급

## 배운 것

1. 데이터 적재 주기/시점

어제 부서 인원 정보와 권한 정보를 동일한 시점으로 가져오기 위해 두 테이블의 적재 시점이 일치하는지를 여쭤봤는데요, 

현재 개발 db에는 ccm0080은 n일에 한 번씩, ccm0081은 일배치로 전체 권한 목록 스냅샷이 누적되어 들어오고, 겹치는 일자가 하루밖에 없어 정확히 파악하기가 어렵습니다. (hh:mm:ss은 동일해서 추후에 일배치로 동일한 시점에 들어온다면 문제가 없지 않을까 예상됩니다.) 다만, 에이전트가 S-PLF 관리자에 의해 비정기적으로 실행되는 경우도 있어 해당 상황에는 다르게 적재 되는지 추가로 확인해야 될 듯 합니다.

```
=> 지금 들어오는 데이터가 운영 데이터임, 일배치가 맞고 비정기 실행 때 추가로 들어오는 건 없음, 다만 80은 매일 들어와서 누적되는 게 맞는지 질문 예정
```


2. '전일 to-be 부서원' 조회 불확실

ccm0080은 부서 이동자(data_cat=10)와 해당 인원들의 to-be 부서, as-is 부서 인원 정보만 포함되어 있어 '전일 to-be 부서원' 정보를 반영하기에는 부족합니다. 현재는 금일 부서 이동자의 to-be 부서가 전일 부서 이동자의 as-is/to-be 부서에 있어야지만 '전일 to-be 부서원'을 알 수 있는 상태입니다.

```
=> 매일 누적되어 부서 이동 정보가 남아있으므로 이전 데이터 조회해서 전일 부서원 정보 조회할 수 있음, 다만 1번에서 얘기한 것처럼 누적되는지 확인 필요, 현재 이 데이터로 case#1, 2가 동작 중이기 때문에 가능할 것으로 보임
```


3. 데이터 확인 필요

- 부서 이동자가 이미 to-be 부서에 있어 (data_cat=10인 사람이 data_cat=20에도 나타남) 금일 to-be 부서원이 모두 있는 것으로 조회돼 case#2 가 없는 것으로 보입니다. 데이터 이상인지, 아니면 금일 to-be 부서원을 조회할 때 본인을 제외해야 되는건지 궁금합니다.

```
=> 10의 부서가 20, 30에 다 나와야 됨, 10/30만 있으면 퇴사, 10/20만 있으면 신규, 금일 to-be 부서원 조회할 때 본인 제외하는 게 맞음, 참고로 퇴사/신규는 설계서엔 없으나 추후에 들어올 거 같다는 예상 중, 참고로 30은 금일 이전 부서원이 아닌 전일 이전 부서원이 들어옴
```

- 일반 사용자로 전환된 경우가 없어 (ccm0080.general_role_yn이 모두 null값) case#3 이 없습니다.

```
=> 일반 사용자 없는 게 맞음, 현재 운영 데이터가 들어오는데 general_role_yn은 이번에 추가된 컬럼이고 아직 해당 케이스가 없는 거임
```

- 계정/권한? 사용 여부가 모두 y 인데 (ccm081.use_yn = y) n인 경우도 있는지, 있다면 권한 조회 시 반영해야 되는지 궁금합니다.

```
=> 이것도 대부분 y일 것이라 판단됨, 보통 권한에 yn 표시를 해두지는 않아 정확히 어떤 것을 의미하는지는 모르나 y만 가져와서 처리하는 게 맞을 것으로 보임
```


추가로, gateway.if_ai_user_auth_group 테이블은 데이터가 없어 확인할 게 없었으나 upsert 하기 위한 PK나 unique 컬럼/인덱스가 없어 어떻게 해야 되는지 확인하고 싶습니다.

```
=> pk가 없는 게 맞고 추가 요청 예정, 현재로선 전체 데이터 새로 추가하는 방향으로 가는 게 맞을 듯함, 추가로 여기서의 use_yn은 추가/삭제 플래그로 보임, gateway에 삭제할 권한 목록 줘야 함(기존 권한)
```

## 배운 것
- [[Dify - db_client_node UNION 쿼리 Invalid operation type 에러]] — Dify의 spance/db_client_node 플러그인이 sqlglot AST 루트 클래스만 보고 DML 타입을 판별해서, 최상위 `UNION`/`INTERSECT`/`EXCEPT`를 `Invalid operation type`으로 거부함. 서브쿼리로 감싸면 우회 가능
- [[PostgreSQL - search_path와 schema 네임스페이스]] — PostgreSQL의 schema = 네임스페이스, search_path = 스키마 검색 PATH. `ALTER ROLE ... SET search_path TO agent_demo, public`으로 사용자에 박아두면 prefix 생략 가능. 단 공유 DB user면 사이드이펙트 주의
- **LLM Instruction은 위치가 곧 attention** — gpt-oss-120b 같은 오픈/소형 모델은 instruction 끝부분 룰을 잘 무시함. 강제할 행동 규칙은 instruction 앞쪽으로 올리고, 긴 reference 데이터(스키마/예시)는 뒤로 밀어야 함
- [[Dify - 멀티턴 Agent 출력 wrapper 선택 전략]] — 멀티턴 function calling agent의 `agent_text`엔 JSON wrapper가 여러 개 섞여 나옴. `max(wrappers, key=row_count)` 휴리스틱은 사전 탐색 쿼리(DISTINCT 등)가 진짜 답보다 row 많을 때 깨짐. 정답은 **last valid wrapper** — agent의 최종 답은 항상 마지막 emit이라는 invariant를 활용

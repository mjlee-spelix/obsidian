### 프론트 로컬 개발환경 세팅 (web 수정사항 확인)

**타임라인**
1. `pnpm dev`(Next.js 개발서버, :3000)로 먼저 시도 → 백엔드가 Docker에 있어서 `localhost:5001` API 호출 필요
2. Docker의 api 서비스에 포트 매핑이 없어서(`5001/tcp`만 컨테이너 내부 노출) 호스트에서 접근 불가 → `docker-compose.yaml` api 서비스에 `ports: "${EXPOSE_API_PORT:-5001}:${DIFY_PORT:-5001}"` 추가
3. 포트 열었지만 API가 unhealthy — `WORKER TIMEOUT → SIGKILL` 반복. 원인: 브라우저에서 signin 페이지 반복 접속 → 요청 폭주 → 워커 과부하 → 타임아웃 → 새 워커 부팅 → 또 폭주 악순환
4. `pnpm dev` 자체도 `Compiling /apps ...`에서 수 분간 멈춤 (Docker + Next.js 동시 실행으로 리소스 부족)
5. 결론: **`pnpm dev` 포기, Docker로 전부 띄우기로 결정**

**docker-compose.yaml 수정사항**
- `api` 서비스: `ports` 추가 (로컬 개발 시 직접 API 호출용, nginx 없이도 접근 가능)
- `web` 서비스: `build: { context: ../, dockerfile: web/Dockerfile }` 추가 — 기존엔 공식 이미지(`langgenius/dify-web:1.13.3`)만 사용해서 로컬 코드 수정이 반영 안 됐음

**실행 방법**
```bash
cd docker
docker compose up -d --build web nginx
# 1~2분 대기 후 localhost:80 접속 (워커 초기화 전에 접속하면 과부하 발생)
```

**API unhealthy 문제 해결**
- 브라우저 탭 전부 닫고 `docker compose restart api` → 1~2분 대기 후 접속하면 정상
- 원래 구조: 브라우저 → nginx(:80) → api(:5001)/web(:3000) 내부 라우팅이라 포트 노출 불필요했음. 포트 추가해도 컨테이너 간 통신에는 영향 없음

### 환경 불일치 결함 2종 (Phase B 핵심 시그널)
- **1: URL state 불가** — 클로드가 계획 단계에서 자발적으로 발견. 대시보드가 설정 모달 탭으로 마운트되니 `useSearchParams`/`router.push` 안 됨. spec은 "URL query string 단일 진실" 가정했는데 실제 환경 다름. → React state로 전환, spec에 `mount_environment` 필드 도입
- **2: 이중 제목** — 1차 구현 후 이미지 1:1 대조에서 발견. 모달이 `activeItem.name`을 자동 렌더 → 우리가 만든 `<h1>`와 충돌. → 컴포넌트 명/책임 재정리 (`dashboard-header` → `dashboard-controls`, 제목 미포함, 컨트롤만 모달 헤더 우측 슬롯에 삽입 — PROVIDER 탭 SearchInput 패턴 따름)
- 공통 패턴: **spec이 가정한 환경 ≠ 실제 마운트 환경**. 코드 수준에서 검증해야만 발견. 옵시디언 spec만으론 못 잡음.

### Windows 폴더 동기화 — Junction 채택
- 어제 만든 `.claude/` 심볼릭 링크는 관리자 권한 필요했음
- 오늘 `images/` 동기화는 일반 권한 PowerShell에서 즉시 필요 → **Junction 사용** (관리자 권한 불필요, 같은 볼륨 한정)
- 동작은 SymbolicLink와 동일 (OS 수준 폴더 인식)
- 지식노트 보강: [[4. 지식노트/Windows - 심볼릭 링크로 폴더 동기화]]

### Docker 빌드 환경 트러블슈팅
- web 빌드 실패: `docker/volumes/` 안의 Linux symlink(`lib64 -> lib`)가 Windows에서 깨진 링크로 보임 → BuildKit 컨텍스트 스캔 실패
- `.dockerignore`는 스캔 후 적용이라 깨진 링크는 ignore에 적혀있어도 폭발
- 해결: 깨진 symlink 삭제 + `.dockerignore`에 `docker/volumes/` 패턴 + `.claude` 추가
- → `.claude` 폴더는 어제 SymbolicLink 만들 때 같이 박았어야 했음 (작은 누락)

### 1차 빌드 후 화면 미반영 — Docker 캐시
- 코드 변경했는데 화면이 1차 그대로 → Docker 레이어 캐시가 이전 코드 유지
- 해결: `docker compose build --no-cache web` (5~10분 소요)
- 학습: `--build`만으론 부족할 수 있음. 큰 구조 변경 시 `--no-cache` 또는 캐시 의도 의심

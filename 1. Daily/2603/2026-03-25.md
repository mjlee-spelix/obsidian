## 배운 것
- ## Dify (디파이) 요약 및 가이드

Dify는 **LLM 애플리케이션 프레임워크**로, 주로 챗봇이나 에이전트 내에서 데이터를 시각화하는 데 초점이 맞춰져 있습니다.

## 1. 환경 문제 (Environment & Runtime)

- **샌드박스 격리:** 코드 노드(JavaScript/Python)는 보안을 위해 서버의 격리된 환경에서 실행됩니다.
    
- **라이브러리 부재:** 브라우저용 라이브러리인 `Chart.js`를 직접 `import`할 수 없습니다. 서버 환경에는 캔버스(Canvas)나 윈도우(Window) 객체가 없기 때문입니다.
    
- **해결책:** 직접 렌더링 대신, 차트의 **설정 값(JSON)**만 생성하거나 **외부 API(QuickChart 등)**를 호출하는 방식을 사용해야 합니다.
    

## 2. 시각화 구현 (Visualization)

- **QuickChart API 방식 (가장 추천):**
    
    - 코드 노드에서 차트 설정을 `JSON`으로 만든 후, `encodeURIComponent`를 사용해 URL을 생성합니다.
        
    - 답변 노드에서 마크다운 `![그래프]({{url}})` 형식을 사용하여 즉시 이미지를 출력합니다.
        
- **플러그인 방식 (Marketplace):**
    
    - `Digitforce Data Analysis` 같은 플러그인을 사용하여 자연어 질문으로 차트를 자동 생성합니다.
        
    - 내부적으로는 구조화된 데이터(JSON)를 브라우저가 해석하여 인터랙티브한 차트로 보여줍니다.
        
- **Base64 파일 변환:** * `base64_codec` 플러그인을 활용해 생성된 이미지 데이터를 실제 파일 객체로 만들어 대화창에 파일로 첨부할 수 있습니다.
## n8n 요약 및 가이드

n8n은 **워크플로우 자동화 도구**로, 데이터의 흐름(Items)과 노드 간의 규격을 맞추는 것이 핵심입니다.

## 1. 환경 문제 (Environment & Runtime)

- **데이터 규격 오류:** 코드 노드 실행 시 반드시 **객체의 배열 `[{ "json": { ... } }]`** 형태를 반환해야 합니다. 단일 객체를 반환하면 `Code doesn't return items properly` 에러가 발생합니다.
    
- **Python Runner 부재:** Self-hosted(Docker 등) 환경에서 Python 노드를 쓰려면 컨테이너 안에 Python 3가 설치되어 있어야 합니다.
    
- **CommonJS 제약:** 최신 버전 n8n이 아니면 `import` 문법 대신 `require`를 써야 하거나, 외부 모듈 호출을 위해 환경 변수(`NODE_FUNCTION_ALLOW_EXTERNAL`) 설정이 필요합니다.
    

## 2. 시각화 구현 (Visualization)

- **배열 기반 데이터 가공:**
    
    - 여러 행의 데이터를 하나의 차트로 묶으려면 `items`를 루프 돌며 `labels`와 `data` 배열로 재조립하는 과정이 필요합니다.
        
- **이미지 처리:**
    
    - `HTTP Request` 노드를 이용해 외부 차트 엔진에서 생성된 이미지를 바이너리(Binary) 데이터로 가져옵니다.
        
    - 이를 이메일 첨부, Slack 전송, 혹은 Google Drive 저장 등 다음 자동화 단계로 연결합니다.
        
- **인터랙티브 제약:**
    
    - n8n UI 자체는 차트 렌더링 도구가 아니므로, 최종 결과물은 주로 이미지 파일이나 HTML 리포트 형태가 됩니다.

확인하신 대로, **Dify Cloud** 환경의 코드 노드는 보안과 성능상의 이유로 `matplotlib`이나 `pandas` 같은 무거운 데이터 분석 라이브러리를 기본적으로 제공하지 않습니다. 주로 `json`, `time`, `re` 등 파이썬 표준 라이브러리 위주로 구성되어 있습니다.

**Self-hosted(로컬 설치)** 환경에서는 해결이 가능합니다. 다만 단순히 패키지만 설치하는 것이 아니라, Dify의 코드 실행 환경인 **Sandbox 서비스**를 직접 수정해야 합니다.

## 1. Self-hosted에서 matplotlib 사용 설정 방법

Dify의 코드 노드는 별도의 Docker 컨테이너(`dify-sandbox`) 안에서 실행됩니다. 따라서 이 컨테이너 안에 라이브러리가 설치되어 있어야 합니다.

## 방법 A: Docker Compose 환경 변수 수정 (가장 권장)

Dify 소스 코드를 내려받아 설치하셨다면, `docker-compose.yaml` 파일 내의 `sandbox` 서비스 설정에 라이브러리를 추가할 수 있습니다.

1. `docker-compose.yaml` 파일을 엽니다.
    
2. `sandbox` 서비스의 `environment` 섹션을 찾습니다.
    
3. `PYTHONPATH` 혹은 라이브러리 설치 경로를 확인하거나, 필요시 커스텀 이미지를 빌드해야 합니다.
    
    - **Tip:** 최신 버전의 Dify Sandbox는 내부적으로 `pip install`을 허용하지 않는 경우가 많으므로, 아래와 같이 **Docker필드**를 수정하여 이미지를 다시 빌드하는 것이 확실합니다.
        

## 방법 B: Sandbox Dockerfile 수정 및 빌드

`dify/api/core/external_resource/sandbox/python/` 경로(버전마다 상이할 수 있음)에 있는 `Dockerfile`에 다음 줄을 추가합니다.

Dockerfile

```
RUN pip install matplotlib numpy pandas
```

그 후 `docker-compose build sandbox` 명령어로 다시 빌드하고 실행하면 코드 노드에서 `import matplotlib`이 정상 작동합니다.

## 2. 'Files' 출력 타입이 없을 때의 우회 전략

Dify 버전(특히 구버전)에 따라 코드 노드의 출력 타입에 `File`이 없을 수 있습니다. 이 경우 **String(문자열)** 타입을 활용해 이미지를 전달해야 합니다.

1. **변수 흐름:** `코드 노드(String 반환)` → `LLM 노드` 또는 `HTTP Request 노드`.
    
2. **형식:** 앞서 설명드린 **Base64** 데이터 문자열(`data:image/png;base64,...`)을 통째로 넘깁니다.
    
3. **출력:** 최종 응답 노드(Answer)에서 다음과 같이 작성하면 사용자에게 이미지가 보입니다.
    
    - `![차트 이미지]({{코드노드_결과_변수}})`

혹시 Docker 환경 설정을 변경하는 과정에서 도움이 필요하신가요? 구체적인 설치 환경(OS 등)을 알려주시면 상세 명령어를 안내해 드릴 수 있습니다.

Dify나 소프트웨어 개발에서 말하는 **샌드박스(Sandbox)**는 아이들이 다치지 않고 안전하게 모래놀이를 할 수 있는 '모래통'에서 유래한 용어입니다.

컴퓨터 공학에서의 샌드박스는 **"외부와 격리된 안전한 실행 환경"**을 의미합니다. Dify의 코드 노드에 이 개념이 왜 중요한지 핵심 위주로 설명해 드릴게요.

## 1. 샌드박스의 핵심 역할: "격리와 보호"

사용자가 작성한 파이썬 코드가 Dify 시스템 전체(서버, DB 등)에 영향을 주지 않도록 가두어 두는 역할을 합니다.

- **시스템 보호:** 만약 사용자가 코드 노드에 `os.remove('/')` 같은 서버의 모든 파일을 지우는 명령어를 넣더라도, 샌드박스라는 가상 공간 안에서만 실행되므로 실제 Dify 서버는 안전합니다.
    
- **자원 제한:** 특정 코드가 무한 루프에 빠져 CPU나 메모리를 독차지하지 못하도록 샌드박스가 사용량을 제한합니다.
    
- **보안:** 해킹 코드나 악성 스크립트가 샌드박스 담장을 넘어 외부 네트워크로 나가는 것을 차단합니다.

## 2. 왜 matplotlib 설치가 안 되었나?

샌드박스는 기본적으로 **'최소한의 기능'**만 갖춘 아주 가벼운 상태로 유지됩니다.

- **Dify Cloud의 경우:** 보안을 위해 외부 라이브러리 설치를 막아두고, 표준 라이브러리만 들어있는 '깨끗한 샌드박스'를 제공합니다. 그래서 `matplotlib`이 없다는 에러가 뜬 것입니다.
    
- **Self-hosted의 경우:** 이 샌드박스는 보통 **Docker 컨테이너** 형태로 돌아갑니다. 주인이 직접 샌드박스 설계도(Dockerfile)를 수정해서 `matplotlib`이라는 도구를 미리 넣어두면, 그때부터 코드 노드에서 해당 라이브러리를 쓸 수 있게 됩니다.

현재 **Docker를 통해 직접 서버를 운영 중이신가요?** 그렇다면 `docker-compose.yaml` 파일을 수정하는 구체적인 방법을 안내해 드릴 수 있습니다.

**Base64**는 8비트 이진 데이터(Binary Data, 예: 이미지나 실행 파일)를 **64개의 출력 가능한 ASCII 문자**로 바꾸는 인코딩 방식입니다.

쉽게 말해, **"컴퓨터만 이해하는 복잡한 데이터(0과 1)를 사람이 읽을 수 있는 텍스트 형식으로 안전하게 포장하는 방법"**이라고 생각하시면 됩니다.

---

## 1. 왜 Base64를 쓰나요? (핵심 이유)

네트워크를 통해 데이터를 주고받을 때, 시스템마다 문자를 처리하는 방식이 달라 데이터가 깨지는 경우가 발생합니다. 특히 이미지는 텍스트가 아니기 때문에 그대로 보내면 중간에 데이터가 손실될 위험이 큽니다.

- **안전성:** 64개의 공통 문자(영문 대소문자, 숫자, `+`, `/`)만 사용하므로 어떤 시스템에서도 데이터가 왜곡되지 않고 전달됩니다.
    
- **통합:** 별도의 이미지 파일 없이, **텍스트 문서(HTML, JSON, XML 등) 안에 이미지 데이터를 직접** 집어넣을 수 있습니다.
    

---

## 2. 어떻게 작동하나요?

Base64는 데이터를 6비트씩 쪼개서 아래 표의 문자로 매핑합니다.

|**구분**|**포함되는 문자**|
|---|---|
|**알파벳**|A-Z (26개), a-z (26개)|
|**숫자**|0-9 (10개)|
|**기호**|`+`, `/` (2개)|
|**패딩**|`=` (데이터 길이를 맞추기 위해 끝에 붙임)|

## 3. Dify 코드 노드에서 왜 필요했나?

Dify의 코드 노드가 이미지 파일 자체를 결과값으로 뱉어내지 못할 때, **"이미지를 아주 긴 텍스트 문장으로 변환"**해서 전달하기 위해 사용합니다.

- **원본:** `chart.png` (이미지 파일)
    
- **Base64 변환 후:** `iVBORw0KGgoAAAANSUhEUgAA...` (매우 긴 문자열)
    
- **HTML/마크다운 활용:** 이 문자열 앞에 `data:image/png;base64,`를 붙여주면 브라우저가 "아, 이 텍스트는 사실 이미지구나!"라고 이해하고 그림으로 보여줍니다.
    

---

## 4. 장점과 단점

- **장점:** 이미지 파일을 따로 관리할 필요가 없어 전송이 간편합니다.
    
- **단점:** 텍스트로 바꾸는 과정에서 용량이 원본보다 **약 33% 정도 커집니다.** (파일이 너무 크면 효율이 떨어짐)
    

---

**확실하지 않습니다:** Dify 특정 버전에서는 Base64 문자열의 길이가 너무 길면 노드 간 데이터 전달 시 메모리 초과가 발생할 수 있습니다. 차트의 해상도를 적절히 조절하는 것이 좋습니다.

Dify에서 이 Base64 문자열을 실제 이미지로 화면에 띄우는 **마크다운(Markdown) 문법** 예시가 필요하신가요?

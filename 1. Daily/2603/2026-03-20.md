스크린샷을 보면 모델이 **텍스트로는** "Let's call get_schema_list"라고 하면서 **실제 tool call은** `execute_sql`을 호출하고 있습니다. `undefined`가 SQL로 들어가서 에러가 난 거예요.

### 이건 프롬프트 문제가 아닙니다

모델(`gpt-oss:latest`)의 **tool call 바인딩 오류**입니다. 모델의 reasoning 텍스트와 실제 function call이 불일치하는 현상으로, 소형 모델에서 자주 발생합니다.

### 가능한 원인

|원인|설명|
|---|---|
|**모델 버전 변경**|`gpt-oss:latest`가 자동 업데이트되면서 tool-use 성능이 변한 경우|
|**tool 수 과다**|연결된 tool이 많으면 소형 모델이 tool 선택을 혼동|
|**Simple Memory 오염**|이전 대화 메모리에 잘못된 패턴이 남아있는 경우|

### 확인/해결 방법

1. **세션 초기화**: Chat에서 새 세션 시작 (이전 메모리 오염 제거)
2. **모델 확인**: `gpt-oss:latest`가 어떤 모델인지 확인 — `ollama list`로 실제 모델/버전 체크
3. **tool 수 줄이기**: 테스트 시 `create_chart`, `create_sheet` 등을 잠시 연결 해제하고 `get_schema_list`, `get_table_list`, `get_columns`, `execute_sql`만 남겨서 테스트
4. **재현 확인**: 같은 질문을 다시 보내봐서 매번 그런지, 간헐적인지 확인

조건 분리 안하고 이 토글만 켜니까 되더라고? 이유가 뭐지?

n8n의 expression 평가 방식 때문입니다.

`=! {{ $json.output.chart }} && {{ $json.output.send_email }}` 이 표현식은:

1. `{{ }}` 안의 값이 먼저 치환됨 → `! true && true` (문자열)
2. `!`와 `&&`는 `{{ }}` 바깥이라 **연산자가 아닌 문자열 리터럴**로 남음

**토글 OFF**: 결과가 문자열 `"! true && true"` → boolean 기대하는데 string이 왔다 → 타입 에러

**토글 ON**: 문자열 `"! true && true"`를 boolean으로 **강제 변환** 시도 → JS 표현식으로 평가 → `!true && true` = `false` ← 정상 동작

결국 토글이 문자열을 JS 표현식으로 재평가해주는 셈입니다.

다만 이건 n8n의 내부 타입 변환에 의존하는 거라, 확실하게 하려면 단일 `{{ }}` 안에 전부 넣는 게 안전합니다:

```
={{ !$json.output.chart && $json.output.send_email }}
```

이러면 토글 없이도 boolean이 바로 반환됩니다.

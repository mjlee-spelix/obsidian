## 배운 것
- **모델은 워크플로우 런이 아니라 LLM 노드에 있다** — `workflow_node_executions.process_data`의 `model_provider`/`model_name`. 모델 보유 노드 3종: `llm`/`question-classifier`/`parameter-extractor`.
- **현재 차트 '미분류' = 챗플로우(advanced-chat)** — 워크플로우가 아님. 챗플로우 message는 모델이 NULL로 생성되고(`message_based_app_generator.py:140-144`) 토큰은 노드 합으로 채워짐. 순수 워크플로우는 message가 없어 차트에서 아예 누락.
- **합 보존은 중첩(iteration/loop)이 있어도 성립** — 내부 노드는 서브엔진에서 돌고 롤업 1회만 부모에 누적 → 모델 노드 각 1회. `message.totalTokens == Σ 노드 토큰`.
- **Prisma collector BigInt 함정** — bigint 컬럼을 `$queryRaw`로 직접 읽으면 JS BigInt → Prisma JSON 직렬화 실패. 토큰은 process_data.usage(JSON number)에서 뽑아 회피.
- **entrypoint self-heal 하드코딩 리스트** — `dify-audit/scripts/entrypoint.sh`가 mart 누락 시 고정 리스트만 재적용. 새 마이그레이션을 여기 추가 안 하면 옛 정의로 조용히 회귀.
- **drift 게이트** — design.md § 2.5.4 DDL과 실제 마트가 1:1 정합이어야 함. 마이그레이션과 design 갱신은 같은 PR (H-DOC-01).
- **운영 provider는 namespaced** — `langgenius/ollama/ollama`, `yangyaofei/vllm/vllm`(서드파티) 형식. `LOCAL_PROVIDERS` bare 매칭(`{"ollama",...}`)은 운영에선 **라벨 0건**(ollama조차). 정규화(마지막 `/` 세그먼트)+`vllm` 추가 필요. **시드·테스트가 bare라 green이지만 운영 버그 못 잡는 맹점.**
- **XX001 `could not read block 0`** = 스토리지/물리 손상 (SQL로는 못 만듦) → 앱 작업 무관. 디스크풀(20%)·dmesg I/O·리부팅·OOM 전부 배제로 우리 작업 탓 아님 확인. `pg_class` 같은 OID 중복 = 시스템 카탈로그 손상. **재시작으로 안 고쳐짐**(파일 레벨).

### 🚀 Jenkins 배포 (194 서버) 절차 정리
- 배포는 **commit 아니라 `v1.x.y` 태그 기준**. master fast-forward 머지 → 태그 생성 → **master+태그 같이 push** → Jenkins "파라미터와 함께 빌드"에서 `DEPLOY_REF`=태그 명시 선택.
- 함정: `DEPLOY_REF` 빈 값이면 옛 commit으로 빌드 / 태그만 만들고 master push 누락 시 옛 commit 가리킴.
- `DEPLOY_MODE`: `recreate`(코드만) vs `full-restart`(DB 마이그레이션·네트워크 변경 시).

## 배운 것

### audit 시스템은 별도 컨테이너 (`dify-audit`) — 테이블만 가져와도 무용지물 ⭐
- audit 운영 = 3가지 한 세트: ① `dify-audit` 컨테이너(별도 Next.js) ② DB audit 스키마+트리거+audit_writer 사용자 ③ .env keycloak/audit 키
- "테이블만 가져오기"는 의미 X — collector 컨테이너 없으면 이벤트 0건
- RBAC vs audit 합치기 무게 차이: RBAC는 git pull+빌드 끝, audit은 git merge + 코드 conflict + DB reset + alembic merge heads + .env 갱신 등 5배 일

### 환경 함정 가족 — 오늘 만난 5종
1. **`docker-compose.yaml`의 image 하드코딩** — 본인 빌드 무시됨. `spx-build.ps1`이 평소 자동 처리하지만 keycloak-auth 같은 다른 브랜치엔 스크립트 없음 → 수동 `docker tag` 필요
2. **컨테이너 안 폴더 잔존** — `docker compose cp` 시 같은 이름 폴더 있으면 동작 미묘. **`rm -rf /tmp/seed` 선행 후 cp** 필요
3. **TRUNCATE multi-table** — 존재하지 않는 테이블 한 개만 끼면 statement 전체 abort. 한 줄씩 분리 안전
4. **mock fixture 재적용** — `gen_random_uuid()` ID로 ON CONFLICT 무용지물. 4번 재적용 → 4배 누적. 결정적 ID 패턴 필수
5. **PowerShell `Get-Content | docker exec` 인코딩** — pipe로 SQL 흘려넣으면 줄바꿈 split. `cp` + `psql -f` 또는 `Get-Content -Raw` 사용

→ 5종 다 "**호스트 ↔ 컨테이너 ↔ DB 3자 동기화**" 가족. defect-catalog 보강 후보.

### Plugin auto-upgrade `DetachedInstanceError` 4차 재발 ⭐
- 어제 3/3 + 오늘 1차 = **누적 4회**. DB reset 직후 첫 로그인 시 `/console/api/workspaces/current/plugin/preferences/fetch` 발동
- 옵션 C(upstream 대기) 유지 어려움 → **옵션 B(임시 hot-fix) 진지 검토 시점**

### 컨테이너 healthcheck 무시 가능한 경우
- `dify-audit` (unhealthy 14회) / `keycloak` (unhealthy 17회) — 둘 다 실제로 정상 작동
- 판단 기준: 컨테이너 로그에 정상 부팅 메시지 있으면 healthcheck unhealthy 무시

### `resource_ownership` NOT NULL 컬럼 4개 함정
- `id` / `tenant_id` / `visibility_scope` / `created_by` 모두 NOT NULL
- `visibility_scope`는 `department`(부서 소속) / `private`(개인) — 우리 환경 분포 10:3
- VSCode Claude도 빠뜨릴 수 있음 → fixture 작성 prompt에 NOT NULL 명시 의무화

### `messages` collector는 풍부, `workflow-runs` collector는 빈약 ⭐
- `messages.ts` details: model/token/error/invokeFrom/totalPrice 등 14필드 — OLTP 거의 완벽 보존
- `workflow-runs.ts` details: 5필드만 — **`triggered_from`/`invoke_from`/`total_price` 누락**
- 일관성 결함: `workflow-nodes.ts`엔 `triggeredFrom` 박혀있는데 `workflow-runs.ts`엔 빠진 비대칭

## 배운 것

### Keycloak 토큰 정합 (P1 배포 검증 사전 작업)
- Access Token(짧음·매 요청 사용) vs Refresh Token(김·재발급 전용)의 분리 사유: 보안 표면 vs UX 절충
- `.env`의 `REFRESH_TOKEN_EXPIRE_DAYS`는 쿠키 Max-Age (브라우저 보관), JWT의 `exp`는 KC가 발급 시 박는 값 → 두 개 정합 안 맞으면 무의미
- KC 계층 규칙: Client에서 lifespan을 realm 상한보다 늘리려고 하면 `invalid_input` 에러. 단축만 가능, 증액은 realm 단위에서만 (= realm 공유 client 전체 영향)
- 옵션 3 채택 사유: realm SSO Session Idle 2시간(기본 30분이 아님) → 데모 UX 양호 → realm 안 건드림 + Client Session Max 8시간만 별도 설정

### spx-agent-docs (Mintlify · CC BY 4.0 · Orphan)
- Mintlify CLI는 로컬 미리보기 전용 — 정적 빌드 명령 부재 → SaaS Cloud가 자체 호스팅 표준 흐름. 사내 자체 호스팅 필요 시 Docusaurus 변환 고려
- dify-docs 버전 태깅 정책: 마이너만(`v1.13.0`, `v1.14.0`). 패치(`v1.13.1~3`) 시점 docs는 별도 태그 없이 일괄 sync 커밋으로 표현 → `git log v1.13.0..v1.14.0` 에서 명시 커밋 찾는 방식
- Git orphan 브랜치: 단일 root로 시작, 이전 히스토리는 reflog에서 90일 복구 가능. upstream sync 포기 결정 시 적합
- CC BY 4.0 fork 의무: LICENSE 파일 보존 + NOTICE.md에 fork 사실/upstream commit SHA/변경 사항 명시 → 의무 충족 + 출처 추적 사슬 확보
- 원본 보존 원칙: 우리 변경은 추가(`ko/`, NOTICE, 신규 챕터)와 외부 파일(`.claude/CLAUDE.md`)로 표현. 원본 수정은 부득이한 경우(`docs.json`, `.gitignore`)만 라인 단위 최소화

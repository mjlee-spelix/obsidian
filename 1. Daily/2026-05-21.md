### 2. Prisma rename 완결 패턴 — entrypoint.sh self-heal cycle
- 5/19 마이그레이션이 `_v_` DROP + `_mv_` 생성 + Layer 2 `_mv_`로 재바인딩 = 의도 완벽
- 근데 entrypoint.sh self-heal이 매 부팅마다 옛 4개 마이그레이션 재실행 → `_v_` 부활 + Layer 2 `_v_`로 도로 묶임
- = **rename 마이그레이션 + 인프라(entrypoint.sh) 동기 갱신 필수**. 둘 중 한쪽만 박으면 cycle
- 해결: 새 마이그레이션 + entrypoint.sh MART_OBJECTS + self-heal 마이그레이션 목록 3곳 동시 정합
- 자동 복구 메커니즘이 의도와 반대로 작동할 수 있음 — **self-heal 목록은 현재 chain 정합 유지 책임**

### 3. PostgreSQL Bitmap Index Scan vs Parallel Seq Scan
- 7일 윈도우 (9K행 매칭) → Bitmap Index Scan (12ms)
- 90일 윈도우 (130K행 거의 다 매칭) → Parallel Seq Scan (40ms)
- 옵티마이저가 **필터 selectivity**로 자동 분기 — 90일은 필터 효과 없으니 풀스캔 + 병렬화가 더 빠름
- = **인덱스는 selective 쿼리에서만 의미**. 광범위 집계는 Layer 2 daily mview로 사전 집계해야 운영급 (`spx_mv_kpi_calls_daily`의 존재 이유)

### 4. tenant_id mismatch 진단 + 복구 흐름
- 시드 데이터 tenant_id (`ff3ccc82-...`) ≠ 로그인 후 자동 생성된 본인 계정 tenant_id (`524f6ce3-...`)
- 첫 증상: 카드/차트 빈손 (500 아님, 데이터 0건)
- 1차 시도: 본인 계정의 tenant를 시드 tenant로 변경 → 500 폭발 (`tenants` 테이블에 시드 tenant 레코드 없음)
- 2차 해결: 본인 tenant로 원복 + 시드 데이터의 tenant_id를 본인 tenant로 일괄 UPDATE + mart REFRESH
- = **시드 = 운영 tenant id에 맞춰서 박거나, 미리 가짜 `tenants` row INSERT 해야 함**

### 5. KPI 카드 의미 vs 이름 mismatch (spec ↔ 사용자 인식 drift)
- spec L107 "총 오브젝트 = 누적 등록 수" / L207 "기간 무관 현재 시점"
- 사용자 인식: "기간 내 오브젝트 수여야지"
- 코드: spec 따랐지만 `count`만 반환, `curr_new`는 계산하고 미반환 → UI에 "+신규" 라벨만 있고 숫자 없음
- = **spec name·body·code·UI·user mental model 5중 정합 필요**. drift 한 곳만 생겨도 사용자에겐 "버그처럼" 보임
- 정정: count 의미 자체를 사용자 인식에 맞추고 (period 내 신규) + spec 갱신 + 이름도 명확히

### 6. stale connection pool 패턴
- 서버 PG가 connection drop 후 api pool에 좀비 connection 남음 → 500 `terminating connection due to administrator command`
- `docker compose restart api`로 즉시 해소 (pool 새로 만듦)
- 영구 방어: `SQLALCHEMY_POOL_PRE_PING=true` (.env)

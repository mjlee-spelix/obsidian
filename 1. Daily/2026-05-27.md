## 배운 것

> 4가지 진단 트랙에서 누적된 학습. SESSION_HISTORY § 2026-05-27 4개 엔트리 참조.

- **vLLM Responses API tool calling 버그 (gemma4 parser)** — 같은 vLLM 서버에서 `/v1/chat/completions`는 `tool_calls` 구조화 정상, `/v1/responses`는 raw text 노출 (`call:Name{k:v}` 형식). 비스트리밍·스트리밍 모두 실패. **모델 교체 시 API 경로별 동작도 함께 검증 필요** → 지식노트 후보
- **n8n `use_responses_api`는 노드 인스턴스별 설정** — 글로벌 X. OpenAI Chat Model + JSON Model 둘 다 개별 변경 필요
- **Structured Output Parser 에러는 상류 노드 확인이 1순위** — 파서 자체 문제가 아니라 모델 출력 형식 문제인 경우 다수. 에러 발생 노드보다 상류 먼저 확인 → 지식노트 후보
- **ngrok 진단 1단계 = 포워딩 대상 서비스(API/Web/Gateway) 매핑 확인** — 매핑 확인 없이 포트 가설 세우면 오진 위험. **본인의 5/26 "5001 mismatch" 가설이 오진 사례** (실제는 Dify Web 3000 매핑) → 지식노트 후보
- **Dify API 도구 프로바이더 Base URL ↔ Flask 실제 라우트 불일치 → Next.js 404 HTML 반환** — Flask JSON 404가 아니면 Dify 자체 응답이라는 신호 (Flask까지 미도달)
- **Dify OpenAI 제공자 API Base에 `/v1` 넣으면 이중 추가** (`/v1/v1/...`) — Dify가 자동 추가하므로 제외 필수
- **n8n Anthropic credential Base URL은 `/v1/messages` 경로 빼야 함** (`https://api.anthropic.com`만) — n8n이 자동 추가하므로 중복. 단 n8n 2.6.3의 credential 테스트 기능 자체는 최신 Anthropic API와 비호환 (실제 노드 실행은 정상)
- **n8n credential 권한 에러는 워크플로우 소유자 X credential 소유자 mismatch** — 다른 사용자가 만든 credential 참조 시 발생. 워크플로우 소유자가 credential 재생성 후 노드에서 재선택

- 향후 SESSION_HISTORY 박을 때 "VSCode 자가 검증 결과"와 "사용자/Claudian 검증 결과" 분리 표기 권장

### rename 작업의 trigger/함수 누락 함정
- Prisma `@@map` 변경 + 마이그레이션은 데이터/인덱스만 옮김. **PostgreSQL trigger 함수 + 5개 trigger는 별도 작업 영역**
- 본 사고에서 setup_audit_triggers.sql이 정상 박혀 있었으나 **entrypoint가 setup_audit_schema.sql:50의 `DROP SCHEMA IF EXISTS audit;` (CASCADE 없음) 의존성 실패로 죽어서** trigger 재배포 단계까지 못 감
- 옛 함수 `audit.log_dify_change()` 살아 있고 5개 trigger가 옛 함수 가리킴 → DELETE/UPDATE 발생 시 옛 테이블 INSERT
- 향후 schema rename 시 trigger 재배포 단계 명시 필수

### `DROP SCHEMA` CASCADE 누락 패턴
- 의존성 살아 있는 schema에 `IF EXISTS`만으로 부족 — 의존성 검사에서 실패해 컨테이너 부팅 막힘
- 폐기 의도면 `CASCADE` 명시 (또는 의존성 사전 정리 단계 추가)
- 5/15 setup_audit_schema.sql:53에 CASCADE 추가 + 사고 재발 방지 주석 박음

### Prisma client는 schema.prisma를 런타임에 안 읽음 — VSCode 진술 일부 틀림
- VSCode가 "기존 generated client가 새 테이블명을 자동 반영"이라고 했는데 **틀림**
- `prisma generate`가 schema.prisma → `src/generated/audit-client/` TypeScript 코드로 **컴파일 시점에 테이블명을 박음**
- @@map 변경 시 prisma generate 안 하면 client는 옛 이름 그대로 SELECT/INSERT 시도 → 런타임 에러 (`relation "X" does not exist`)
- 단 `pnpm prisma migrate dev`는 마이그레이션 적용 직후 자동 generate → 그 경우 redundant
- npm install은 dependency 변경 0이라 불필요 (VSCode 과보호)

### 인프라 사실 3건 (5/15 추적 + 수습 과정 누적)
- **web 컨테이너 = production 빌드** (`langgenius/dify-web:1.13.3`, `next start` 상당, 볼륨 마운트 없음). 코드 변경 시 `docker compose build web && up -d web` 필수. HMR 없음
- **Docker build는 git이 아닌 working tree에서 읽음** → 커밋 안 해도 빌드만 하면 컨테이너에 반영됨. 커밋과 빌드 별개 단위
- **gunicorn 자동 reload 안 함** — endpoint/모듈 변경 시 `docker compose restart api` 필수. destroy/recreate 불필요

### PowerShell + docker exec에서 psql 메타 명령 escape 안 먹힘
- `docker compose exec db_postgres psql -c "\d table"` → `\d` escape 안 됨, syntax error
- 대안: `information_schema` 쿼리로 우회 (`SELECT ... FROM information_schema.columns WHERE table_name=...`)
- `\dp` 권한 조회는 `information_schema.table_privileges` 사용
- `head -N` 없음 — `Select-Object -First N` 또는 grep `-c`

### 백엔드 SSO 콜백이 프론트 상수 가로채는 패턴
- 5/14에 `DEFAULT_POST_LOGIN_PATH = '/dashboard'` 프론트 8파일 일괄 교체 완료된 것으로 박혔으나, Keycloak SSO 로그인 시 여전히 `/apps`로 감
- 진범: `api/controllers/console/auth/keycloak.py:184`의 `redirect(f"{console_web_url}/apps")` — 백엔드가 302로 `/apps` 박아 응답 → 프론트 상수가 실행되기 전에 가로채짐
- **결정타**: Network 탭 Response Location 헤더가 가장 빠른 판별 도구
- 가설 여러 개일 땐 한 번에 다 고치지 말고 변수 하나씩 분리해서 검증해야 진짜 원인이 묻히지 않음

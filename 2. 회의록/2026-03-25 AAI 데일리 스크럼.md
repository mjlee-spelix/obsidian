## 논의 내용

### 채팅형 인터페이스 구현 방향
- 사용자 입력을 가능한 적게, 정확하게 받아야 함
- 전부 텍스트 입력 vs 입력폼 제공 여부 고민 필요
- 결재 리스트 노출 시 몇 개까지, 어떤 항목을 미리보기로 보여줄지 결정 필요
- 참고 방향: 클로드 코드처럼 후보 버튼(선택지 JSON)을 output으로 내는 방식 검토
- 기존 채팅형 AI UI 벤치마킹도 병행 고려

### HITL (Human-in-the-Loop) UX 처리
- UI 레벨에서 레이아웃 팝업으로 처리 → 에이전트/워크플로우가 끊기지 않아 보이도록
- 이전 대화 내용을 사용자 요청과 함께 input → agent → output 반복
- Agent의 memory 기능 활용

### LLM 인프라 및 모델 운영
- 41번 서버 ollama/vLLM 정리 후 A100 4개로 gpt-120b 사용 예정이었으나 **일단 보류**
  - n8n 기존 모델 정리 이슈 + 철도청/경찰청 사용 중 등의 사유
- 코난 LLM 도입 시 모델 간 성능 비교 필요
  - 모델별 성능/품질 차이, 시나리오/비즈니스별 적합 모델 파악

### 차트 생성 방식
- 차트 그리는 기능을 노드로 만들어 재사용성 높이는 방향
- 일단 Dify로 워크플로우 이관 후 작업 시작
- 툴로 차트 이미지 생성 → base64 변환 시 string 길이가 길어져 **context 소모 이슈** 존재

### 로그인/인증
- 추후 UI 개발 시 로그인 방식 결정 필요
  - SSO, Keycloak, Supabase 등 검토
  - 로그인 화면 구현 후 세션 기반으로 동작하도록

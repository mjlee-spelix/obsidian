### 코난 방문 결과

- 운영자들이 장애 로그, 매뉴얼 등을 넣고 조회하는 시스템 기획 중
- 코난 GPU + LLM + RAG로 경찰청 로그 데이터 검색 시스템 발주 예정
- 개발 파트너로 우리 팀 가능성 있음

### 관리 기능 차기 타겟 (최대 1달)

**1) SSO 연동** — 승랑님 담당
- 사내 Directory 서비스 연계를 통한 Dify 로그인 (계정/암호 방식)
- 향후 고객/파트너 요청 시 SAML 2.0, OIDC, OAuth 등 지원
- 승랑님이 작업한 Keycloak으로 대체하기로 결정
- Keycloak 메서드 등 확인 필요

**2) RBAC** — 권대리님 담당
- 권한 기본 속성: 권한없음(N), 읽기 전용(R), 편집자(E), 관리자(A)
- 워크스페이스 및 개별 오브젝트 구조 설계
  - 기존 스키마: 워크스페이스ID + 에이전트ID-ChatID
  - 신규 스키마: 워크스페이스ID + 프로젝트(또는 부서ID) + 에이전트ID/ChatID
- 접근 관리 구조: 개별 Object 레벨 vs 업무그룹 레벨 설계

**3) 감사로그** — 승랑님 담당
- 프롬프트 수정 이력, 지식베이스 활동 기록 저장/내보내기 (컴플라이언스 필수)
- Dify, n8n 로그 → RDB 저장 → 대시보드 분석 수행
- 로그 저장 방식 검토: ① RDB에 전체 저장 ② LLM으로 식별 후 저장 ③ RDB 저장 후 배치 분류
- Dify 로그 형식 조사 및 RDB 적재 방식 결정 필요
- 대시보드 메뉴 구성 고민 (계정별, 업무별 등)
- 오픈소스 모델 사용 시 토큰 관련 로그 요청 있었음

**4) 다중/조직별 워크스페이스 중앙 관리**
- 부서/업무/프로젝트별 오브젝트 모니터링 및 중앙 통제
- 기간별 도구 생성 개수, 이용 통계 등
- 토큰 사용 통계 (내/외부 모델 모두)
- 워크플로우별 모니터링 데이터 저장 위치 확인 필요 (로그 기반인지 확인)

**5) CI/CD**
- GitOPS (Git + Jenkins + Docker)
- 대상: agt-spx-agent, agt-dify-src, agt-n8n-src, agt-web-src
- n8n은 노드 소스를 깃으로 연동 가능 (지정 레포로 pull/push)
- 개발서버 워크플로우 수정 → 운영서버 반영 구조

**6) 브랜드 및 환경 커스터마이징**
- Dify → SPX-Agent 브랜딩 (로고, 솔루션명)
- 환경변수 수정 (`/dify/docker/.env`): 로그설정, 파일업로드 용량제한, 외부 DB/Redis 연결
- 운영 단계에서는 필요한 것만 남기고 개발 환경과 분리 예정
- 단기 메모리는 Redis 연결 검토 중 (프로젝트별 등)

**7) PII 마스킹, 고가용성**
- 클러스터링 배포 및 Scale-out 아키텍처 (K8S 배포 향후 고려)
- 자동 마스킹 보안 가드레일 (데이터 구축 단계 vs 조회 단계)
- 철도청은 rule-base로 진행 (정규식 기반 조회 시 마스킹 처리)

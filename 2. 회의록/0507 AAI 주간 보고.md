## 논의 내용

### 1. 화면 레이아웃
- 관리자 설정 좌측 탭에 햄버거 메뉴 도입 → 탭 접고 화면 넓히기
- 카드 크기 조정 필요할 수 있음 (현재도 grid 반응형이지만 Phase 2 우측 드로어 작업 시 카드가 좁아질 가능성)
- **고려해둘 사항**: 드로어 컴포넌트 시작 시점에 카드 min-width 재검토

### 2. 데이터 마트
- 대시보드용 스키마 별도 설계
- 인덱싱 / DB 튜닝으로 응답 시간 최대한 줄이기
- 우선 **배치**로 갱신 (실시간 X)
- 3초 이내로 응답 뽑아오는 게 목표
- ETL 배치 vs 실시간 — 우선 배치
- **TanStack staleTime 5분과는 다른 레이어**
  - staleTime: 클라이언트(브라우저) 캐시
  - 데이터 마트: 서버 응답 자체를 빠르게
  - 둘 다 유지

### 3. 로딩 UX (스켈레톤)
- 화면 프레임(카드 프레임, 제목 등)을 먼저 보이게 → 쿼리 결과는 나중
- 비동기 렌더로 체감 로딩 시간 단축
- **순서**: 데이터 마트 먼저 적용 → 그래도 느리면 스켈레톤 적용

### 4. 유저 정보 출처
- `tenant_user` ❌ → **`accounts` 테이블 사용**
- resource_ownership.owner_account_id → accounts.id JOIN으로 통일

### 5. mount 관련 피드백
- 평소 작업 흐름: 개발 → 이미지 새로 빌드 → 확인
- → **개발 중 mount 회귀, 검증은 빌드** (회사 표준 흐름)
- 버그 발견 시 리스트만 누적, 막히지 않으면 일단 미루고 진행
- 막히는 경우에만 해결하고 해결 방법까지 적기

### 6. 구현 초점
- 대시보드 만들 때 막히는 게 아니면 mount/버그 얘기는 우선 미룸
- 구현 자체에 집중

### 7. dev 배포
- **내일(5/8) 1시까지** 작업 분량 dev에 올리기 (통합 테스트 목적)
- 미완성이라도 푸시 OK

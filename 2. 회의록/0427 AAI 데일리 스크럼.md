### Dify 라이선스
- 카피라이트/로고 제거가 라이선스상 금지됨
- 프론트를 따로 구현하여 Dify를 백엔드로 사용해야 함
- 로고 제거는 별도 연락 필요 (엔터프라이즈 기능 중 하나로, 소스에 명시되어 있음)
- 소스 코드 공개 제약이 있는 라이선스 존재 → MIT / Apache / BSD 라이선스를 사용하기로
- 소스 분석 결과: [[4. 지식노트/Dify - 엔터프라이즈 vs 커뮤니티 커스텀 브랜딩 범위.md|엔터프라이즈 vs 커뮤니티 커스텀 브랜딩 범위 정리]]

### 개발 환경 구성
- 기존 Demo용 Dify는 유지
- 개발용 Dify를 159 서버에 새로 띄우고, DB 변경 작업은 여기서 진행
- 새로 올린 Dify에 개인 업무 결과물 합쳐서 테스트 예정 (테스트 서버에서 베타 테스트)

### 인증/권한 관리 (PPT 4p)
- 인증은 Keycloak으로 처리
- 권한 관리는 로컬에서 처리
- 기존 테이블은 건드리지 않고, 필요한 테이블만 추가하는 방향
  - `users`, `departments` / `user_departments`, `object_ownership` / `permissions`, Redis 권한 캐시
- 오브젝트 단위: App / Knowledge Base / Tool
- Local App에서 DB 가져와서 인가 처리

### 워크스페이스 구조 변경 (PPT 6p)
- 워크스페이스를 부서 이름으로 변경
- 단일 워크스페이스를 부서로 치환하는 구조

### 설정 화면 변경 (PPT 9p)
- '멤버' 탭을 '부서 관리' 등으로 변경
- 대시보드, 감사 로그 등의 탭 추가

### 중앙 관제 대시보드 (PPT 12p)
- DB에서 데이터 가져와서 화면 구현해보기 (우선 화면 구현 먼저)
- 현재는 통계만 표시하지만, 추후 중앙 통제 액션 추가 가능성 있음
  - 오브젝트 비활성화, 부서 간 이동, 토큰 한도 설정, 임계치 도달 알림 등
  - 아직 구체적 정의는 안 됨

### 감사 로그 (PPT 13p)
- DB에서 보는 것과 로그에서 볼 수 있는 것이 다름

### 대시보드 vs 감사 로그 구분
- 구분 기준이 아직 명확하지 않음
- **대시보드**: 통계량 중심, 차트로 통합 표시 (어떤 에이전트가 많이 쓰이는지 등 관리 목적)
- **감사 로그**: Raw 데이터 그 자체, 특정 사건 발생 시 추적 용도

### 개발 프로세스
- 화면 설계 이미지를 Claude에게 줘서 프론트 먼저 구현 → 이에 맞춰 백엔드 구현하는 순서로 진행 예정

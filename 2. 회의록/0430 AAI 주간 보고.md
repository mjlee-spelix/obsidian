## 논의 내용

### 1. 개발 환경 / 빌드 파이프라인

- **Jenkins 빌드 흐름**: 마스터 브랜치에서 개발된 코드를 `git tag` 후 `git push` → Jenkins가 받아서 빌드 → 도커 이미지까지 생성
- 깃 태그 기준으로 자동 도커 빌드 트리거
- **dify-devel DB**를 중앙으로 사용 — 각자 로컬에 별도 띄우지 않고 개발 서버 DB 바라보고 작업
- 개발/SW 변경사항 게시판: https://board.worksmobile.com/main/article/4070000000194704249?fontButtonShow=true

### 2. 인증·인가 아키텍처 (PDF 4p — 적용 시나리오)

- **인증**: Keycloak (OIDC)
- **인가**: 로컬 앱이 자체 관리 (Dify CE 본체 무수정, 테이블 4개 신설)
- **흐름**:
  - Dify에서 계정 생성 → Keycloak에 등록
  - 사용자가 로그인할 때만 로컬 `account` 테이블에 동기화 (마지막 접속 시각 등)
  - JIT(Just-In-Time) 프로비저닝
- **Keycloak을 `account` 테이블에 동기화하는 이유**:
  - 오브젝트 생성 시마다 권한 부여 프로세스가 추가됨
  - 매번 Keycloak에서 유저 정보 조회하면 비효율
  - 고객사가 SSO 조회 등을 허용 안 해주는 케이스 → 로컬 동기화 필수
- **테이블 4개**: `users`, `departments`, `user_departments`, `object_ownership`, `object_permissions`
- **권한 부여 대상**: 개인 + 부서(group) — JWT `groups claim` 누적

### 3. 설정 페이지 변경 방향

- 기존 **멤버 탭 제거** 예정
- 우리가 만드는 **부서/사용자 등 RBAC 테이블 사용 화면**으로 대체
- 김이사님 작업 영역과 정렬 필요 (사이드바 합의 — H-DASH-15)

### 4. 로그 수집 ETL 파이프라인

- **방향**: 배치 → 실시간으로 확장 (Stage별 진행)
- **대시보드는 데이터 마트 형태로 보여주기**
- DW(Data Warehouse) 종류는 미정
- **로그 통합 작업**: 로그 파일 + DB에 흩어진 데이터를 통합 테이블로 → **승랑님 작업**
- 우리는 통합된 스키마 받아서 그대로 사용

### 5. 중앙 관제 대시보드 (PDF v0.3 리뷰)

#### 5-1. 화면 구조 (PDF 슬라이드 35)

- **헤더 + 컨텍스트 바**: 기간 · 새로고침 (5분 캐시) + 활성 필터 칩 + URL 북마크
- **KPI 4종** (Dify CE 추출 가능):
  - 총 오브젝트 ← `apps + datasets + tools COUNT`
  - 활성 사용자 ← `messages.from_account_id DISTINCT`
  - API 호출 ← `messages + workflow_runs COUNT`
  - **에러율 24h** ← `messages.error + runs.status='failed'` ※ 우리 spec엔 "토큰 사용" 으로 잡혀있음 — 조정 필요
- **차트·테이블**:
  - 좌: 부서별 오브젝트 스택 차트
  - 우: 모델별 토큰 사용량
  - 하: 부서별 활동 표
- **호버**: 상위 3건
- **클릭**: 드로어
- **brush**: 범위 필터

#### 5-2. 동적 인터랙션 (PDF 슬라이드 16, 17)

> 회의 결정: 정적 → 동적 순서. 동적은 Phase 2.

- **17p — KPI 카드 클릭 시**: 카드 아래 차트 영역이 해당 KPI에 맞게 변경
  - 총 오브젝트: 부서별 누적 / Top 소유자 / 부서별 신규 생성
  - 활성 사용자: 부서별 DAU·WAU / 모델별 사용자 / 신규·이탈
  - API 호출: 부서별 호출 수 / 모델별 점유 / 부서별 호출 RPS
  - 에러율: 부서별 에러율 / Top 에러 유형 / 모델별 실패율
  - **차트·테이블의 위치/행 수/색상 체계는 그대로** (메트릭만 교체)
  - URL 직링크: `?metric=calls`
  - ESC 또는 재클릭으로 종합 뷰 복귀
- **16p — 부서별 호출 수 막대 클릭 시**: 우측 드로어 슬라이드 인 (200~300ms)
  - 컨텍스트 칩 + 닫기
  - 요약: 호출/사용자/에러 카드 3종
  - 로그 6~10건 + 검색 + CSV → "전체 보기 →" 클릭 시 감사 로그 풀뷰

#### 5-3. 18p (참고용)

- 데이터 없는 항목은 **조정해서 빼거나** 다른 항목으로 대체 가능

#### 5-4. Dify CE 매핑 (PDF)

- **대시보드 (집계)**: `messages` · `workflow_runs`를 SUM·COUNT·AVG·% 집계
- **감사 로그 (원본 row)**: `messages` · `workflow_runs` · `node_executions` · `feedbacks`
- **CE 비지원 (제외)**: admin 행위(비활성·이관·삭제), 권한·역할 변경 이력, 토큰 한도 설정 변경 → 별도 운영 도구

### 6. DB 스키마 분담

- **분담 결정**: 통합 스키마 의견도 나왔으나 → **나눠서 개발하기로**
- **로그용/대시보드용 스키마**: 승랑님이 먼저 짜고 공유
  - 우리는 그 스키마대로 목업 데이터 만들어서 화면 채우기
- **dify-devel DB만 바라보고 개발**
- 깃에 스키마 작업 → 받아서 사용

## 우리 SPX-Agent 작업에 미치는 영향

### 즉시 반영
- **KPI 4종 재검토**: 우리 spec은 `토큰 사용`인데 PDF는 `에러율 24h` — 어느 쪽 갈지 결정 필요
- **컨텍스트 바**: 우리 spec에 없음 — 활성 필터 칩 + URL 북마크 (단, 모달 환경 제약 고려 → URL 북마크 어려움)
- **5분 캐시 표시**: 헤더에 "5분 캐시" 안내 (현재 spec엔 없음)

### Phase 2 (동적 인터랙션) 신규 spec 후보
- KPI 카드 클릭 → 차트 영역 메트릭 전환
- 부서별 차트 막대 클릭 → 우측 드로어 (감사 로그 미리보기)
- ESC / 재클릭으로 복귀
- URL 직링크 (`?metric=calls` 등)

### 외부 의존 / 블로커 추가
- **로그/대시보드 스키마 (승랑님)** — 백엔드 작업 블로커. 받기 전까지 목업으로 진행
- **Jenkins 빌드 환경** — 추후 DB 스키마 받은 다음 활성화

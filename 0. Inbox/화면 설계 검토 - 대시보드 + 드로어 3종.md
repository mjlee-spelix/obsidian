## 1. 대시보드 메인 화면

### 1.1 상단 KPI 4종

| 항목 | 의미 | 가치 평가 | 개선 |
|---|---|---|---|
| **총 오브젝트 234** (App 11 / KB 5 / Tool 8) | 전사 보유 자산 카운트 (앱/지식베이스/도구) | ✅ 가치 명확 — 거버넌스 입장에서 "우리 회사가 뭘 갖고 있나"는 기본 질문 | ⚠️ **합계 불일치**: 11+5+8=24인데 카드엔 234. 마지막 자릿수 오타 또는 다른 카운트 정의 |
| **활성 사용자 87** | 기간 내 호출한 사용자 수 (DAU/MAU 둘 중 하나) | ✅ 가치 명확 — 도구 채택률 지표 | ⚠️ **기간 정의 모호**: 헤더 기간 따라가는지, 24h 고정인지. 카드 라벨에 "(7일 기준)" 같이 명시 필요 |
| **API 호출 351K** | 기간 내 LLM 호출 총수 | ✅ 가치 명확 — 사용량 + 비용 분포의 1차 신호 | 단위 K/M 압축 OK (전역 규칙) |
| **에러율 0.84%** | 실패 호출 / 전체 호출 | ✅ 가치 명확 — 서비스 안정성 신호 | 이사님 결정으로 **호출+보안 통합 의미**가 되어야 함. 라벨에 "(호출+보안 포함)" 미니 안내 또는 hover tooltip 필요 |

**종합**: KPI 4종 다 의미 있음. 단 **두 가지 정합성 이슈**:
- 총 오브젝트 234 vs 11+5+8=24 — 오타인지 다른 정의인지 확인
- 모든 KPI가 헤더 기간 필터를 따라간다는 점이 화면에 명시 안 됨

### 1.2 좌하 — 부서별 오브젝트 차트

**구성**: 부서별(IT/마케팅/재무/인사) × 오브젝트 종류(App/KB/Tool) 스택 막대

| 평가 축 | 결과 |
|---|---|
| 의미 명확성 | ✅ "어느 부서가 얼마나 많은 자산 보유" 명확 |
| 사용자 가치 | ✅ 거버넌스 — 부서별 자산 편중 / 누락 부서 발견 |
| 개선 필요 | ⚠️ "외부 22" 막대 의도 — 오브젝트는 부서 소유 개념이라 "외부 사용자"는 부적합. **이사님 결정대로 "외부" 막대 제거 → "미배정"으로 통합** |
| 마트 정합성 | ✅ 5/12 결정대로 `resource_ownership` 직접 조회 (audit 아님) |

### 1.3 우하 — 모델별 사용자 차트

**구성**: 모델별 (GPT-4, Claude 3, ...) 활성 사용자 수

| 평가 축 | 결과 |
|---|---|
| 의미 명확성 | ✅ "어느 모델을 누가 쓰나" |
| 사용자 가치 | 🟡 **약함** — 모델 채택은 보통 비용/품질 비교가 중요한데 "사용자 수"만으론 의사결정 어려움 |
| 개선 제안 | (a) 같이 보여야 할 메트릭: 모델별 호출 비중 / 모델별 토큰 / 모델별 평균 응답시간 (b) 또는 KPI 드로어로 빠지는 것이 자연스러움 — 메인 화면에선 더 임팩트 있는 차트로 교체 검토 |
| 마트 정합성 | ⚠️ **WORKFLOW 앱의 모델 정보 audit에 들어오는지 검증 필요** (workflow-runs collector 5필드 비대칭 영향) |

### 1.4 하단 — 부서별 활동 테이블

**현재 컬럼** (추정): 부서 / DAU / WAU / 신규 / 이탈 / 호출 / 토큰

| 평가 축 | 결과 |
|---|---|
| 의미 명확성 | 부서별 다차원 메트릭 한 줄로 — 의미는 OK |
| 사용자 가치 | ✅ 높음 — 부서 비교의 핵심 표 |
| **이사님 결정 충돌** | ❌ **신규 / 이탈 컬럼 삭제** 확정. 표 컬럼 재설계 필요 |
| 개선 제안 | 삭제된 신규/이탈 자리에 대안: (a) **에러율** (안정성 신호) / (b) **Top 모델** / (c) **평균 응답시간** / (d) 그냥 컬럼 줄여서 단순화 |
| 마트 정합성 | audit + RBAC JOIN으로 가능. 부서 기준 = 앱 소유 통일 (이전 사용자 소속 기준 폐기) |

### 1.5 헤더 / 컨트롤 바

- 기간 (24h / 7d / 30d / Custom) — ✅ 표준 UX
- 부서 필터 — ✅ 가치 명확
- 새로고침 — ✅
- **이사님 결정 반영**: 기간 max = 90일 고정. **Custom 옵션에서 90일 초과 선택 자체가 불가능해야 함** (옵션 disabled 또는 picker max 설정)

### 1.6 컨텍스트 바 (드로어 열림 상태)

- "재무 (드로어 열림) — 닫기" 같은 표시
- ✅ 사용자가 드로어 안에 있는 상태를 시각화 — 좋음
- ⚠️ 다만 드로어 자체가 열려있으면 사용자가 그걸 인지하니까 이 바가 추가 가치 주는지는 의문. UX 테스트 후 결정 가치

## 2. 차트 드로어 화면

### 2.1 시나리오 — 부서 막대 클릭 → 우측 드로어

**예시**: 재무 막대(14.5K) 클릭 → 재무 활동 로그 6건 + 미니 메트릭 + 풀뷰 링크

### 2.2 드로어 구성 항목별

| 영역 | 의미 | 가치 | 개선 |
|---|---|---|---|
| **컨텍스트 헤더** "재무 활동 — 최근 / Last 7 days context inherited" | 부서 + 기간 컨텍스트가 좌측 차트에서 상속됐음을 명시 | ✅ 매우 좋음 — 사용자가 "지금 뭘 보고 있나" 즉시 인지 | "context inherited" 영문 표현은 한국어 UI 통일 — "기간 상속됨" 같은 표현 검토 |
| **탭: 부서 / 지표 / 기간 / 에러** | 드로어 내에서 컨텍스트 재선택 가능 | 🟡 의미 모호 — 탭인지 라벨인지 헷갈림. "에러: 1"이 탭이면 클릭 시 동작 정의 필요 | 명세 필요: 클릭 시 드로어 컨텍스트 재설정인지 단순 표시인지 |
| **미니 KPI 3종** (호출 14.5K / 활성 사용자 73 / 에러 406) + % 추이 | 좌측 차트의 부서별 막대를 드릴다운한 메트릭 | ✅ 높음 — 한 부서의 다차원 신호 한눈에 | **에러 = 406, 에러율 = 다른 카드에 0.84%인데 정의 차이?** — "에러 건수" vs "에러율" 일관성 확인 필요 |
| **검색창 + CSV 내보내기** | 활동 로그 안에서 키워드 검색 + 데이터 내보내기 | ✅ 어드민 핵심 기능 | CSV는 H-DASH-12 (대량 데이터 OOM) 방어 필요 — 1000행 제한 |
| **활동 로그 6/24** | 24건 중 6건 미리보기 (시간순) | ✅ 좋은 UX — "더 있음" 명시 | "6/24"의 24가 어디서 오는지 — 기간/필터 적용 결과 총 건수? 명세 필요 |
| **로그 행** (14:32 / 최영재(재무) / 월결산 자료요약 / OK) | 시간 / 사용자 / 메시지 본문 / 상태 | ✅ 매우 가치 큼 — "누가/언제/뭐 했나" 한 줄 | 메시지 본문 = audit details에 query 없으면 OLTP `messages.query` JOIN 필요 (5/11 마트 메모 § 3 발견) |
| **로그 행 에러 케이스** (model_timeout — 30s 초과 / ERROR) | 에러 행은 분류 라벨 + 색상 다름 | ✅ 좋음 — 라벨 정규화는 H-DASH-18 ILIKE 분류 활용 | audit details->>'error'에 적용. 라벨은 6종 (rate_limit / auth_error / quota_exceeded / connection_error / context_length / server_unavailable / model_timeout?) |
| **"더 많이 보기 → 감사 로그 풀뷰"** | 풀뷰(`/audit` 페이지) 연결 | ✅ 좋음 — drill path 명확 | URL 컨텍스트(부서/모델/기간/필터) 전달 명세 — chart-drawer spec에 박혀있는지 확인 |

### 2.3 드로어 동작 명세 (우측 패널)

**트리거**:
- 좌측 차트 부서 막대 클릭 (다른 차트 막대도 동일?)
- 테이블 행 클릭
- → ✅ 일관된 트리거 패턴 (UX 학습 비용 낮음)

**컨텍스트 전달**:
- 클릭 자체에서 컨텍스트 (부서/기간/모델) 드로어로 전달
- → ✅ 명확

**단가/종료**:
- X / ESC / 외부 클릭
- → ⚠️ **모달 제약 충돌 주의**: `account-setting/index.tsx`가 base-ui dialog 기반이라 ESC가 자동으로 모달 닫기. 드로어 ESC 자체 핸들링 금지 (CLAUDE.md 명시)

**페이지 이동 없이 즉시 확인 + 깊은 분석은 풀뷰로** — ✅ 매우 좋은 정보 아키텍처

### 2.4 인터랙션 푸터 (200~300ms 슬라이드 인)

- ✅ 표준 UX
- ⚠️ **설정 모달 사이드바 접기/펴기와의 공간 충돌** — 오늘 발생 이슈. 사이드바 + 본문 + 드로어 동시 표시 시 공간 부족. 별도 트랙으로 결정 중

## 3. KPI 드로어 화면

### 3.1 4개 영역 고정 레이아웃

**구성**: 좌상 / 우상 / 좌하 / 우하 + 표 (KPI마다 의미는 다르지만 위치 일관)

| KPI | 좌상 | 우상 | 좌하 | 우하 | 표 |
|---|---|---|---|---|---|
| **총 오브젝트 1,247** | Top 부서 분포 | App/KB/Tool 분포 | Top 소유자 | (?) | 부서별 신규 생성 |
| **활성 사용자 428** | DAU/WAU 추이 | 모델별 사용자 | 신규/이탈 ❌ | (?) | 부서별 사용자 활동 |
| **API 호출 84.2K** | 부서별 호출 | 모델별 호출 비중 | 부서별 호출 RPS 추세 | Top 앱 / 추세 | 부서별 호출 RPS 표 |
| **에러율 1.8%** | 부서별 에러율 | Top 에러 유형 | (?) | (?) | 부서별 에러 테이블 |

### 3.2 4개 영역 의미와 가치

**고정 4영역 레이아웃의 장점**:
- ✅ UX 학습 비용 낮음 — KPI 드로어 4종이 같은 구조라 사용자가 한 번 익히면 다 익숙
- ✅ 시각적 일관성

**고정 4영역 레이아웃의 단점**:
- 🟡 **메트릭마다 자연스러운 영역 수가 다른데 4로 강제 → 빈 영역 또는 억지 차트 위험**
- 예: 에러율 KPI는 부서별 에러율 + Top 에러 유형 + 표면 충분. 좌하/우하 영역에 뭘 넣을지 미정 (이미지에서도 불명확)

**이사님 결정 충돌**:
- ❌ 활성 사용자 KPI 드로어의 **"신규/이탈 자리"는 삭제** 확정. 다른 콘텐츠로 채워야 함
- 후보: (a) DAU 시계열 (b) 활성 시간대 분포 (c) Top 앱 / 부서별 활동

**부서 기준 통일 반영**:
- 활성 사용자 → 앱 소유 부서 기준 통일 (이전 사용자 소속 기준 폐기) → 드로어 표 컬럼 의미 갱신

### 3.3 컨텍스트 일관성

- 기간 + 부서 + 모델 필터가 대시보드 헤더와 동기
- ✅ 매우 좋음 — 단일 컨텍스트로 일관 탐색

### 3.4 풀뷰 연결

- "모든 컨텍스트(부서/모델/기간/필터링)를 URL에 실어 감사 로그 풀뷰로 이동"
- ✅ 좋음 — 단 풀뷰는 `/audit`인데 KPI 드로어에서 풀뷰로 가는 자연스러운 경로가 있는지 (KPI 드로어에서도 풀뷰로 갈 일이 있나? 차트 드로어와 달리 집계 화면이라)

## 4. 종합 평가

### 4.1 잘 된 점

1. ✅ **3-tier 정보 구조**: 메인(요약) → 드로어(부서 다차원) → 풀뷰(감사 로그) — 사용자 의도에 따라 자연스럽게 깊이 조절
2. ✅ **컨텍스트 상속**: 차트 클릭 시 부서/기간/모델 자동 상속 → 학습 비용 낮음
3. ✅ **KPI 드로어 4영역 고정 레이아웃**: 학습 비용 낮음, 일관성 ↑
4. ✅ **이벤트 로그 행 단위**: 시간/사용자/내용/상태 — 어드민이 보기에 핵심 정보
5. ✅ **CSV 내보내기 + 검색 + 풀뷰 링크**: 어드민 도구로서 기본 도구 다 갖춤

### 4.2 개선 필요 (정의/명세 문제)

| 항목 | 이슈 | 해결 방향 |
|---|---|---|
| 총 오브젝트 234 | 합계 24와 불일치 | 숫자 오타인지 다른 정의인지 확인 |
| 활성 사용자 87 | 기간 정의 불명 | 카드에 기간 라벨 추가 |
| 에러율 0.84% | 호출+보안 통합 의미 미표시 | tooltip 또는 미니 라벨 |
| 미니 메트릭 "에러 406" | 에러 카드 0.84%와 정의 차이 | 컨벤션 통일 (건수 vs 율) |
| 활동 로그 "6/24" | 24의 출처 불명 | 명세 또는 hover 안내 |
| 모델별 사용자 차트 가치 | 약함 — 채택 의사결정 어려움 | 모델별 호출/토큰/응답시간 같이 보여주는 형태로 |
| KPI 드로어 4영역 빈자리 | 메트릭마다 자연스러운 영역 수 다름 | KPI별로 영역 콘텐츠 명세 (현재 일부 미정) |

### 4.3 이사님 결정 반영 필수 변경

| 항목 | 변경 |
|---|---|
| 활동 테이블 신규/이탈 컬럼 | **삭제** → 대체 컬럼 검토 (에러율 / Top 모델 / 평균 응답시간 등) |
| KPI 드로어 활성 사용자 신규/이탈 자리 | **삭제** → 대체 콘텐츠 검토 |
| 부서별 오브젝트 "외부" 막대 | **제거** → 미배정 통합 |
| 부서 기준 (활성 사용자, DAU 등) | **앱 소유 부서로 통일** — 표 라벨/주석에 명시 |
| 에러 KPI | **호출+보안 통합 의미** — tooltip 또는 라벨 명시 |
| 기간 max | **90일 고정** — Custom picker에서 90일 초과 옵션 자체 없음 |

### 4.4 PM/이사님 확인 / 디자이너 회의 필요 항목

1. **총 오브젝트 234 vs 합계 24** — 숫자 오타 / 정의 차이 확인
2. **활동 테이블 신규/이탈 자리 대체 컬럼** — 에러율 / Top 모델 / 평균 응답시간 중 어느 게 가치 큰지
3. **KPI 드로어 빈 영역** — KPI별로 4영역 콘텐츠 확정 필요 (메트릭마다 자연스러운 영역 수 다름)
4. **모델별 사용자 차트** — 메인에 유지할지, KPI 드로어로 빠질지, 다른 차트(모델별 호출 비중)로 교체할지
5. **컨텍스트 바** — 드로어 열림 상태 표시 바가 추가 가치 주는지 (UX 테스트 후 결정)
6. **활동 로그 메시지 본문 표시 방식** — query를 audit details에 넣을지(collector 보강) OLTP JOIN으로 가져올지

### 4.5 spec 갱신 / 마트 검증 의존 항목

- **dept-activity spec** — 신규/이탈 컬럼 삭제 + 부서 기준 통일 + 대체 컬럼 정의
- **kpi-drill-through spec** — 4영역 콘텐츠 명세 + 신규/이탈 자리 대체
- **chart-drawer spec** — 메시지 본문 표시 방식 (audit details vs OLTP JOIN) 결정
- **dashboard-controls spec** — 기간 max 90일 picker UX
- **kpi-cards spec** — KPI별 기간 라벨/에러 통합 의미 표시

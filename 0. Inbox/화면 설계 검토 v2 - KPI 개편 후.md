5. 🆕 **어느 앱이 효과적인가, 어느 앱이 죽었나?** — 4번 KPI (앱별 통계, TBD)

## KPI 4종 — 새 4축 패턴

| KPI | 축 (재정의) | 의미 | 의사결정 |
|---|---|---|---|
| 1. 총 오브젝트 | Volume (보유량) | 회사가 보유한 LLM 자산 양 | 자산 편중·미배정 정리 |
| 2. **부서별 사용** | 부서별 활용도 (actor) | 부서 내 사람들이 워크스페이스 내 app/kb/tool을 얼마나 썼나 | 부서별 도입 정착·교육 대상 |
| 3. **부서별 앱 호출** | 부서별 호출 강도 (owner) | 부서가 만든·소유한 앱이 얼마나 호출됐나 | 모델 비용·인프라 사이징 |
| 4. **앱별 통계** | 앱별 분석 (TBD) | 앱 단위 성과·품질 분석 | 죽은 앱 정리, 효과적 앱 확산 |

### 4축 재정의 변화 분석

| 축 | v1 | v2 |
|---|---|---|
| Volume | ✅ 그대로 | ✅ 그대로 |
| Breadth (채택 폭, 사람 수) | "활성 사용자" | **사라짐** — grain이 사람 수 → 사용 건수로 이동 |
| Depth (사용 강도) | "API 호출" | **부서별 호출**로 명칭 명확화 (의미 큰 변화 없음) |
| Quality (안정성·보안) | "에러율" | **사라짐** — 앱별 통계로 교체 |
| 부서별 활용도 (신규) | — | 2번 KPI |
| 앱별 분석 (신규) | — | 4번 KPI |

**v2 신규 모호점**:
- 2번(부서별 사용 = 사용 건수)과 3번(부서별 호출 = 호출 건수)이 **둘 다 "건수" 단위** → 사용자 처음 봤을 때 헷갈릴 가능성 큼
- 의미 차이: 2번 = actor 부서(사용자가 속한 부서) / 3번 = owner 부서(앱을 만든 부서)
- → **카드 부제목·툴팁 보강 필요** (피드백 표 A)

#### 하단 표 컬럼 재검토 — DAU/WAU의 운명

> v1 ②-1 분석은 "부서 / DAU / WAU / Stickiness / 활성앱수"를 권장. v2에서 **KPI 본문 메트릭이 사람 수 → 건수로 바뀌었으므로 DAU/WAU가 이 표에 남는 의미가 약해짐**. ⇒ 피드백 표 B·C로 결정 필요.

| 옵션                | 컬럼 세트                             | grain 일관성                   |
| ----------------- | --------------------------------- | --------------------------- |
| (1) v1 권장 유지      | 부서/DAU/WAU/Stickiness/활성앱수        | 🟡 KPI 본문(건수)과 표(사람 수) 불일치  |
| (2) 건수 일관 ⭐       | 부서/사용 건수/사용자 수/사용자당 건수/활성 앱 수     | ⭐⭐⭐ KPI 본문과 일관, 사용자·앱 차원 균형 |

- ❌ **"에러는 건수+비율 둘 다 표시"** — 4번 KPI 자체가 사라지면서 무효

## v1 자체 결정 6건 유효성 매트릭스

> v1 "자체 결정 완료" 6건이 2차 미팅 결정에 의해 어떻게 영향받는지 명시.

| v1 결정 | v2 상태 | 비고 |
|---|---|---|
| 에러 표시 컨벤션 (호출/활성은 KPI 카드와 통일, 에러는 건수+비율 둘 다) | ❌ **무효** | 에러율 KPI 자체 사라짐 |
| 신규/이탈(사용자) 삭제 | ✅ **유효** | 1차 미팅 결정과 일관 |
| 메인 우하 = 모델별 토큰 사용량 (가치 명확) | ✅ **유효** | 메인 화면 영역, KPI 개편 영향 없음 |
| 부서별 활동 테이블 신규(app/kb/tool) 컬럼 유지 | 🟡 **재검토** | 2/3 KPI 메트릭 변경 영향, 표 컬럼 재정렬 필요 가능성 |
| 비용 KPI 별도 추가 후순위 | ✅ **유효** | 4번 KPI(앱별 통계)가 비용 신호 일부 흡수 가능성 (TBD) |
| 컨텍스트 바 slim 설계 (활성 메트릭 칩 1종만) | ✅ **유효** | 단 메트릭 라벨 갱신 필요 |
| 외부 막대 = 미배정 통합 (1차 미팅 자체결정) | ✅ **유효** | 메인 좌하 차트 영역, KPI 개편 영향 없음 |

**요약**: 7건 중 5건 유효, 1건 무효, 1건 재검토. 메인 화면 영역(좌하·우하·하단 표)은 KPI 개편 영향 거의 없음 — 영향은 KPI 드로어 4종에 집중.

## 종합 평가

### v1 대비 강점 보존
1. ⭐ **3-tier 정보 구조** (메인 요약 → 드로어 부서 다차원 → 풀뷰 감사 로그) — 유효
2. ⭐ **컨텍스트 상속** — 유효
3. ⭐ **활동 로그 행 단위** — 유효
4. ✅ **신규/이탈 삭제** — 유효

### v2 신규 강점
1. ⭐ **활성 사용자 우하 = Top 사용자** — v1 약점이 이사님 결정으로 자연 해소
2. ⭐ **부서별 호출 명명 명확화** — v1 "활성 vs 호출 헷갈림" 모호점 부분 해소

### v2 신규 약점
1. **2·3번 KPI 둘 다 "건수" 단위로 헷갈림 가능** — 부제목·툴팁 보완 필요 (A)
2. **Quality(안정성·보안) 신호 부재** — KPI 단계에서 사라짐, 다른 위치 결정 필요 (F)
3. **DAU/WAU 메트릭 운명 미정** — KPI 본문 메트릭 변경에 따른 정합성 문제 (B·C)
4. **4번 KPI + 차트 드로어 4종 둘 다 TBD** — 화면 설계 가시성 떨어짐 (D·E)

### 자체 결정 가능 (PM 컨펌 권장)
1. KPI 2·3 카드 부제목·툴팁 추가 (모호성 해소)
2. 부서별 사용 KPI 하단 표 컬럼 = (2) 건수 일관 옵션
3. 컨텍스트 바 메트릭 라벨 갱신 (활성 사용자 → 부서별 사용 / 에러율 → 앱별 통계)

### 디자이너/PM 컨펌 필수
1. **DAU/WAU 메트릭 운명** — 폐기·압축·이동 중 선택 (C)
2. **보안·에러 신호 위치** — KPI에서 빠진 영역의 대안 위치 (F)
3. **부서별 활동 테이블(메인 하단) 컬럼 재검토** — 2·3번 KPI 메트릭 변경 영향
4. **앱별 통계 KPI 설계 컨펌** (D 작업 완료 후)
5. **차트 드로어 4종 가치 검증** (E 작업 완료 후 — 전체 제거 결정 포함)

# 대시보드 라우팅 이동 - 1 라우팅 컨벤션

> 현재 대시보드는 설정 모달의 탭으로 마운트되어 있으며 URL을 변경하지 않음
> (`web/app/components/header/account-setting/dashboard-page/`).
> 별도 라우트로 분리할 때 어떤 URL을 쓸지 결정하기 위한 기존 컨벤션 정리.

---

## 기존 라우팅 구조 (트리)

Next.js App Router. 괄호로 감싼 디렉토리 `(name)`은 **Route Group** — URL에 안 박히고 layout만 묶음.

```
web/app/
├── layout.tsx                              # 루트 레이아웃 (전역)
├── page.tsx                                # "/" 진입
├── (commonLayout)/                         # 일반 로그인 사용자 영역 (URL 영향 X)
│   ├── layout.tsx                          # AppContext + RoleRouteGuard 포함
│   ├── role-route-guard.tsx                # 역할 기반 리다이렉트 (datasetOperator → /datasets)
│   ├── apps/page.tsx                       # /apps  (앱 목록)
│   ├── app/                                # /app   (단수형 — 상세 진입)
│   │   └── (appDetailLayout)/
│   │       └── [appId]/
│   │           ├── layout.tsx              # 앱 상세 사이드바
│   │           ├── overview/page.tsx       # /app/{id}/overview
│   │           ├── configuration/page.tsx  # /app/{id}/configuration
│   │           ├── workflow/page.tsx
│   │           ├── logs/page.tsx
│   │           ├── annotations/page.tsx
│   │           ├── develop/page.tsx
│   │           └── permissions/page.tsx
│   ├── datasets/                           # /datasets
│   │   ├── page.tsx
│   │   ├── connect/, create/, create-from-pipeline/
│   │   └── (datasetDetailLayout)/
│   │       └── [datasetId]/
│   │           ├── documents/, hitTesting/, api/, settings/, pipeline/, permissions/
│   ├── explore/                            # /explore
│   │   ├── layout.tsx
│   │   ├── apps/page.tsx                   # /explore/apps
│   │   └── installed/[appId]/page.tsx      # /explore/installed/{id}
│   ├── tools/page.tsx                      # /tools
│   ├── plugins/page.tsx                    # /plugins
│   └── education-apply/page.tsx            # /education-apply
├── (humanInputLayout)/                     # 외부 폼 (token 기반)
│   └── form/[token]/page.tsx
├── (shareLayout)/                          # 공유 챗봇/완성형/워크플로 (token 기반)
│   ├── chat/[token]/, chatbot/[token]/, completion/[token]/, workflow/[token]/
│   ├── webapp-signin/, webapp-reset-password/
└── install/, init/, signin/, education-apply/    # 인증/온보딩 단발 페이지
```

**탑 네비게이션 (`web/app/components/header/`)에서 직접 링크되는 URL**:
- `/apps`
- `/datasets`
- `/explore/apps`
- `/tools`
- `/plugins`

**컨벤션 요약**:
1. 톱레벨 세그먼트는 **복수형 명사** (`apps`, `datasets`, `tools`, `plugins`) 또는 **도메인 동사/명사** (`explore`, `education-apply`)
2. 상세 진입은 단수형 `app/[appId]`, `datasets/[datasetId]` — 목록/상세 분리
3. Route Group `(commonLayout)`, `(appDetailLayout)` 등은 **레이아웃 그룹화 전용**으로 URL에는 노출되지 않음
4. RBAC는 `(commonLayout)/role-route-guard.tsx`에서 `pathname` 기반으로 일괄 가드 — `datasetOperator`는 `/apps, /app, /explore, /tools` 진입 시 `/datasets`로 redirect

## 어드민 페이지 흔적

**라우트 레벨**: 없음. `web/app/(commonLayout)/admin/` 또는 `web/app/admin/` 디렉토리 부재.
**컴포넌트 레벨**: 다수 존재 — `web/app/components/admin/` 하위에 대시보드 위젯이 이미 구현됨:

```
web/app/components/admin/
├── dashboard-controls/      # 기간 필터 + 새로고침 버튼 (모달 헤더 슬롯에 삽입)
├── kpi-section/             # KPI 카드 4종
├── dept-objects-chart/
├── model-tokens-chart/
├── dept-activity-table/
├── drill-charts/            # Phase 2 드로어용 (calls, errors, objects, users)
└── drill-tables/            # Phase 2 드릴 테이블
```

**마운트 지점**: `web/app/components/header/account-setting/dashboard-page/index.tsx` → 설정 모달의 "대시보드" 탭. URL 변경 없음.

**API 경로 컨벤션** (CLAUDE.md 명시): `/console/api/admin/dashboard/` — **`admin` 네임스페이스를 이미 사용 중**.

## URL 후보 비교 표

| 후보 경로 | 장점 | 단점 |
|----------|------|------|
| **`/admin/dashboard`** | • API 경로(`/console/api/admin/dashboard/`)와 1:1 대칭 — 멘탈 모델 일치<br>• 향후 `/admin/users`, `/admin/audit`, `/admin/objects` 등 어드민 페이지가 **단일 prefix 하위로 묶임**<br>• `role-route-guard.tsx`에 `'/admin'` 한 줄만 추가하면 RBAC 게이트 완성 (admin 역할 외 redirect)<br>• "어드민 전용"이라는 정체성이 URL에 노출됨 (CLAUDE.md 첫 줄과 일치) | • 1개 세그먼트 깊어짐<br>• 현재는 단일 페이지뿐이라 prefix가 잉여로 느껴질 수 있음 |
| **`/dashboard`** | • 가장 짧고 외우기 쉬움<br>• 톱레벨 단일 세그먼트 — 기존 컨벤션(`apps`, `tools`)과 형태 일치 | • "dashboard"가 너무 일반적인 단어 — 향후 사용자별/앱별 대시보드가 생기면 충돌 위험<br>• URL만 봐서는 어드민 전용임을 알 수 없음 → RBAC 가드를 화이트리스트 방식으로 별도 분기 필요<br>• API 경로(`admin/dashboard`)와 어긋남 |
| **`/admin`** (단독) | • 짧음. 현재 단일 페이지 현실과 일치<br>• 내부 탭 전환만 쓴다면 URL 안 늘어남 | • 다른 어드민 페이지가 추가되면 `/admin`이 **랜딩인지 대시보드인지 모호**해짐 — 어쩔 수 없이 `/admin → /admin/dashboard` redirect를 박아야 함<br>• 어드민 사이드바 패턴(`/admin/users` 등)을 도입할 때 root index 처리 추가 작업<br>• 기존 `apps`, `datasets`처럼 명사 한 단어로 끝나지 않아 "무엇의 admin인가"가 불명확 |

### 보조 관찰

- `app/(appDetailLayout)` 패턴을 보면 이 코드베이스는 **detail layout을 group으로 묶는 데 익숙**함. `/admin/dashboard`와 함께 `(commonLayout)/admin/layout.tsx`(또는 `(adminLayout)`)를 둬서 향후 어드민 사이드바를 분리하기 좋음.
- 탑 네비 (Header)는 5개 메뉴로 짜여 있고 어드민 진입은 **계정 메뉴 하위 또는 우상단 아이콘**으로 들어가는 것이 자연스러움 — 톱 네비를 늘리지 않는다는 가정 하에 `/admin/dashboard`가 깊이로 인한 불편 없음.

## 추천 + 근거

**`/admin/dashboard` 추천.** API 경로(`/console/api/admin/dashboard/`)와 정확히 대응되고, `RoleRouteGuard`에 `/admin` prefix 한 줄로 RBAC 게이트를 박을 수 있어 어드민 후속 페이지(`users`, `audit` 등) 확장 비용이 가장 낮음.

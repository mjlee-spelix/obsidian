# 대시보드 라우팅 이동 — 4 사이드바 진입점 분석

> 보고 전용 (코드 변경 없음). 대시보드 메뉴 아이템을 **탐색(Explore) 종속 사이드바**에 추가할 때의 진입점·패턴·아이콘 조사.

## 1. 사이드바 컴포넌트 위치 (파일 + 라인)

| 후보                   | 파일 경로                                                 | 비고                                                                                  |
| -------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------- |
| **탐색 종속 사이드바 (1순위)** | `web/app/components/explore/sidebar/index.tsx`        | `/explore/*` 경로 좌측 패널. "앱 갤러리" + "WEB APPS" 두 영역 (`SideBar` 컴포넌트, line 32–174)      |
| 탐색 영역 마운트 지점         | `web/app/(commonLayout)/explore/layout.tsx`           | `<ExploreClient>` 래퍼로 children 감쌈 (line 8–18). 사이드바 자체는 `ExploreClient` 내부에서 렌더     |
| (참고) 설정 모달 사이드바      | `web/app/components/header/account-setting/index.tsx` | 이미 `ACCOUNT_SETTING_TAB.DASHBOARD` 등록되어 있음 (line 107–112). 모달 닫기 전용 진입점             |
| (참고) 메인 헤더 네비        | `web/app/components/header/index.tsx`                 | `ExploreNav` / `AppNav` / `DatasetNav` / `ToolsNav` 인라인 배치 (line 103–106). 전역 1단 메뉴 |

> 사용자가 명시한 후보 중 `(commonLayout)/layout.tsx`는 `<Header>` + children 컨테이너만 담당하고 사이드바는 갖지 않음. 사이드바는 explore 트리에만 존재.

## 2. 메뉴 아이템 등록 패턴

### 2-A. 탐색 종속 사이드바 — **인라인 JSX 슬롯** (배열 아님)
- `web/app/components/explore/sidebar/index.tsx`
- 메뉴 데이터 구조 없음. JSX 직접 작성.
- 슬롯 구성:
  1. **최상단 단일 링크** (`/explore/apps` "앱 갤러리", line 90–101) — `Link` + `i-ri-apps-fill` 아이콘 + `isDiscoverySelected` 활성 스타일
  2. **WEB APPS 섹션** (line 110–133) — `useGetInstalledApps()` 결과를 `installedAppItems`로 map (line 65–86), `AppNavItem`으로 렌더
  3. **하단 접기 버튼** (line 135–150)
- 활성 판별: `useSelectedLayoutSegments()` 의 마지막 segment 비교 (`lastSegment === 'apps'`).
- 폴드(`isFold`) / 모바일(`isMobile`) 상태에 따라 라벨 숨김 처리.

### 2-B. 설정 모달 사이드바 — **GroupItem[] 배열 + map** (대조용 참고)
- `web/app/components/header/account-setting/index.tsx`
- `workplaceGroupItems: GroupItem[]` 배열 (line 59–125)을 IIFE로 빌드 → `menuItems` 그룹 묶음(line 130–148) → `map`으로 렌더(line 175–203).
- `GroupItem` 필드: `key`, `name`, `description?`, `icon`, `activeIcon`
- 조건부 노출 패턴:
  - `isCurrentWorkspaceDatasetOperator` 시 빈 배열 (line 60–61)
  - `enableBilling` 시 push (line 84–92)
  - `enableReplaceWebAppLogo || enableBilling` 시 push (line 115–122)
- 대시보드 항목은 **무조건 push** (line 107–113) — 권한 게이트 없음.

### 2-C. 메인 헤더 네비 — **컴포넌트별 분리, 권한 인라인 가드**
- `web/app/components/header/index.tsx` line 103–106
- 각 `*Nav` 컴포넌트(`ExploreNav` 등) 별도 파일에서 `useSelectedLayoutSegment()` 로 자기 자신 활성 판별.
- 권한 가드는 부모(`Header`)에서 `&&` 인라인 (`!isCurrentWorkspaceDatasetOperator && <ExploreNav .../>`).

## 3. 추가 위치 + 방식 (코드 예시 — 미적용)

### 옵션 A. 탐색 사이드바 상단에 "DISCOVERY"와 나란히 한 줄 추가 (1순위 추천)
- 위치: `web/app/components/explore/sidebar/index.tsx` line 89–101 직후 (WEB APPS 섹션 line 110 직전).
- 이유: "앱 갤러리"와 같은 1단계 진입점 격으로 시각적 동등 처리. WEB APPS는 사용자 설치 앱이라 의미 계층이 다름.
- 활성 판별: `lastSegment === 'dashboard'` 또는 `segments.includes('dashboard')`.

```tsx
// 기존 line 90-101 "앱 갤러리" 블록 직후 삽입 (예시 — 미적용)
const isDashboardSelected = lastSegment === 'dashboard'

<div className={cn(isDashboardSelected ? 'text-text-accent' : 'text-text-tertiary')}>
  <Link
    href="/explore/dashboard"   // 실제 라우트는 라우팅 설계 결정에 따름
    aria-label={isMobile || isFold ? t('sidebar.dashboard', { ns: 'explore' }) : undefined}
    className={cn(
      isDashboardSelected ? 'bg-state-base-active' : 'hover:bg-state-base-hover',
      'flex h-8 items-center gap-2 rounded-lg px-1 mobile:w-fit mobile:justify-center pc:w-full pc:justify-start',
    )}
  >
    <div className="flex size-6 shrink-0 items-center justify-center rounded-md bg-components-icon-bg-blue-solid">
      <span aria-hidden="true" className="i-ri-dashboard-fill size-3.5 text-components-avatar-shape-fill-stop-100" />
    </div>
    {!isMobile && !isFold && (
      <div className={cn(
        'truncate',
        isDashboardSelected
          ? 'text-components-menu-item-text-active system-sm-semibold'
          : 'text-components-menu-item-text system-sm-regular',
      )}>
        {t('sidebar.dashboard', { ns: 'explore' })}
      </div>
    )}
  </Link>
</div>
```

추가 필요 작업:
- i18n: `web/i18n/ko-KR/explore.json` / `web/i18n/en-US/explore.json` 에 `"sidebar.dashboard"` 키 추가 (현재 사이드바에 사용중인 키: `sidebar.title`, `sidebar.webApps`, `sidebar.noApps.*`).
- 권한 가드: 어드민 전용이라면 `useAppContext()` 의 적절한 플래그(예: `isCurrentWorkspaceOwner`)로 조건부 렌더.

### 옵션 B. WEB APPS 섹션과 같은 레벨의 별도 그룹 (2순위)
- 위치: line 110 `installedApps.length > 0 &&` 블록 위 또는 아래에 새 그룹 추가.
- 이유: "관리(Admin)" 같은 별도 라벨로 묶을 명분이 생기면 채택. 현재는 항목이 1개라 옵션 A가 단순.

### 옵션 C. (비추천) 메뉴 데이터 구조로 리팩토링 후 등록
- 인라인 JSX → `items: NavItem[]` 배열로 변환 후 map.
- 변경 범위가 사이드바 전체에 미치므로 진입점 추가 작업의 비용 대비 효과 낮음. 별도 리팩토링 안건으로 분리 권장.

## 4. 아이콘 컨벤션 + 추천

### 컨벤션 (이 레포지토리 3가지 혼재)
| 방식 | 사용처 | 예시 |
|------|--------|------|
| **iconify CSS 클래스 `i-ri-*-line` / `i-ri-*-fill`** (UnoCSS preset) | 설정 모달 메뉴, **탐색 사이드바 본문** | `<span className="i-ri-apps-fill size-3.5" />` (explore/sidebar `index.tsx:97`), `<span className="i-ri-dashboard-line w-5 h-5" />` (account-setting `index.tsx:110`) |
| **`@remixicon/react` React 컴포넌트** | 헤더 1단 네비 (`*Nav`) | `import { RiPlanetFill, RiPlanetLine } from '@remixicon/react'` (explore-nav `index.tsx:3-6`) |
| 자체 SVG / lucide | 발견되지 않음 (이 영역에서) | — |

> 같은 remix-icon 패밀리지만 사이드바 본문은 CSS 클래스 방식이 표준. **옵션 A 적용 시 CSS 클래스 방식으로 작성**해 주변과 일치시키는 것을 권장.

### 대시보드 아이콘 추천 (1~2순위)
1. **`i-ri-dashboard-line` / `i-ri-dashboard-fill`** (강력 추천)
   - 이미 `account-setting/index.tsx:110-111` 에서 사용 중 → **앱 전체 일관성** 확보.
   - 사용자가 "설정 모달의 대시보드 탭"을 이미 학습한 상태이므로 아이콘 동일성이 인지 전이를 돕는다.
2. **`i-ri-bar-chart-2-line` / `i-ri-bar-chart-2-fill`** (대안)
   - 차트 중심 화면임을 강조하고 싶을 때.
   - 단점: 대시보드 탭 아이콘과 어긋남 → 동일 기능에 두 아이콘이 생기는 인지 부담.
3. (참고) `i-ri-pie-chart-line/fill`, `i-ri-line-chart-line/fill` — 부서/모델 차트 비중이 더 크다고 보면 채택 가능. 권장 순위 밖.

### 활성/비활성 처리 패턴 (이 레포의 관용)
- `*-line` (outline) = 비활성 / `*-fill` (filled) = 활성. 설정 모달, 헤더 ExploreNav 모두 동일 규칙.
- 옵션 A 코드 예시에서는 단순화를 위해 `i-ri-dashboard-fill` 한 종류만 표기 — 실제 적용 시 `isDashboardSelected ? 'i-ri-dashboard-fill' : 'i-ri-dashboard-line'` 분기 권장.

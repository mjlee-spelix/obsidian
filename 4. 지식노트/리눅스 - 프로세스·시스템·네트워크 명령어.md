# 리눅스 - 프로세스·시스템·네트워크 명령어

## 핵심
- 서버에서 "뭐가 느린지, 뭐가 돌아가고 있는지, 디스크/메모리 괜찮은지" 확인하는 명령어들
- `ps aux | grep` 조합은 특정 프로세스 찾을 때 가장 많이 쓰는 패턴
- `curl`은 API 테스트할 때 필수, `ssh`/`scp`는 서버 접속/파일 전송에 필수
- 서버 장애 시 확인 순서: 프로세스(`ps`) → 메모리(`free`) → 디스크(`df`) → 네트워크(`ping`, `ss`)

## 상세

### 프로세스 관리

#### ps — 프로세스 목록

```bash
ps                         # 현재 터미널의 프로세스만
ps aux                     # 시스템 전체 프로세스 (가장 많이 씀)
ps aux | grep python       # python 관련 프로세스만 필터
ps -ef                     # 부모-자식 관계까지 보기
```

`ps aux` 출력 읽는 법:
```
USER  PID  %CPU %MEM    VSZ   RSS TTY STAT START TIME COMMAND
root  1234  0.5  2.1 123456 45678 ?   Sl   Apr22 1:23 python app.py
      └ PID     └ CPU/메모리 사용률                    └ 실행 명령어
```

#### top / htop — 실시간 시스템 모니터링

```bash
top                        # 실시간 프로세스 모니터링 (q로 나가기)
htop                       # top의 개선 버전 (색상, 마우스 지원) — 설치 필요
```

top 안에서 유용한 키:
| 키 | 동작 |
|----|------|
| `q` | 나가기 |
| `P` | CPU 사용률 순 정렬 |
| `M` | 메모리 사용률 순 정렬 |
| `k` | 프로세스 종료 (PID 입력) |

#### kill — 프로세스 종료

```bash
kill 1234                  # PID 1234 프로세스에 종료 신호 (정상 종료 요청)
kill -9 1234               # 강제 종료 (안 죽을 때 사용)
kill -15 1234              # 정상 종료 (= kill 1234)
killall python             # 이름으로 전부 종료
```

**흔한 패턴:**
```bash
# 특정 프로세스 찾아서 죽이기
ps aux | grep "python app.py"    # PID 확인
kill 1234                        # 종료
```

### 시스템 리소스 확인

#### df — 디스크 용량

```bash
df -h                      # 전체 디스크 사용량 (사람이 읽기 쉬운 단위)
df -h /                    # 루트 파티션만
```

```
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        50G   35G   13G  73% /
                              └── 여유 공간    └── 사용률 (90% 넘으면 위험!)
```

#### du — 폴더별 용량

```bash
du -sh *                   # 현재 디렉토리의 폴더별 크기
du -sh /var/log            # 특정 폴더 크기
du -sh * | sort -rh        # 큰 순서대로 정렬
du -sh * | sort -rh | head # 가장 큰 10개만
```

- 디스크가 꽉 찼을 때 `du -sh * | sort -rh`로 뭐가 큰지 추적

#### free — 메모리 확인

```bash
free -h                    # 메모리 사용량
free -h -s 3               # 3초마다 갱신
```

```
              total    used    free    shared  buff/cache  available
Mem:           16G     8.5G    1.2G      256M        6.3G       7.0G
                                                              └── 실제 사용 가능 (이걸 봐야 함!)
```

- `available`이 실제로 쓸 수 있는 메모리 (free만 보면 안 됨)

### 네트워크

#### curl — HTTP 요청

```bash
curl https://example.com                    # GET 요청
curl -X POST https://api.com/data           # POST 요청
curl -X POST -H "Content-Type: application/json" \
     -d '{"key": "value"}' https://api.com  # JSON POST
curl -o 파일명 https://example.com/file     # 파일 다운로드
curl -I https://example.com                 # 헤더만 확인
curl -v https://example.com                 # 상세 출력 (디버깅용)
```

- API 테스트할 때 Postman 대신 빠르게 확인 가능

#### wget — 파일 다운로드

```bash
wget https://example.com/file.tar.gz        # 파일 다운로드
wget -O 새이름.tar.gz https://example.com/file.tar.gz  # 이름 지정
```

#### ping — 연결 확인

```bash
ping google.com            # 연결 확인 (Ctrl+C로 중지)
ping -c 5 192.168.10.200   # 5번만 테스트
```

- 서버가 살아있는지 가장 빠르게 확인하는 방법

#### netstat / ss — 포트/연결 상태

```bash
# 열린 포트 확인
ss -tlnp                   # TCP 리스닝 포트 + 프로세스 (최신 방식)
netstat -tlnp              # 같은 용도 (구버전)

# 특정 포트 확인
ss -tlnp | grep 8080       # 8080 포트 누가 쓰고 있는지
```

| 옵션 | 의미 |
|------|------|
| `-t` | TCP만 |
| `-l` | 리스닝(대기) 중인 것만 |
| `-n` | 포트 번호로 표시 (이름 대신) |
| `-p` | 프로세스 정보 포함 |

#### ssh — 원격 서버 접속

```bash
ssh user@192.168.10.200            # 기본 접속 (22번 포트)
ssh -p 2222 user@server.com        # 포트 지정
ssh -i ~/.ssh/id_rsa user@server   # 키 파일 지정
```

#### scp — 서버 간 파일 복사

```bash
# 로컬 → 원격
scp 파일.txt user@192.168.10.200:/home/user/

# 원격 → 로컬
scp user@192.168.10.200:/home/user/파일.txt ./

# 폴더 전체 복사
scp -r 폴더/ user@192.168.10.200:/home/user/
```

### 서버 장애 시 확인 순서

```
1. 서비스 살아있나?     → ps aux | grep 서비스명
2. 메모리 부족?        → free -h (available 확인)
3. 디스크 꽉 찼나?     → df -h (90% 이상이면 위험)
4. 뭐가 디스크 먹나?   → du -sh * | sort -rh
5. 네트워크 문제?      → ping, ss -tlnp
6. 로그 확인          → tail -f /var/log/syslog
```

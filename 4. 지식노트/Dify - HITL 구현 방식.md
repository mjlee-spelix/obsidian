# Dify - HITL 구현 방식

## 핵심
- Dify 자체 Human Input 노드를 워크플로우 중간에 삽입하는 것이 아닌, **Memory 기반 + Client Orchestration** 방식으로 HITL 구현
- UI 레벨에서 팝업 처리 → 사용자는 워크플로우가 끊기지 않는 것처럼 느낌

## 상세

### 구현 원리
1. 워크플로우가 한 번 실행되며 중간 결과를 **Memory에 저장**
2. 사용자 입력이 필요한 시점에 UI 레벨에서 팝업/프롬프트 표시
3. 사용자 입력을 **이전 대화 내용과 함께 다시 에이전트에 전달** (input → agent → output 반복)
4. Agent의 **Memory 기능**으로 대화 맥락 유지

```
[흐름]
사용자 요청
  → 에이전트 실행 (메모리에 기록)
  → 중간 확인 필요 시 UI 팝업 (레이아웃 팝업)
  → 사용자 응답 + 이전 대화 내용 → 에이전트 재실행
  → 최종 결과 반환
```

### UI 처리
- **레이아웃 팝업** 방식: 에이전트/워크플로우가 끊기지 않아 보이도록
- Front/Back 어디서든 구현 가능 (JS 라이브러리 무관, JSON 형태만 맞추면 됨)
- Client에서 Orchestration 처리

### Human Input 노드 vs Memory 방식 비교

| | Human Input 노드 | Memory 기반 |
|---|---|---|
| **구현 위치** | Dify 워크플로우 내부 | Client 레벨 |
| **API 연동** | 복잡 (미검증) | 상대적으로 단순 |
| **UX** | 워크플로우 일시 정지 | 자연스러운 대화 흐름 |
| **권장 여부** | 단순 케이스 | 복잡한 다단계 확인 |

# Dify - 멀티 에이전트 설계 패턴

## 핵심
- 마스터 에이전트 + 서브 에이전트 구조로 역할 분리
- 마스터는 큰 카테고리만 판단, 세부 처리는 서브 에이전트에 위임

## 상세

### 구현 방법 2가지

#### 방법 1. 질문 분류기 기반 분기
- 질문 분류기 노드에 클래스 설정 + 클래스별 설명 작성
- 사용자 요청 → 분류기가 자동으로 해당 에이전트로 분기

#### 방법 2. 서브 에이전트를 도구로 등록
- 마스터 에이전트에 서브 에이전트들을 **도구(Tool)**로 등록
- 마스터가 사무, 유틸 등 큰 카테고리 판단 → 서브 실행

### 마스터 / 서브 역할 분리 원칙

| 마스터 에이전트 | 서브 에이전트 |
|---|---|
| 기본적인 질문 답변 | 케이스에 종속된 처리 |
| 큰 카테고리 판단 | 도메인 특화 로직 |
| 전체 흐름 오케스트레이션 | 메일 주소 없을 때 사용자에게 묻기 등 |

- 마스터에 모든 도구 설명 X → 도구 설명이 너무 길어져 성능 저하
- 공통 유틸(메일 발송 등)은 **util agent**로 분리해 재사용

### 통합 챗봇 구성 방향
- **통합 챗봇**: 인사/복지 규정 등 일반 질문
- **개별 챗봇**: 매출 분석, 전자결재 등 업무별
- 임베디드 코파일럿이 이상적이나 기존 앱 수정 필요한 어려움 있음

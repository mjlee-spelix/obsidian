# LangGraph Checkpointer와 상태 저장

> State가 "지금 이 순간의 메모리"라면, Checkpointer는 그 메모리를 **저장/재개**하는 장치.

## 핵심
- **Checkpointer** = 그래프 실행 중간의 State를 저장하는 지속성(persistence) 계층.
- 이걸 붙이면 세 가지가 가능해진다:
  - **메모리**: 이전 대화/실행 상태를 기억 (멀티턴 챗봇)
  - **중단/재개**: 도중에 멈췄다가 나중에 이어서 실행
  - **Human-in-the-loop**: 특정 지점에서 멈춰 사람 승인을 받고 재개

## 상세
개념 구조 (Python):
```python
from langgraph.checkpoint.memory import MemorySaver

checkpointer = MemorySaver()             # 실습용 인메모리 (운영은 DB 기반 사용)
graph = builder.compile(checkpointer=checkpointer)

# thread_id로 "대화 세션"을 구분 — 같은 id면 상태가 이어짐
config = {"configurable": {"thread_id": "user-123"}}
graph.invoke({"messages": [{"role": "user", "content": "안녕"}]}, config)
graph.invoke({"messages": [{"role": "user", "content": "방금 뭐라 했지?"}]}, config)
# → 두 번째 호출이 첫 번째 상태를 기억함
```

기억할 점:
- **`thread_id`** 가 핵심 — 세션(대화)별로 상태를 분리/유지하는 열쇠.
- 실습은 `MemorySaver`(휘발성), 운영은 SQLite/Postgres 등 **영속 Checkpointer**로 교체.
- Human-in-the-loop: 특정 노드 앞에서 실행을 멈추고(interrupt), 사람이 State를 확인/수정한 뒤 재개하는 흐름의 기반이 바로 이 Checkpointer.

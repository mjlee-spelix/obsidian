# LangGraph로 사고하기 - 5단계 설계법

> 공식 문서 "Thinking in LangGraph"의 핵심. API보다 **사고방식**을 먼저 익히는 게 중요.

## 핵심
- LangGraph로 에이전트를 만들 땐 항상 같은 흐름을 따른다:
  **① 프로세스를 단계로 쪼갠다 → ② 각 단계가 뭘 하는지 정한다 → ③ State 설계 → ④ Node 구현 → ⑤ Edge로 연결**
- 즉, "코드부터"가 아니라 **"이 업무를 어떤 단계들로 나눌 수 있지?"** 부터 그린다.

## 상세
예시: 고객 지원 이메일 처리 에이전트
- **Step 1. 워크플로우를 단계로 매핑**: 이메일 읽기 → 의도 분류 → 문서 검색 → 답변 초안 → 사람 검토 → 발송. 각 단계가 하나의 **Node** 가 된다.
- **Step 2. 각 단계의 성격 파악** — 4가지 유형으로 분류:
  - LLM 단계 (이해/분석/생성/판단) — 예: 의도 분류, 답변 초안
  - Data 단계 (외부 정보 조회) — 예: 문서 검색
  - Action 단계 (외부 동작 수행) — 예: 이메일 발송
  - User input 단계 (사람 개입) — 예: 관리자 검토
- **Step 3. State 설계**: 모든 노드가 공유하는 "메모장". 노드들이 여기 읽고 쓴다. → [[02. LangGraph 핵심 개념 - State, Node, Edge]]
- **Step 4~5. Node 구현 + Edge 연결**: 어떤 노드는 항상 다음 단계로 가고(고정 엣지), 어떤 노드는 상황에 따라 갈림길을 정한다(조건부 엣지). → [[03. LangGraph 조건부 엣지와 분기]]

> 팁: 노드 중 "다음에 어디로 갈지 결정하는 노드"와 "항상 같은 곳으로 가는 노드"를 구분하는 게 설계의 핵심.

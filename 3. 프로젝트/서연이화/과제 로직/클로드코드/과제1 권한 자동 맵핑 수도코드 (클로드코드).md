# 과제 1: 인사 정보 기반 권한 자동 맵핑 — 수도 코드 (클로드코드)

> **작성 기준**
> - [[서연이화 과제별 구현 로직 (클로드코드)]] 문서의 과제 1 로직을 **언어 비종속 수도 코드**로 구체화한 문서.
> - 특정 언어·DB·프레임워크에 종속되지 않도록 일반 의사코드로 작성한다. (`함수`, `반복`, `조건`, `집합 연산` 등)
> - 📍 = 핵심 구현 작업.
> - 핵심 설계 불변식(invariant): **① 멱등성** — 같은 배치를 두 번 돌려도 결과 동일, **② 결정성** — 같은 입력 → 같은 출력, **③ 감사 추적** — 모든 변경은 근거(룰ID)와 함께 기록.

## 0. 데이터 구조 정의

```
// ── 입력: 그룹웨어 인사변동 이벤트 ──
구조체 인사변동이벤트:
    event_id        : 식별자          // 멱등 처리 키
    사번            : 문자열
    변동유형        : 열거형 { 입사, 이동, 승진, 퇴사 }
    이전부서        : 부서코드 | 없음
    신규부서        : 부서코드 | 없음
    직급            : 문자열
    발령일          : 날짜
    처리상태        : 열거형 { 미처리, 처리완료, 격리, 실패 }

// ── 정책: 데이터로 외부화 (코드 아님) ──
구조체 권한정책:
    policy_id       : 식별자
    조건_부서코드   : 부서코드 | 와일드카드(*)
    조건_직급       : 문자열   | 와일드카드(*)
    부여대상        : 권한항목 집합   // 역할/메뉴/기능
    동작            : 열거형 { grant, revoke }
    우선순위        : 정수            // 충돌 해소용 (낮을수록 우선)

// ── 상태: 사용자별 현재 권한 스냅샷 ──
구조체 사용자권한:
    사번            : 문자열
    권한항목        : 권한항목
    상태            : 열거형 { 활성, 회수 }
    부여근거        : policy_id

// ── 감사: 모든 변경 이력 ──
구조체 변경이력:
    log_id          : 식별자
    사번            : 문자열
    권한항목        : 권한항목
    변경전          : 상태
    변경후          : 상태
    적용룰          : policy_id
    처리시각        : 타임스탬프
    결과            : 열거형 { 성공, 실패, 스킵 }
```

## 1. 메인 배치 (진입점)

```
함수 권한맵핑_일배치():
    run_id   = 새_실행ID()
    배치로그_시작(run_id)

    // [1] 수집 — 실패 시 전체 중단 (부분 데이터로 권한 변경 금지)
    시도:
        이벤트목록 = 수집_인사변동_증분()          // 2장
    예외 e:
        알림_발송("수집 실패 — 배치 중단", e)
        배치로그_종료(run_id, 상태=수집실패)
        반환

    // [2] 정규화·검증 — 불량 데이터는 격리하고 정상분만 진행
    (정상목록, 격리목록) = 정규화_및_검증(이벤트목록)   // 3장
    각 evt in 격리목록:
        evt.처리상태 = 격리
        기록_격리(evt, 사유)

    // [3] 이벤트 정렬·병합 (동일인 동일발령일 다중 이벤트 대비)
    처리단위목록 = 정렬_및_병합(정상목록)             // 4장

    재처리큐 = 빈_큐()

    // [4] 처리단위별 권한 산출 → Diff → 적용
    각 단위 in 처리단위목록:
        시도:
            목표권한 = 룰엔진_정책평가(단위)          // 📍 5장
            현재권한 = 조회_현재권한(단위.사번)
            diff     = 권한_Diff(현재권한, 목표권한)   // 📍 6장

            만약 diff.변경없음():
                기록_감사(단위.사번, 결과=스킵)       // 멱등: 변경 0건
                계속

            적용결과 = 권한_변경_적용(단위.사번, diff) // 7장
            기록_감사_일괄(단위.사번, diff, 적용결과)  // 📍 8장

            만약 적용결과.부분실패():
                재처리큐.추가(적용결과.실패분)
        예외 e:
            재처리큐.추가(단위)
            기록_감사(단위.사번, 결과=실패, 사유=e)

    // [5] 마무리
    처리_재처리큐(재처리큐)                          // 9장
    리포트 = 집계_결과(run_id)
    배치로그_종료(run_id, 상태=완료, 리포트)
    알림_발송_요약(리포트)                            // 부여 N / 회수 M / 실패 K
```

## 2. 수집 (증분)

```
함수 수집_인사변동_증분() -> 이벤트목록:
    마지막처리시각 = 조회_체크포인트()               // 전체 재처리 방지

    원본 = 외부어댑터.조회_인사변동(
        이후시각 = 마지막처리시각,
        재시도   = 3,                                // 타임아웃·재시도 필수
        백오프   = 지수백오프
    )

    적재_staging(원본)                                // 원본 보존 후 가공
    이벤트목록 = 파싱(원본)

    // 수집 성공 시에만 체크포인트 전진 (실패 시 다음 배치가 재수집)
    갱신_체크포인트(현재시각())
    반환 이벤트목록
```

> **유의**: 체크포인트는 **처리 성공 후 전진**시켜야 누락이 없다. 수집 0건은 정상(변동 없음)일 수 있으나, 어댑터 오류로 인한 0건과 구분하기 위해 응답 메타(HTTP 상태 등)를 함께 검증한다.

## 3. 정규화·검증

```
함수 정규화_및_검증(이벤트목록) -> (정상, 격리):
    정상 = []
    격리 = []
    각 evt in 이벤트목록:
        // 필수값 검증
        만약 비어있음(evt.사번) 또는 비어있음(evt.변동유형):
            격리.추가(evt, 사유="필수값 누락"); 계속

        // 마스터 정합성 (부서 구조는 플랫 → 상위부서 상속 없음)
        만약 evt.사번 not in 사번마스터:
            격리.추가(evt, 사유="미등록 사번"); 계속
        만약 evt.변동유형 in {이동, 승진} 그리고 evt.신규부서 not in 부서마스터:
            격리.추가(evt, 사유="미등록 부서코드"); 계속

        // 정규화 (부서코드 표준화, 직급 표기 통일 등)
        evt.신규부서 = 표준화_부서코드(evt.신규부서)
        evt.직급     = 표준화_직급(evt.직급)
        정상.추가(evt)
    반환 (정상, 격리)
```

## 4. 이벤트 정렬·병합

```
// 동일인의 동일 발령일에 복수 이벤트(예: 이동 + 승진)가 올 수 있음
함수 정렬_및_병합(정상목록) -> 처리단위목록:
    그룹 = 그룹화(정상목록, 기준=(사번, 발령일))
    처리단위목록 = []
    각 (키, 이벤트들) in 그룹:
        // 우선순위 정렬: 퇴사 > 이동 > 승진 > 입사
        //  - 퇴사가 섞이면 다른 변동은 무의미 → 퇴사로 수렴
        정렬(이벤트들, 기준=변동유형_우선순위)
        만약 이벤트들 에 퇴사 포함:
            처리단위목록.추가( 처리단위(키.사번, 최종유형=퇴사) )
        아니면:
            병합본 = 병합_이벤트(이벤트들)   // 최종 부서·직급으로 수렴
            처리단위목록.추가( 처리단위(키.사번, 병합본) )
    반환 처리단위목록
```

> **유의**: 병합 규칙은 비즈니스 확인 사항. "이동+승진 동시 발령" 시 신규부서+신규직급을 함께 반영하는 것이 일반적이나, 고객사 정책으로 확정 필요.

## 5. 📍 룰엔진 정책 평가

```
// 결정적: 같은 (부서, 직급, 변동유형) → 같은 권한셋
함수 룰엔진_정책평가(단위) -> 목표권한셋:
    만약 단위.최종유형 == 퇴사:
        반환 빈_집합()                       // 전체 회수 → 목표권한 없음

    // 1) 매칭되는 정책 수집 (와일드카드 포함)
    후보정책 = []
    각 정책 in 권한정책_전체():
        만약 매칭(정책.조건_부서코드, 단위.부서)
           그리고 매칭(정책.조건_직급, 단위.직급):
            후보정책.추가(정책)

    // 2) 우선순위로 충돌 해소 (낮은 우선순위 값이 우선)
    정렬(후보정책, 기준=우선순위)

    목표권한셋 = 빈_집합()
    각 정책 in 후보정책:
        만약 정책.동작 == grant:
            목표권한셋.합집합(정책.부여대상)
        아니면: // revoke
            목표권한셋.차집합(정책.부여대상)

    // 3) 예외 케이스 분기
    목표권한셋 = 예외처리(목표권한셋, 단위)
    반환 목표권한셋


함수 예외처리(권한셋, 단위) -> 권한셋:
    조건분기 단위.최종유형:
        case 입사:
            // 신규 입사 기본 권한 보강
            권한셋.합집합( 기본권한_신규입사(단위.부서) )
        case 이동:
            // 이전부서 전용 권한은 룰엔진 산출 결과에 이미 미포함
            // (목표셋 기준이므로 Diff 단계에서 자동 회수됨)
            통과
    // 신설부서: 정책 미존재 시
    만약 단위.부서 not in 정책_보유부서:
        권한셋.합집합( 기본권한_신설부서() )
        플래그_검토필요(단위, "신설부서 정책 미정의")
    // 1인부서: 승인자 부재 → 대체 승인라인/관리자 권한 정책
    만약 부서_인원수(단위.부서) == 1:
        권한셋 = 적용_1인부서정책(권한셋, 단위)
    반환 권한셋
```

> **유의**: 정책·예외 규칙은 모두 **데이터로 외부화**(권한정책 테이블 + 예외 설정값). 코드에는 "평가 방법"만 두고 "정책 내용"은 두지 않는다 → 정책 추가가 코드 배포 없이 데이터 변경으로 가능.

## 6. 📍 권한 Diff 산출 (멱등성의 핵심)

```
함수 권한_Diff(현재권한셋, 목표권한셋) -> diff:
    현재활성 = { p.권한항목 for p in 현재권한셋 if p.상태 == 활성 }

    부여대상 = 목표권한셋 - 현재활성        // 목표엔 있고 현재 없음
    회수대상 = 현재활성  - 목표권한셋        // 현재 있고 목표에 없음

    반환 diff(부여=부여대상, 회수=회수대상)


함수 diff.변경없음() -> 불리언:
    반환 비어있음(diff.부여) 그리고 비어있음(diff.회수)
```

> **유의**: 이미 일치하는 권한은 절대 건드리지 않는다(불필요한 쓰기·로그 방지). 이 집합 연산이 멱등성을 보장한다 — 두 번째 실행 시 `부여=∅, 회수=∅` 이 되어 변경 0건.

## 7. 권한 변경 적용

```
함수 권한_변경_적용(사번, diff) -> 적용결과:
    성공 = []; 실패 = []

    // 회수를 부여보다 먼저 (보안: 과다 권한을 먼저 제거)
    각 항목 in diff.회수:
        r = 외부어댑터.회수권한(사번, 항목, 멱등키=(사번, 항목, "revoke"))
        (r.ok ? 성공 : 실패).추가(항목)

    각 항목 in diff.부여:
        r = 외부어댑터.부여권한(사번, 항목, 멱등키=(사번, 항목, "grant"))
        (r.ok ? 성공 : 실패).추가(항목)

    반환 적용결과(성공, 실패)
```

> **유의**: 멱등키를 외부 시스템 호출에 부여해 재시도 시 중복 적용을 막는다. 부분 실패는 정상 시나리오로 간주하고 성공분/실패분을 분리한다(전체 롤백 여부는 업무 규칙으로 결정).

## 8. 📍 감사 기록

```
함수 기록_감사_일괄(사번, diff, 적용결과):
    각 항목 in diff.회수:
        결과 = (항목 in 적용결과.실패) ? 실패 : 성공
        적재_변경이력( 변경이력(
            사번=사번, 권한항목=항목,
            변경전=활성, 변경후=회수,
            적용룰=근거룰(항목), 처리시각=현재시각(), 결과=결과 ))
    각 항목 in diff.부여:
        결과 = (항목 in 적용결과.실패) ? 실패 : 성공
        적재_변경이력( 변경이력(
            사번=사번, 권한항목=항목,
            변경전=회수, 변경후=활성,
            적용룰=근거룰(항목), 처리시각=현재시각(), 결과=결과 ))
```

> **유의**: 모든 변경은 **적용 룰ID(근거)** 와 함께 기록 → "왜 이 권한이 바뀌었나"를 역추적 가능. 권한은 보안·감사 대상이므로 추적성이 기능 요건 자체다.

## 9. 재처리 큐

```
함수 처리_재처리큐(큐):
    각 항목 in 큐:
        만약 항목.재시도횟수 < 최대재시도:
            항목.재시도횟수 += 1
            지연_재투입(큐, 항목, 지연=백오프(항목.재시도횟수))  // 지수 백오프
        아니면:
            기록_영구실패(항목)
            알림_발송("권한 변경 영구 실패 — 수동 처리 필요", 항목)
```

> **유의**: 무한 재시도 방지를 위해 재시도 상한·백오프를 둔다. 상한 초과는 담당자에게 알려 수동 처리로 전환.

## 10. 테스트 관점 (결정적 로직이라 단위 테스트가 쉬움)

```
// 룰엔진은 순수 함수 → 입력만 주면 출력 검증 가능
테스트 "이동 시 이전부서 권한 회수 + 신규부서 권한 부여":
    단위    = 처리단위(사번="A", 부서="영업2", 직급="대리", 최종유형=이동)
    현재    = { "영업1-메뉴", "공통-메뉴" }
    목표    = 룰엔진_정책평가(단위)          // 기대: { "영업2-메뉴", "공통-메뉴" }
    diff    = 권한_Diff(현재, 목표)
    단언 diff.부여 == { "영업2-메뉴" }
    단언 diff.회수 == { "영업1-메뉴" }

테스트 "멱등성 — 두 번째 실행은 변경 0건":
    목표    = 룰엔진_정책평가(단위)
    diff1   = 권한_Diff(현재, 목표);  권한_변경_적용("A", diff1)
    현재2   = 조회_현재권한("A")
    diff2   = 권한_Diff(현재2, 목표)
    단언 diff2.변경없음() == 참

테스트 "퇴사 시 전체 회수":
    단위    = 처리단위(사번="A", 최종유형=퇴사)
    목표    = 룰엔진_정책평가(단위)          // 기대: 빈 집합
    단언 비어있음(목표)
```

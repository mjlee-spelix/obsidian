# 과제 1. 인사 정보 기반 권한 자동 맵핑 수도코드

## 1. 목적

인사 변동 정보를 기준으로 업무 시스템 권한을 자동 부여·회수한다.  
신규 입사, 부서 이동, 직급 변경, 겸직, 휴직, 퇴사 같은 이벤트를 처리하고, 자동 처리할 수 없는 예외는 담당자 검토 대상으로 분리한다.

---

```text
HrChangeEvent

  employee_name      이름

  before_dept_code   변경 전 부서코드
  after_dept_code    변경 후 부서코드

  after_grade_code   변경 후 직급코드
  employment_status  재직상태: ACTIVE, LEAVE, RETIRED
```

## 3. 전체 프로세스

```text
인사 변동 데이터 조회 -> 정렬 -> 데이터 검증 -> 사용자 현재 권한 조회 -> 목표 권한 계산 -> 권한 변경안 생성 -> 충돌·예외 검증 -> 권한 변경 실행 -> 처리 이력 저장 -> 실패·승인 필요 건 알림
```

## 4. 메인 배치 수도코드

```pseudocode
FUNCTION runPermissionMappingBatch(batch_date):
    hr_events = fetchHrChangeEvents(batch_date)
    policies = fetchActivePermissionPolicies()
    user_master = fetchUserMaster()

    sorted_events = sortEvents(hr_events)

    batch_result = {
        success_count: 0,
        fail_count: 0,
        approval_required_count: 0,
        skipped_count: 0
    }

    FOR EACH event IN sorted_events:
        process_id = createProcessLog(event)

        TRY:
            validation_result = validateHrEvent(event, user_master)

            IF validation_result.is_valid == FALSE:
                saveException(process_id, event, validation_result.errors)
                markProcessAsFailed(process_id, "VALIDATION_FAILED")
                batch_result.fail_count += 1
                CONTINUE

            current_state = fetchCurrentPermissionState(event.employee_id)

            target_permissions = calculateTargetPermissions(
                event,
                current_state,
                policies
            )

            change_plan = buildPermissionChangePlan(
                current_state.current_permissions,
                target_permissions
            )

            review_result = reviewChangePlan(
                event,
                current_state,
                change_plan,
                policies
            )

            IF review_result.requires_manual_review == TRUE:
                saveManualReviewRequest(process_id, event, change_plan, review_result.reasons)
                markProcessAsPendingApproval(process_id)
                batch_result.approval_required_count += 1
                CONTINUE

            execution_result = executePermissionChange(event.employee_id, change_plan)

            IF execution_result.is_success == TRUE:
                savePermissionHistory(process_id, event, current_state, change_plan, execution_result)
                markProcessAsSuccess(process_id)
                batch_result.success_count += 1
            ELSE:
                saveException(process_id, event, execution_result.errors)
                markProcessAsFailed(process_id, "EXECUTION_FAILED")
                batch_result.fail_count += 1

        CATCH error:
            saveException(process_id, event, error.message)
            markProcessAsFailed(process_id, "SYSTEM_ERROR")
            batch_result.fail_count += 1

    sendBatchSummary(batch_date, batch_result)
    RETURN batch_result
```

## 5. 인사 변동 정렬 로직

동일 사용자의 여러 이벤트가 같은 배치에 포함될 수 있으므로 처리 순서가 중요하다.

```pseudocode
FUNCTION sortEvents(hr_events):
    change_type_priority = {
        RETIRE: 1,
        LEAVE: 2,
        RETURN: 3,
        TRANSFER: 4,
        JOB_CHANGE: 5,
        NEW_HIRE: 6
    }

    RETURN hr_events SORT BY
        effective_date ASC,
        employee_id ASC,
        sequence_no ASC,
        change_type_priority[change_type] ASC
```

유의사항:
- 퇴사 이벤트가 있으면 이후 권한 부여 이벤트보다 우선 처리해야 한다.
- 같은 사용자에게 부서 이동과 직무 변경이 동시에 발생하면 최종 발령 상태 기준으로 권한을 계산해야 한다.

## 6. 데이터 검증 수도코드

```pseudocode
FUNCTION validateHrEvent(event, user_master):
    errors = []

    IF isEmpty(event.employee_id):
        errors.ADD("사번 누락")

    IF isEmpty(event.change_type):
        errors.ADD("인사변동유형 누락")

    IF event.change_type NOT IN [NEW_HIRE, TRANSFER, JOB_CHANGE, LEAVE, RETURN, RETIRE]:
        errors.ADD("지원하지 않는 인사변동유형")

    IF event.change_type != RETIRE AND isEmpty(event.after_dept_code):
        errors.ADD("변경 후 부서코드 누락")

    IF event.change_type != RETIRE AND NOT existsDept(event.after_dept_code):
        errors.ADD("등록되지 않은 변경 후 부서코드")

    IF event.change_type IN [TRANSFER, JOB_CHANGE] AND NOT existsUser(event.employee_id, user_master):
        errors.ADD("기존 사용자 마스터 없음")

    IF event.change_type == NEW_HIRE AND existsActiveUser(event.employee_id, user_master):
        errors.ADD("신규 입사 대상이나 이미 활성 사용자로 존재")

    IF event.change_type == RETIRE AND event.employment_status != RETIRED:
        errors.ADD("퇴사 이벤트와 재직상태 불일치")

    RETURN {
        is_valid: errors.SIZE == 0,
        errors: errors
    }
```

## 7. 목표 권한 계산 수도코드

```pseudocode
FUNCTION calculateTargetPermissions(event, current_state, policies):
    IF event.change_type == RETIRE:
        RETURN calculateRetirePermissions(current_state)

    IF event.change_type == LEAVE:
        RETURN calculateLeavePermissions(current_state)

    IF event.change_type == RETURN:
        RETURN calculateReturnPermissions(event, current_state, policies)

    IF event.change_type == NEW_HIRE:
        RETURN calculateNewHirePermissions(event, policies)

    IF event.change_type == TRANSFER:
        RETURN calculateTransferPermissions(event, current_state, policies)

    IF event.change_type == JOB_CHANGE:
        RETURN calculateJobChangePermissions(event, current_state, policies)

    RAISE "지원하지 않는 인사변동유형"
```

### 7.1 신규 입사 권한 계산

```pseudocode
FUNCTION calculateNewHirePermissions(event, policies):
    base_permissions = findPermissionsByPolicy(
        policies,
        dept_code = event.after_dept_code,
        job_code = event.after_job_code,
        grade_code = event.after_grade_code

    common_permissions = findCommonEmployeePermissions(policies)

    target_permissions = UNION(common_permissions, base_permissions)

    RETURN target_permissions
```

### 7.2 부서 이동 권한 계산

```pseudocode
FUNCTION calculateTransferPermissions(event, current_state, policies):
    old_dept_permissions = findDeptPermissions(policies, event.before_dept_code)
    new_dept_permissions = findPermissionsByPolicy(
        policies,
        dept_code = event.after_dept_code,
        job_code = event.after_job_code,
        grade_code = event.after_grade_code
    )

    retained_permissions = filterRetainablePermissions(
        current_state.current_permissions,
        event
    )

    exception_permissions = filterValidExceptionPermissions(
        current_state.exception_permissions,
        event
    )

    target_permissions = UNION(
        retained_permissions,
        new_dept_permissions,
        exception_permissions
    )

    target_permissions = REMOVE(
        target_permissions,
        permissionsThatMustBeRevoked(old_dept_permissions, event)
    )

    RETURN target_permissions
```

## 8. 권한 변경안 생성 수도코드

```pseudocode
FUNCTION buildPermissionChangePlan(current_permissions, target_permissions):
    add_permissions = target_permissions - current_permissions
    revoke_permissions = current_permissions - target_permissions
    keep_permissions = current_permissions INTERSECT target_permissions

    RETURN {
        add_permissions: add_permissions,
        revoke_permissions: revoke_permissions,
        keep_permissions: keep_permissions
    }
```

예시:

```text
현재 권한: [A, B, C]
목표 권한: [B, C, D]

추가 권한: [D]
회수 권한: [A]
유지 권한: [B, C]
```

## 9. 변경안 검토 수도코드

```pseudocode
FUNCTION reviewChangePlan(event, current_state, change_plan, policies):
    reasons = []

    IF hasNoPermissionAfterChange(event, change_plan):
        reasons.ADD("변경 후 권한 없음")

    IF containsHighRiskPermission(change_plan.add_permissions, policies):
        reasons.ADD("고위험 권한 추가")

    IF containsConflictingPermissions(change_plan):
        reasons.ADD("상충 권한 동시 보유")

    IF isOnePersonDepartment(event.after_dept_code) AND event.change_type == TRANSFER:
        reasons.ADD("1인 부서 이동으로 권한 정책 확인 필요")

    IF hasMultipleDepartments(event.employee_id):
        reasons.ADD("겸직 사용자 권한 확인 필요")

    IF hasUnexpiredManualException(current_state.exception_permissions):
        reasons.ADD("수동 예외 권한 존재")

    IF change_plan.add_permissions.SIZE == 0 AND change_plan.revoke_permissions.SIZE == 0:
        RETURN {
            requires_manual_review: FALSE,
            is_no_change: TRUE,
            reasons: ["변경 사항 없음"]
        }

    RETURN {
        requires_manual_review: reasons.SIZE > 0,
        is_no_change: FALSE,
        reasons: reasons
    }
```

## 10. 권한 변경 실행 수도코드

```pseudocode
FUNCTION executePermissionChange(employee_id, change_plan):
    execution_errors = []
    executed_actions = []

    FOR EACH permission IN change_plan.revoke_permissions:
        result = revokePermission(employee_id, permission)

        IF result.is_success == TRUE:
            executed_actions.ADD({
                action: "REVOKE",
                permission: permission
            })
        ELSE:
            execution_errors.ADD({
                action: "REVOKE",
                permission: permission,
                message: result.error_message
            })

    FOR EACH permission IN change_plan.add_permissions:
        result = grantPermission(employee_id, permission)

        IF result.is_success == TRUE:
            executed_actions.ADD({
                action: "GRANT",
                permission: permission
            })
        ELSE:
            execution_errors.ADD({
                action: "GRANT",
                permission: permission,
                message: result.error_message
            })

    RETURN {
        is_success: execution_errors.SIZE == 0,
        executed_actions: executed_actions,
        errors: execution_errors
    }
```

유의사항:
- 권한 회수 후 부여 순서로 처리한다.
- 일부 실패가 발생하면 성공한 작업까지 되돌릴지, 실패 권한만 재처리할지 정책을 정해야 한다.
- 퇴사자는 모든 권한 회수가 완료되지 않으면 실패 알림 우선순위를 높인다.

## 13. 재처리 수도코드

```pseudocode
FUNCTION retryFailedProcess(process_id):
    failed_process = fetchProcessLog(process_id)
    event = fetchHrChangeEvent(failed_process.event_id)

    IF failed_process.status NOT IN ["VALIDATION_FAILED", "EXECUTION_FAILED", "SYSTEM_ERROR"]:
        RETURN "재처리 대상 아님"

    IF failed_process.status == "VALIDATION_FAILED":
        IF isExceptionResolved(process_id) == FALSE:
            RETURN "검증 오류가 해결되지 않아 재처리 불가"

    RETURN processSingleEvent(event)
```

```pseudocode
FUNCTION processSingleEvent(event):
    policies = fetchActivePermissionPolicies()
    user_master = fetchUserMaster()

    validation_result = validateHrEvent(event, user_master)

    IF validation_result.is_valid == FALSE:
        RETURN "재처리 실패: 검증 오류"

    current_state = fetchCurrentPermissionState(event.employee_id)
    target_permissions = calculateTargetPermissions(event, current_state, policies)
    change_plan = buildPermissionChangePlan(current_state.current_permissions, target_permissions)
    review_result = reviewChangePlan(event, current_state, change_plan, policies)

    IF review_result.requires_manual_review == TRUE:
        RETURN "재처리 보류: 수동 검토 필요"

    execution_result = executePermissionChange(event.employee_id, change_plan)

    IF execution_result.is_success == TRUE:
        RETURN "재처리 성공"
    ELSE:
        RETURN "재처리 실패: 권한 변경 실패"
```

## 14. 권한 정책 관리 로직

```pseudocode
FUNCTION registerPermissionPolicy(policy):
    validation_result = validatePolicy(policy)

    IF validation_result.is_valid == FALSE:
        RETURN validation_result.errors

    deactivatePreviousPolicyIfSameScope(policy)
    INSERT policy INTO permission_policy

    RETURN "정책 등록 완료"
```

```pseudocode
FUNCTION validatePolicy(policy):
    errors = []

    IF isEmpty(policy.dept_code) AND isEmpty(policy.job_code):
        errors.ADD("부서 또는 직무 조건 중 하나는 필수")

    IF policy.permission_set IS EMPTY:
        errors.ADD("부여 권한 목록 누락")

    IF hasConflictingPermission(policy.permission_set):
        errors.ADD("정책 내 상충 권한 포함")

    IF policy.is_high_risk == TRUE AND policy.approval_required == FALSE:
        errors.ADD("고위험 권한은 승인 필요로 설정해야 함")

    RETURN {
        is_valid: errors.SIZE == 0,
        errors: errors
    }
```

## 15. 주요 예외 케이스

| 예외 케이스 | 처리 방식 |
|---|---|
| 부서코드가 마스터에 없음 | 자동 처리 중단, 예외 큐 등록 |
| 신규 입사자인데 이미 활성 사용자 존재 | 자동 처리 중단, 사용자 중복 확인 |
| 퇴사자인데 권한 회수 실패 | 긴급 실패 알림, 재처리 대상 등록 |
| 고위험 권한 추가 | 자동 반영 보류, 승인 요청 |
| 겸직 사용자 | 기본 권한 계산 후 수동 검토 대상 |
| 1인 부서 이동 | 권한 회수 범위 확인 필요 |
| 임시 권한 보유자 | 만료일 확인 후 유지 또는 회수 |
| 변경 전후 권한 차이 없음 | 처리 완료로 기록하되 권한 변경은 실행하지 않음 |

## 16. 구현 시 유의사항

- 권한 룰은 코드에 직접 박지 않고 정책 데이터로 관리해야 한다.
- 권한 회수 로직은 부여 로직보다 보수적으로 설계해야 한다. 특히 퇴사·휴직은 누락되면 보안 문제가 된다.
- 모든 권한 변경은 변경 전·후 상태를 저장해야 감사 대응이 가능하다.
- 자동 확정 기준과 수동 검토 기준을 명확히 분리해야 운영자가 결과를 신뢰할 수 있다.
- 배치가 중간에 실패해도 같은 데이터를 다시 실행했을 때 중복 부여나 중복 회수가 발생하지 않도록 멱등성을 확보해야 한다.
- 인사 발령일과 실제 시스템 반영일이 다를 수 있으므로 예약 적용 또는 적용 지연 정책을 고려해야 한다.

# 코난 솔루션 정리

> 정리 기준: `코난 솔루션` 폴더의 교육 자료를 바탕으로, **코난 솔루션만의 강점**과 **서연이화 과제에 적용하면 효과가 큰 기능** 위주로 정리.

## 한 줄 요약

코난 솔루션은 단순 LLM 호출 도구라기보다, **폐쇄망/기업 내부 문서를 대량 색인하고 한국어 검색 품질을 튜닝해 RAG 검색 근거를 안정적으로 제공하는 검색·RAG 인프라**에 강점이 있다.  
서연이화 과제에서는 Dify가 워크플로우·LLM 생성·외부 시스템 연동을 맡고, 코난은 **문서 색인·청킹·키워드/벡터 검색·동의어/사용자사전·검색 튜닝·대량 배치 추론**을 담당하는 구조가 가장 적합하다.

---

## 코난 솔루션의 핵심 강점

### 1. 대용량 문서 RAG에 적합한 검색 엔진 기반 구조

- 문서를 `chunk` 단위로 색인하고, 각 chunk에 벡터·키워드·메타데이터를 함께 저장한다.
- 검색 API(`/ksm/rag/v5/search`, `/ksm/rag/v6/search`)로 RAG용 chunk를 바로 반환할 수 있다.
- `topk`, `threshold`, `relscore`, `method`, `vk` 등 파라미터로 검색 결과 수, 벡터 유사도 임계값, 키워드 검색 엄격도, 키워드/벡터 검색 방식을 조정할 수 있다.
- 7천~1만 건 이상의 품질 대책서, 600건 이상의 기술 표준 문서처럼 **문서 수가 많고 검색 품질이 중요한 과제**에서 Dify Knowledge 단독보다 안정적이다.

### 2. 한국어 검색 튜닝과 키워드 검색 품질

- `title`, `chunk`, `lines` 필드를 나누어 검색 가중치를 줄 수 있다.
- 예시 기준으로 title 매칭, 같은 라인 내 키워드 인접도, 기본 relevance, 최신성 등을 조합해 랭킹을 만들 수 있다.
- `method` 값으로 검색 엄격도를 조절할 수 있어, “넓게 찾기”와 “정확히 찾기”를 과제별로 분리할 수 있다.
- 한국어 명사·복합명사·형태소 기반 키워드 추출 옵션을 활용할 수 있어, 제조 도메인 용어 검색에 유리하다.

### 3. 키워드 + 벡터 하이브리드 검색

- `embedding-10` 기반 벡터 검색과 키워드 검색을 함께 사용할 수 있다.
- `vk` 옵션으로 키워드/벡터/혼합 검색을 선택할 수 있다.
- 의미가 비슷하지만 표현이 다른 문서 검색에는 벡터 검색을, 품번·품명·공법·문서 제목처럼 정확한 용어가 중요한 경우에는 키워드 검색을 강화할 수 있다.
- 서연이화 과제처럼 “현상·원인 설명은 자연어이고, 품명·공법·차종은 정확 매칭이 필요한” 경우 하이브리드 검색이 특히 유용하다.

### 4. 청킹 전략을 세밀하게 통제 가능

- `Chunk Size`, `Overlap Size`로 문서를 적절한 길이로 나누고 문맥 단절을 줄일 수 있다.
- 소제목을 추출해 chunk title로 활용할 수 있다.
- 표(Table)는 행/열 구조가 깨지면 의미가 훼손되므로, 하나의 chunk로 유지하는 전략을 사용할 수 있다.
- 기술 표준 문서, 품질 대책서처럼 표·소제목·절 번호가 중요한 문서에서 검색 품질을 높일 수 있다.

### 5. 메타데이터·볼륨 기반 검색 범위 제어

- `customfield`를 활용해 문서 유형, 차종, 품명, 공장, 연도, 고객사, 이슈 타입 등으로 필터링할 수 있다.
- `vols`로 검색 대상 볼륨을 지정할 수 있어, 과제별·문서 유형별·사업부별 검색 영역을 분리하기 좋다.
- 과제 6의 대책서 검색에서는 `품명별`, `이슈타입별`, `고객사별`, `연도별` 볼륨/메타데이터 설계가 핵심이 될 수 있다.

### 6. 동의어·신조어·사용자 사전 기반 도메인 보정

- `synfile`, `lconf` 등을 통해 동의어 사전, 신조어 사전, 사용자 사전을 검색에 반영할 수 있다.
- 고객사 용어와 사내 용어가 다른 경우, 예를 들어 `DOOR TRIM LH`와 `도어트림 좌측` 같은 매핑에 활용 가능하다.
- 품명 오타 보정, 약어 확장, 공법명 표준화, 고객사별 용어 차이 보정에 강점이 있다.

### 7. 색인·운영·디버깅 기능

- Indexing Wizard로 DB, 서버 문서파일, 덤프파일 등을 GUI 기반으로 수입·색인할 수 있다.
- 색인 스케줄을 지정할 수 있고, 필요 시 `ddl.k`, `dml.k`를 커스터마이징할 수 있다.
- 색인 로그, 검색 로그, 시스템 로그를 통해 검색 결과 이상, 색인 오류, API 요청을 추적할 수 있다.
- 메모리 설정, 병렬 처리 설정, 캐시 등 운영 최적화 기능이 있어 폐쇄망 운영형 프로젝트에 적합하다.

### 8. KonanLLM Studio의 프롬프트·배치·모니터링 기능

- 프롬프트 갤러리에서 템플릿 생성, 버전 관리, 배포가 가능하다.
- 플레이그라운드에서 모델·파라미터별 응답을 비교하고 RAG 도구를 연동해 테스트할 수 있다.
- JSONL 기반 배치 추론으로 다량 문서를 일괄 요약·추론할 수 있다.
- GPU 상태, 요청 현황, 모델 상태, 작업 이력 등을 운영 관점에서 확인할 수 있다.

## 서연이화 과제별 활용 포인트

| 과제 | 코난 활용 적합도 | 활용하면 좋은 기능 | 적용 방향 |
|---|---:|---|---|
| **3 기술 표준 문서 요약/비교** | 높음 | 청킹, 표 1-chunk 유지, 소제목 title화, RAG 검색 API, Studio 배치 | 기술 표준 문서를 코난에 색인하고, Dify/LLM은 요약·버전 비교 생성에 집중 |
| **6 과거 대책서 RAG** | 매우 높음 | 대용량 RAG 색인, 하이브리드 검색, customfield, 볼륨 분리, relscore/topk 튜닝 | 현상·원인 입력 → 유사 대책서 검색 → 근거 chunk 기반 대책 가이드 생성 |
| **11 컬러 사양표·오타 보정** | 높음 | 동의어/사용자 사전, 키워드+벡터 검색, threshold, TopK 후보 | 고객사 품명·오타를 사내 표준 부품명 후보로 매칭 |
| **13 품명·공법 추천** | 높음 | 동의어·신조어 사전, 형태소/복합명사 추출, 검색 랭킹 튜닝 | 입력 품명에서 표준 품명·공법 후보를 검색하고 빈도/가중치와 결합 |
| **12 수축률 추천** | 중간 | 유사 이력 RAG, 콜드스타트 보완, 근거 검색 | ML 예측이 주력. 단, 신규 조합은 코난으로 유사 생산 이력 검색해 fallback 근거 제공 |
| **14 업체 맵핑** | 중간 | 과거 결재/업체 매핑 사례 검색, 메타데이터 필터 | HTML에서 추출한 업체 정보를 과거 사례와 비교해 매핑 정확도 보강 |
| **1 권한 맵핑** | 낮음 | 과거 권한 사례 검색 정도 | 순수 룰 기반이라 코난 주력 영역은 아님 |
| **2 단가 조회 RPA** | 낮음 | 문서/OCR 후처리 정도 | 브라우저 자동화가 핵심이라 코난 직접 활용도 낮음 |

## 추천 아키텍처

### 기본 역할 분담

```text
전처리/OCR 결과
    ↓
코난 Search/RAG-X
    - 문서 색인
    - 청킹
    - 임베딩
    - 키워드/벡터 검색
    - 동의어·사용자 사전
    - 메타데이터 필터
    ↓ Search API
Dify / 외부 워크플로우
    - 사용자 입력 수신
    - 코난 검색 API 호출
    - LLM 요약·비교·생성
    - IF/ELSE 분기
    - 사내 시스템 API 전송
```

### 왜 이 구조가 좋은가

- 코난은 **검색 품질과 대량 색인**에 강하고, Dify는 **업무 흐름 구성과 LLM 응답 생성**에 강하다.
- 모든 것을 Dify Knowledge에 넣기보다, 검색 품질이 중요한 대용량 문서는 코난에 맡기는 편이 안정적이다.
- 검색 결과가 API로 제공되므로 Dify HTTP Request 노드와 결합하기 쉽다.
- 폐쇄망 제조 환경에서 운영 로그, 색인 스케줄, 검색 튜닝을 관리하기 좋다.

## 과제 6: 대책서 RAG 적용 예시

### 코난에 맡길 부분

- 과거 대책서 OCR 텍스트 색인
- 문서별 메타데이터 설계
  - 차종
  - 품명
  - 공장
  - 고객사
  - 불량 현상
  - 원인
  - 대책 유형
  - 발생 연도
- chunk title에 문서 제목·소제목·불량 유형 반영
- 현상/원인 기반 하이브리드 검색
- `topk`, `relscore`, `threshold` 튜닝
- 품명·현상 동의어 사전 구축

### Dify/LLM에 맡길 부분

- 사용자 입력 정리
- 원인 입력 유무에 따른 검색 분기
- 코난 search API 호출
- 검색된 대책서 근거를 바탕으로 신규 대책 보고서 초안 생성
- 출처 문서/근거 chunk 함께 표시

### 기대 효과

- 대량 대책서에서 유사 사례를 빠르게 찾을 수 있다.
- 단순 벡터 검색보다 품명·현상·원인 키워드를 함께 반영할 수 있다.
- 검색 결과 근거가 명확해져 LLM 환각을 줄일 수 있다.

## 과제 3: 기술 표준 문서 요약/비교 적용 예시

### 코난 활용 포인트

- 100여 장짜리 기술 표준 문서를 chunk 단위로 색인
- 소제목을 title로 활용해 “시험 항목”, “합격 기준”, “변경 이력” 검색 품질 향상
- 표는 하나의 chunk로 유지해 시험 기준표가 깨지지 않도록 처리
- 버전별 문서를 customfield로 구분
- 과거 버전과 최신 버전의 관련 chunk를 검색해 LLM 비교에 투입

### 특히 좋은 기능

- 초기 630건 문서 요약은 KonanLLM Studio의 JSONL 배치 추론으로 일괄 처리 가능
- 실시간 비교 요청은 코난 RAG 검색 + Dify LLM 비교 생성 구조로 분리 가능

## 과제 11·13: 품명/오타/공법 매칭 적용 예시

### 코난 활용 포인트

- 부품 마스터, 품명 사전, 공법 사전, 고객사별 명칭을 별도 볼륨으로 색인
- 동의어·신조어·사용자 사전으로 고객사 용어와 사내 용어 연결
- 키워드 검색은 정확 명칭/품번에 강하게, 벡터 검색은 유사 표현에 활용
- TopK 후보와 점수를 반환해 자동 확정/사용자 선택을 분기

### 예시 흐름

```text
고객사 입력 품명
    ↓
정규화·약어 확장
    ↓
코난 검색: 품명 마스터 TopK
    ↓
점수 높음: 자동 매핑
점수 애매: 후보 3~5개 반환
    ↓
Dify/LLM이 컬러값·공법 추천 결과 정리
```

## 과제 12: 수축률 추천에서의 보조 활용

과제 12의 핵심은 XGBoost/scikit-learn 기반 수치 예측 ML이므로 코난이 주 모델은 아니다.  
다만 아래 영역에서 코난을 붙이면 설계 완성도가 높아진다.

- 초기 데이터가 부족한 경우, 유사 재질·업체·공법 이력 검색
- 신규 조합에 대한 콜드스타트 fallback
- “왜 이 수축률을 추천했는가”에 대한 과거 유사 사례 근거 제공
- ML 예측값 + RAG 유사 사례 + LLM 설명 생성 구조 구성

추천 구조:

```text
입력: 재질/업체/공법/공장/품질 조건
    ↓
ML API: 수축률 예측
    ↓
코난 RAG: 유사 이력 검색
    ↓
LLM: 예측값 + 유사 사례 + 주요 영향 요인 설명
```

## 결론: 코난을 우선 적용할 과제

1. **과제 6 대책서 RAG**  
   - 코난 강점이 가장 직접적으로 드러나는 과제.
   - 대용량 문서, 유사 사례 검색, 메타데이터 필터, 동의어 사전, 하이브리드 검색이 모두 필요.

2. **과제 3 기술 표준 문서 요약/비교**  
   - 긴 문서 청킹, 표 처리, 버전별 검색, 배치 요약에 적합.

3. **과제 11 컬러·오타 보정 / 과제 13 품명·공법 추천**  
   - 한국어 검색, 동의어/신조어 사전, TopK 후보 검색이 강점.

4. **과제 12 수축률 추천**  
   - 주력은 ML이지만, 유사 이력 검색과 설명 근거 보강용으로 붙이면 좋음.

> 따라서 서연이화 제안에서는 “코난 = LLM 생성기”로 설명하기보다, **제조 문서와 마스터 데이터를 업무에 쓸 수 있는 검색 가능한 지식베이스로 바꾸는 RAG 검색 인프라**로 포지셔닝하는 것이 가장 설득력 있다.

# 더미 대책서 세트 — RAG 출력 모양 spike용

> [!summary] 목적
> Dify Knowledge Retrieval 노드의 **출력 스키마·점수 척도를 1회 캡처**하기 위한 더미 개선대책서 16건. 품질 검증용 풀 테스트(7천건)가 **아니라** 출력 모양 탐색(spike)용. 근거: [[3. 프로젝트/서연이화/과제5/measure-Dify 비교 및 Dify 구현 범위.md]] 6.6절.

## 형식 — 하이브리드 (PPTX 설계 반영)

PPTX `과제5 S-CLM 과거 대책서 기반 최적 대책서 추천.pptx` 의 5-1 파이프라인(`비정형 PDF → OCR 6항목 구조화 → Vector DB`)을 더미 한 파일에 압축:

- **프론트매터(구조화 6항목)** = OCR 추출 결과 / 검색 DB 저장 형태 → **A(구조화 레코드) 경로**용
- **본문(비정형 서술)** = 개선대책서 원본 텍스트 → **B(청크→LLM 추출) 경로**용

→ 한 더미로 A·B 두 검색 모드 출력 모양을 **동시 캡처·비교** 가능.

## 변별 테스트 포인트
- **D01·D02**: 같은 현상(도어트림 단차), 다른 원인 → 검색이 한 현상에 복수 원인 후보를 끌어오는지.
- **D01~D04**: 치수 계열 의미 유사 → top-k 점수 분포·순위 확인.
- **현상군 간**: 도장/조립/성형은 의미 비유사 → 오검색(false retrieval) 여부.

## spike 절차
1. 이 16건 `.md`를 Dify Knowledge에 등록(인덱싱 방식: 고품질/경제형, 청킹 룰 기본).
2. 질의 예: "도어트림 상단 단차 불량" → Retrieval 노드 1회 실행.
3. **output 캡처**: item 키(content/text/metadata/score), 점수 척도(0~1? 0~100?), source/ragSource 형태.
4. 캡처 결과로 B1(점수 정책)·B2(필드명) 확정 → [[3. 프로젝트/서연이화/과제5/RAG 독립 항목 확정 체크리스트.md]] 업데이트.

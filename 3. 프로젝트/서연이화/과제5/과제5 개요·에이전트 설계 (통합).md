# 과제5 — S-CLM 과거 대책서 기반 최적 대책서 추천 (개요·에이전트 설계)

> [!summary] 이 노트의 목적
> 설계서(PPTX 6슬라이드)와 과제정의서(PNG 5장)를 **하나로 합친 원문 레퍼런스**. PPT·이미지 왔다 갔다 안 하고 이 문서만 봐도 과제 전체가 파악되게 정리. (설계서 PPT가 최신 → 정의서와 다르면 PPT 기준)
> ※ Dify 구현/노드 설계 얘기는 제외 — 그건 [[3. 프로젝트/서연이화/과제5/Dify 설계 전 모호점 정리.md]] 참고.

## 1. 과제 한눈에

**두 개의 에이전트로 구성**된다.

| 구분 | 5-1 과거 대책서 수집·저장 에이전트 | 5-2 최적 대책서 추천 에이전트 |
|---|---|---|
| 대상 업무 | 품질 이력 수집·OCR 구조화·검색 DB 구축 | 현상·원인 기반 최적 대책서 추천 |
| 업무 목적 | 과거 품질 이력(형태·연도·사유·개선대책서)+개선대책서 텍스트를 검색 DB(색인·임베딩)로 구축 → 5-2의 기반 데이터 마련 | 과거 유사 사례 검색 또는 상용 LLM으로 현상-원인-대책 초안 및 점검 가이드 제시 (AI 방향 제시, 사람이 수행 완성) |
| 사용 플랫폼 | S-CLM | S-CLM |
| 최종 결과 | 과거 품질 이력 메타데이터 + 개선대책서 구조화 텍스트 기반 검색 DB(키워드·벡터) | 현상-원인-대책 구조의 대책서 초안 및 필수 점검항목(점검시트) 가이드 |

> [!note] 핵심 요약 (설계서 슬라이드1)
> AI 에이전트는 **과거 품질 이력 기반 유사 사례 검색** 또는 **상용 LLM(OpenAI ChatGPT)** 으로 대책서 초안과 점검 가이드를 제시하며, **최종 완성은 사용자가 수행**한다(HITL).
> 추천 = **외부 LLM 생성 + 내부 RAG 검색(사내 유사사례) 결합**. ※ 내부 RAG는 **현재 더미(미구축)**.

**처리 개념 흐름**
`현상·원인 입력 → 유사 과거 사례 검색 / 상용 LLM 질의 → 현상-원인-대책 초안 생성 → 사용자 검토·확정 → S-CLM 반영·증분 색인`

|---|---|

| 참조 | 과거 품질 이력 검색 DB(메타·텍스트·벡터), 보고서 양식 가이드 |

## 4. 에이전트 5-1 — 과거 품질 이력 수집·저장

OCR로 비정형 개선대책서(약 7,000건)를 구조화 추출하여 검색 DB(Vector)를 구축한다.

> [!example] 입력 데이터 예시 (설계서 슬라이드3)
> 발생형태: 치수불량 / 귀책사유: 가공불량 / 발생장소: 사출공정 / 대책방안: 금형 보정 (비정형 문서 약 7,000건)

| 단계 | 단계명 | 처리 주체 | 설명 | 입력/연동 | 참조 | 출력 |
|---|---|---|---|---|---|---|

| S2 | 품질문제 변동 내역 전송 | S-CLM | 품질문제 생성·변경 내역을 AI 플랫폼으로 전송 | 비정형 문서 | - | 전송 데이터 |

## 5. 에이전트 5-2 — 최적 대책서 추천 (OpenAI ChatGPT 연동)

사용자 현상·원인을 받아 **내부 RAG 검색(더미) + 외부 LLM 생성**을 결합해 현상-원인-대책 초안과 점검 가이드를 만든다. AI는 방향 제시, 사람이 확정.

> [!example] 입력 데이터 예시 (설계서 슬라이드5)
> 현상: 도장면 흐름 결함 / 원인: (공란 또는 기입) / 모델: gpt-5-nano·5.5·5.5-pro 선택

**사용자 흐름 (S-CLM 화면)**
1. **R1** 현상 입력 후 원인 추천 → 원인별 대책 추천 요청 (모델 선택 가능, 외부망)
2. **R2** AI가 생성한 원인별 대책 후보를 사용자가 체크·확정 (직접 추가·비고 가능)
3. **R3** 확정 대책서를 화면 표시·다운로드, 작성완료 시 ChatGPT 세션 종료

**처리 단계 상세** (설계서 슬라이드6 — 협의 확정 기준)

| 단계 | 단계명 | 처리 주체 | 설명 | 입력/연동 | 참조 | 출력 |
|---|---|---|---|---|---|---|
| R1 | 현상·원인·대책 추천 요청 | S-CLM (화면O) | 현상 입력 후 원인 추천 → 원인별 대책 추천 요청(모델 선택 가능) | 현상, 이미지, 원인 | - | 생성 요청 |
| A1 | 대책서 생성 요청 수신 | AI 플랫폼 | 품질문제 ID·메타데이터 및 사용자 입력 정보를 수신 | 품질문제 ID, 메타데이터, 현상·원인 | - | 수신 데이터 |
| A2 | 입력 데이터 점검·분기 | AI 플랫폼 | 필수 입력값·형식 점검, 원인 공란/기입 여부로 처리 분기 결정 | 현상·원인 텍스트 | - | 점검·분기 결과 |
| A3 | 내부 RAG 검색 · 외부 LLM 질의 | AI 플랫폼 | 사내 유사사례를 내부 RAG로 검색(현재 더미)하고 외부 LLM 호출 질의를 구성. 원인 공란/기입에 따라 분기 | 현상·원인 텍스트 | 내부 RAG 검색 DB(미구축·더미) | 상용 LLM 대책 내용 |
| A4 | 외부 LLM(ChatGPT) 호출 | AI 플랫폼 | DMZ 외부망으로 ChatGPT(gpt-5-nano/5.5/5.5-pro)를 prev_response_id 세션 체이닝으로 1~3회 호출해 대책 답변 수신 | 검색 메타데이터(현상·원인) | - | 검색 결과 |
| A5 | 후보 통합·원인별 대책 생성 | AI 플랫폼 | 외부 LLM 답변과 내부 RAG 결과를 **점수순 통합·정렬**하여 원인별 대책 그룹(**합 최대 10**) 구성, 토큰·비용 누적 집계 (AI 방향 제시, 사람이 확정) | 검색 결과, LLM 대책 내용 | 보고서 양식 가이드 | 대책서 초안·점검 가이드 |
| A6 | 생성 대책서 S-CLM 전달 | AI 플랫폼 | 생성된 대책서 초안을 S-CLM으로 전달 | 대책서 초안 | - | 전달 데이터 |
| R2 | 대책 확정 및 작성완료 | S-CLM (화면O) | 원인별 대책 후보를 체크·확정(직접 추가·비고), 작성완료 시 ChatGPT 세션 종료 | 대책서 초안 | - | 화면 표시 대책서 |
| A7 | 확정 대책서 증분 색인 | AI 플랫폼 | 사용자 확정 대책서를 증분 색인하여 과거 품질 이력 검색 DB에 재활용 | 확정 대책서 | 과거 품질 이력 검색 DB | 증분 색인 결과 |

**외부망 연동 (DMZ)**: ChatGPT Responses API, 문서별 세션 컨텍스트(`prev_response_id → response_id`) 유지·중계, 세션 체이닝 1~3회 반복.

## 6. 협의사항 (정의서 02) — 확정/미확정

> 상태: ☑ 확정 / ☐ 확인 필요

| No | 구분 | 확인 사항 | 담당 | 현재 가정/확정 내용 | 상태 |
|---|---|---|---|---|---|
| 1 | 입력 데이터 | 품질문제마스터 DB 연동 항목 | 서연이화/지산 | 이슈 형태·연도·사유·개선대책서 등 수집 항목 정의 | ☐ |
| 2 | 메타데이터 | 검색 DB 구성 메타데이터 항목 | 서연이화/코난 | 검색 DB 구성에 필수적인 메타데이터 항목 검토·승인 | ☐ |
| 3 | RAG | RAG 볼륨 구성 | 서연이화/코난 | RAG 볼륨 구성에 따른 검토·승인 | ☐ |
| 4 | OCR | 개선대책서 OCR 추출 구조·범위 | 코난 | 발생형태·귀책사유·발생장소·중요도·발생년도·대책방안 등 구조화 범위, 수행 시 추가 검토 | ☐ |
| 5 | 결과 형식 | 대책서 보고서 양식 | 서연이화 | 보고서 양식 가이드·승인 (현상-원인-대책) | ☐ |
| 6 | 산출 방식 | AI 산출물 형태 | 서연이화 | 완성 대책서가 아닌 **필수 점검항목 제시** → 사람이 수행 시 다음 스텝 안내(점검시트 형태) | ☐ |
| 7 | 입력 | 원인란 공란/기입 분기 처리 | 코난 | **원인 공란 시: 유사 현상 기반 원인+대책 제시 / 기입 시: 유사 현상·원인 기반 대책 제시** ※PM확정: **원인 미지정 시 대책 불가**(공란이면 원인 추천→지정 후 대책) | ☑ |
| 8 | 이미지 | 첨부 이미지 활용 범위 | 코난 | **첨부 이미지는 분석에 미활용, 보고서 원인란에 삽입** | ☑ |
| 9 | 화면 | 대책서 요청·표시 UI | 지산 | 생성 요청 UI 및 초안 표시/다운로드 기능 제공 | ☐ |
| 10 | 검색 | 내부 대책서 검색 | 코난 | 상용 LLM 원인이나 대책 답변에 기존 관련 대책서 검색하여 제시 | ☐ |
| 11 | 참조 데이터 | 외부망 상용 LLM 활용 방향인데 **내부 과거 개선 대책서를 활용하는지 확인 필요** | 서연이화 | - | ☐ |

## 7. 핵심 사실 메모 (자주 헷갈리는 것)

- **두 에이전트**: 5-1(수집·저장, 검색 DB 구축) → 5-2(추천). 검색 DB는 5-1이 만들고 5-2가 공유.
- **데이터 규모**: 품질문제마스터 DB·개선대책서 각 **약 7,000건** (현재 전부 미착수).
- **추천 = 내부 RAG + 외부 LLM 결합**. 내부 RAG는 **코난 RAGops 솔루션**(코난이 Dify용 RAG 노드 제공). 현재 더미 지식베이스는 개발용 임시.
- **원인은 대책의 필수 선행**: 원인 미지정 시 대책 추천 불가. 공란이면 원인 추천→지정 후 대책. (PM 확정)
- **구현**: 전체 Dify, 별도 백엔드 없음. 호출 횟수 제한·상태(exclude 등)는 프론트. 토큰·비용은 실제 구현 미사용.
- **모델**: gpt-5-nano / 5.5 / 5.5-pro, 사용자 선택(설계서 명시).
- **세션**: ChatGPT Responses API, prev_response_id 체이닝 **1~3회**, 작성완료 시 종료.
- **개수**: 원인별 대책 그룹 **합 최대 10**, 점수순 통합·정렬.
- **이미지**: 분석엔 미사용, 보고서 원인란 삽입만.
- **HITL**: AI는 초안·필수 점검항목(방향) 제시, **최종 완성·확정은 사람**.
- **재활용**: 사용자 확정 대책서 → 증분 색인 → 검색 DB 재투입.

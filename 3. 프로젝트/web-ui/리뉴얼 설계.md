## 배경

현재 UI는 **Legacy / Agent** 탭으로 나뉘어 있고, 각각 카드 그리드에서 개별 페이지로 이동하는 구조.
이번 리뉴얼에서는 탭 구분을 없애고, **Dify 챗봇 중심의 메인 화면** + **기능별 페이지**로 재구성한다.

## 현재 구조

```
Sidebar: [Legacy] [Agent]
  ├─ Legacy 탭 → ERP/CRM, G/W 카드
  └─ Agent 탭  → 6개 에이전트 카드 → 각각 /agents/{id}/ 페이지
```

## 목표 구조

```
Sidebar 메뉴 (트리형):
  ├─ 메인 ─────────── 클릭 시 통합 Dify 웹앱 표시
  │    ├─ 매출 분석 ── Dify 웹앱 임베드
  │    ├─ 전자 결재 (DB) ── Dify 웹앱 임베드
  │    ├─ 전자 결재 (SAP/Salesforce) ── Dify 웹앱 임베드
  │    └─ 사규 검색 ── Dify 웹앱 임베드
  ├─ 커스텀 UI ─────── 펼치면 하위 메뉴
  │    ├─ 메일 전송 ── 외부 UI 삽입
  │    └─ 매출 분석 ── 외부 UI 삽입
  └─ 기존 UI ───────── 에이전트/레거시 카드 모아보기
```

## 페이지별 설계

### 1. 메인 (Dify 챗봇)

- **메인** 자체 = 통합 챗봇 (Dify 웹앱 iframe 임베드)
- 사이드바에서 "메인" 아래에 하위 메뉴 4개: `매출 분석` | `전자 결재 (DB)` | `전자 결재 (SAP/Salesforce)` | `사규 검색`
- 각 하위 메뉴도 **별도 Dify 웹앱** iframe 임베드
- 총 5개의 Dify 웹앱 URL 필요

### 2. 커스텀 UI (Dify 워크플로우 연동)

Dify 웹앱으로 구현 못하는 부분을 직접 UI로 만든 예시 묶음.

- **메일 전송**: 외부에서 작업한 UI 소스를 받아 삽입 (페이지만 준비)
- **매출 분석**: 외부에서 작업한 UI 소스를 받아 삽입 (페이지만 준비)

### 3. 기존 UI

- 현재 Agent + Legacy 항목을 **카드 그리드 한 페이지**에 모두 표시
- 카드 클릭 시 기존 개별 페이지로 이동 (agents/legacy 경로 구분 불필요)
- 기존 코드 거의 그대로 유지

## 작업 순서

### 1단계: Sidebar + 라우팅 뼈대

현재 Sidebar는 Legacy/Agent 두 개 버튼을 눌러 전환하는 플랫 구조.
이걸 트리형 메뉴(펼침/접힘 가능한 부모-자식 구조)로 교체한다.
메뉴 데이터를 별도로 정의해서 Sidebar가 그걸 읽어 렌더링하도록 하고,
각 메뉴 항목이 어떤 경로로 이동하는지 매핑해둔다.
루트 레이아웃에 새 Sidebar를 넣고, 각 경로에 빈 페이지를 만들어서
메뉴 클릭 → 페이지 이동이 되는 것까지 확인한다.

### 2단계: 메인 (Dify iframe) + Header

루트 페이지(`/`)에 Dify 통합 챗봇 iframe을 띄운다.
기존 `AgentDetailView`가 이미 URL을 받아 iframe으로 표시하는 구조이므로 이걸 재활용한다.
이름을 일반적으로 바꾸고(예: `IframeView`), URL만 넘기면 되도록 정리한다.
매출분석/전자결재/사규검색 페이지도 같은 컴포넌트에 각각 다른 URL을 넘겨서 구현한다.
이 단계에서 Dify 웹앱이 iframe 안에서 정상 동작하는지 확인한다.
공통 Header도 이 단계에서 같이 구현한다. 페이지 제목 + Workflow 버튼을 포함하고,
메뉴 데이터에 워크플로우 정보를 추가해서 기존 WorkflowModal을 재활용한다.
기존 UI(/showcase)에서는 Workflow 버튼을 숨긴다.

### 3단계: 기존 UI 모아보기

현재 Agent 카드 그리드와 Legacy 카드 그리드가 탭으로 분리되어 있는데,
이걸 `/showcase` 한 페이지에 합쳐서 전부 보여준다.
기존 `AgentCardGrid` → `CardGrid`로 이름을 변경하고, AGENT_LIST + LEGACY_LIST를 합쳐서 넘긴다.
카드 클릭 시 기존 개별 페이지로 이동하는 동작은 유지.
카드 이미지 높이를 뷰포트 비율(25vh)로 설정하고, 카드가 많아도 스크롤 되도록 변경.

### 4단계: 커스텀 UI 빈 페이지

`/custom/mail`, `/custom/sales` 경로에 빈 페이지를 만들어둔다.
"준비 중" 안내 정도만 표시하고, 나중에 외부 소스를 받으면 그 안에 삽입하는 구조.

### 5단계: 기존 페이지 레이아웃 통일

현재 `/agents/*`, `/legacy/*` 페이지들은 자체 layout에서 기존 Sidebar를 쓰고 있다.
이 layout을 새 트리형 Sidebar를 쓰도록 교체한다.
각 페이지의 콘텐츠 영역은 건드리지 않고 감싸는 레이아웃만 바꾸면 된다.

### 6단계: 라우트 구조 리팩토링

기존에 `app/agents/`, `app/legacy/`, `app/(main)/` 3개로 분산되어 있던 라우트를 `app/(main)/` 하나로 통합.

**라우트 변경:**
- `app/agents/*` → `app/(main)/showcase/*`로 이동
- `app/legacy/*` → `app/(main)/showcase/*`로 이동
- `app/agents/`, `app/legacy/` 폴더 삭제
- 내부 경로 참조 일괄 변경: `/agents/sales-support/...` → `/showcase/sales-support/...`
- `data/agents.ts`, `data/legacy.ts`의 `previewUrl` 변경: `/agents/X` → `/showcase/X`, `/legacy/X` → `/showcase/X`

**이점:** 모든 페이지가 `(main)` route group의 레이아웃(TreeSidebar + Header)을 공유하므로, 페이지 이동 시 레이아웃이 리마운트되지 않음.

**헤더 통합:** `MainHeader`와 `Header` 두 컴포넌트가 동일한 역할을 중복 수행 → `Header` 하나로 병합, props(`onBack`, `onOpenWorkflow`)로 분기.

**미사용 코드 정리:** 구조 변경으로 불필요해진 컴포넌트 삭제 (`Sidebar`, `MainHeader`, `ShowcasePage`, `AgentDetailView`, `LegacyTabView`, `MockDashboard`, `DashboardHeader`, `registry.ts`)

**버그 수정:** `layout.tsx` icon 타입 위반 → 폴백 값 추가, `login/page.tsx` 로딩 상태 미해제 → `try/finally` 추가

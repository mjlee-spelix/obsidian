## 배경

v1 리뉴얼에서 트리형 사이드바 + Dify 챗봇 중심 구조로 재구성 완료.
이번 v2에서는 **사이드바 메뉴를 "챗봇 / UI" 2그룹으로 재편**하고, 기존 UI 모아보기(카드 그리드)를 없앤다.

## 현재 구조 (v1)

```
Sidebar:
  ├─ 메인 ─────────── / (통합 Dify 챗봇)
  │    ├─ 매출 분석 ── /sales-analysis
  │    ├─ 전자 결재 (DB) ── /approval/db
  │    ├─ 전자 결재 (SAP/SF) ── /approval/sap
  │    └─ 사규 검색 ── /policy
  ├─ 커스텀 UI ─────── (펼침/접힘만)
  │    ├─ 메일 전송 ── /custom/mail
  │    └─ 매출 분석 ── /custom/sales
  └─ 기존 UI ───────── /showcase (카드 그리드)
       └─ 카드 클릭 → /showcase/{id}/ 개별 페이지
```

**문제점:**
- "커스텀 UI"와 "기존 UI"가 분리되어 있지만, 사용자 관점에서는 둘 다 "UI 데모"
- "기존 UI"는 카드 그리드 한 단계를 거쳐야 개별 페이지에 접근
- 메뉴 구분 기준이 "챗봇 vs UI"가 아닌 "메인 vs 커스텀 vs 기존"이라 직관적이지 않음

## 목표 구조 (v2)

```
Sidebar:
  ├─ 챗봇 ─────────── (그룹, 클릭 불가)
  │    ├─ 통합 ──────── / (기존 메인)
  │    ├─ 매출 분석 ── /sales-analysis
  │    ├─ 전자 결재 (DB) ── /approval/db
  │    ├─ 전자 결재 (SAP/SF) ── /approval/sap
  │    └─ 사규 검색 ── /policy
  └─ UI ───────────── (그룹, 클릭 불가)
       ├─ 메일 전송 ── /custom/mail         (Dify 워크플로우 연동)
       ├─ 매출 분석 ── /custom/sales        (Dify 워크플로우 연동)
       ├─ 영업 지원 ── /showcase/sales-support/
       ├─ 매출 분석 (에이전트) ── /showcase/sales-analysis/
       ├─ 시장 모니터링 ── /showcase/market-monitor/
       ├─ 운영 지원 ── /showcase/ops-support/
       ├─ AI 컴플라이언스 ── /showcase/compliance/
       ├─ 데이터 조회 ── /showcase/data-query/
       ├─ ERP/CRM ── /showcase/erp-sap/
       └─ G/W ── /showcase/approval/
```

**핵심 변경:**
- 3그룹(메인/커스텀UI/기존UI) → 2그룹(챗봇/UI)
- "메인"이 부모 겸 페이지였던 구조 → "챗봇" 그룹 아래 "통합" 자식으로 분리
- "기존 UI" 카드 그리드 제거, 개별 항목이 사이드바에 직접 표시
- 부모 메뉴는 펼침/접힘만 (클릭 시 페이지 이동 없음)

## 코드 변경 범위

### 1. `data/sidebar-menu.ts` — 메뉴 데이터 재편

```
변경 전:
- 메인 (id: main, href: /)
  - 매출 분석 ...
- 커스텀 UI (id: custom-ui, href 없음)
  - 메일 전송 ...
- 기존 UI (id: showcase, href: /showcase)

변경 후:
- 챗봇 (id: chatbot, href 없음)
  - 통합 (id: chatbot-main, href: /)
  - 매출 분석 ...
- UI (id: ui, href 없음)
  - 메일 전송 ...
  - 영업 지원 (id: ui-sales-support, href: /showcase/sales-support/)
  - ... (AGENT_LIST + LEGACY_LIST에서 생성)
```

- "메인" 부모가 `href: /`를 갖고 있었음 → "챗봇" 부모는 `href` 없음, "통합" 자식이 `href: /`
- "기존 UI" `href: /showcase` 제거
- UI 그룹 children에 AGENT_LIST + LEGACY_LIST 항목 추가

### 2. `components/TreeSidebar.tsx` — 동작 변경

- 부모 메뉴 클릭 시 페이지 이동 로직 제거 (기존: "메인" 클릭 → `/` 이동)
- 부모 메뉴는 **펼침/접힘만** 수행
- UI 그룹 항목 수가 많아지므로 스크롤 처리 필요할 수 있음

### 3. `/showcase` 카드 그리드 페이지 — 제거

- `app/(main)/showcase/page.tsx` 삭제
- 카드 그리드 더 이상 불필요 (사이드바에서 직접 접근)
- `components/CardGrid.tsx` 미사용 시 삭제

### 4. `app/(main)/layout.tsx` — 헤더 로직 조정

- `/showcase` 페이지가 없어지므로 `pathname !== '/showcase'` 조건 제거
- showcase 상세 페이지가 사이드바 메뉴에 포함되므로, `findMenuItemByPath`로 통합 처리 가능
- `ALL_SHOWCASE_ITEMS` 별도 조회 로직 간소화 가능

### 5. 변경 불필요한 것

- 라우팅 경로: `/`, `/sales-analysis`, `/approval/*`, `/policy`, `/custom/*`, `/showcase/*` 모두 유지
- 각 페이지 컴포넌트 내부: 변경 없음
- Dify 웹앱 URL: 변경 없음
- 컴포넌트 파일 위치: 변경 없음

## 작업 순서

### 1단계: sidebar-menu.ts 재편

- "메인/커스텀UI/기존UI" → "챗봇/UI" 구조로 변경
- UI 그룹에 AGENT_LIST + LEGACY_LIST 항목을 children으로 추가
- `findMenuItemByPath` 업데이트 (showcase 상세 경로도 매칭되도록)

### 2단계: TreeSidebar 수정

- 부모 메뉴 클릭 동작: 펼침/접힘만 (href 없는 부모는 이동하지 않음)
- 이미 href가 없으면 이동 안 하는 로직이 있을 수 있으므로 확인 필요

### 3단계: layout.tsx 헤더 로직 정리

- showcase 상세 페이지가 sidebar-menu에 있으므로 `findMenuItemByPath`만으로 처리
- `ALL_SHOWCASE_ITEMS` 별도 조회 로직 제거 또는 간소화
- `/showcase` 조건 분기 제거

### 4단계: 불필요 파일 삭제

- `app/(main)/showcase/page.tsx` (카드 그리드)
- `components/CardGrid.tsx` (미사용 확인 후)

## 검증

- 사이드바 "챗봇" 펼치면 통합/매출분석/전자결재/사규검색 표시
- 사이드바 "UI" 펼치면 메일전송/매출분석/영업지원/... 전체 표시
- "챗봇", "UI" 부모 클릭 시 페이지 이동 없이 펼침/접힘만
- 각 자식 클릭 시 해당 페이지 이동 + 헤더 정상 표시
- `/showcase` 직접 접근 시 404 또는 리다이렉트

> ※ permissions·departments는 신규 챕터(§B) — 코드 검증 사실만 기술됐는지, 분석본과 정합한지 함께 확인

```
━━ 워크스페이스 검수 → 수정 분류 (괄호=발견 페이지) ━━

1) 전역 규칙  (모든 챕터 공통 — 다른 그룹 작성·검수 시 적용)
  G1. 없는 기능을 "없다"고 설명하지 말 것
      "워크스페이스 전환 불가"(readme) · "멀티 워크스페이스 메뉴 없음"(personal)
      · "부서 삭제 UI 없음"(departments) → 제품에 없으면 그냥 언급 안 함
  G2. UI 라벨 = 실제 한국어 화면 텍스트 그대로 (영문·임의번역 금지, i18n/화면 대조)
      "Edit info"→정보 편집하기 · "Export DSL"→DSL 내보내기(app-mgmt)
      · "가시성 범위"→공개 범위 · "취소 버튼"→삭제 버튼(permissions)
  G3. 개발자 시점 용어 → 사용자 표현
      '모달' '다이얼로그' '확인 다이얼로그' '현재 화면에서는' 회피 → 동작·결과로 서술(permissions)
  G4. 전문 용어는 첫 등장 시 정의 (DSL 설명이 뒤에 나옴 → 처음 나올 때)(app-mgmt)
  G5. 사용자가 안 궁금한 내부 동작·군더더기 제거 (= 전역 #8 문장 적합성)
      "외부 시스템 그룹 동기화"(readme) · "여러 그룹이 부서로 매핑"(departments)
      · "비공개에선 소유부서 표시 안 함"(permissions)
  G6. 주어·주체 모호한 문장 회피 ("자동 부여되는 권한" — 누가?)(permissions)
  G7. 어색한 직역 헤딩·용어 다듬기 ("## 진입" 등)(personal, permissions)

2) 그룹 규칙  (워크스페이스 한정 — 사실·구조)
  W1. 메인 메뉴 = 화면 "상단"(좌측 아님). 순서: 대시보드 / 탐색 / 스튜디오 / 지식 / 도구
  W2. 대시보드 = 메인 메뉴에만(설정 안에 없음), 역할 무관 노출
  W3. 워크스페이스 설정 진입 = 우측 상단 아바타 → 설정
  W4. 권한 챕터 사이드바 탭 이름 = '개요'
  W5. 개인 설정 = 언어·시간대만 가능. 프로필·로그인 방식 설명 X (사용자는 SSO 계정 로그인뿐)

3) 기존 전역 규칙 누락 → 다른 그룹도 grep 재점검  (이미 있는 규칙인데 새어나옴)
  - #1 SaaS 유료 기능 잔존: model-providers '로드 밸런싱'(원문=유료 기능) → 전 그룹 SaaS grep
  - #6 KC/로그인 서술: 로그인 방식 설명·"외부 시스템 그룹 동기화" 과다 노출 → 점검
  - 결정2 외부연결 제거 잔재: "서드파티 도구 API 키(보안 조치)"(app-mgmt)

4) 확인 필요 → 코드·UI로 사실 재검증  (추측 금지)
  - 역할별 메뉴·기능 노출: model-providers "관리자 이상만" · readme 사용자/부서/감사로그
    메뉴 역할 노출 → A1 분석본·코드 대조
```

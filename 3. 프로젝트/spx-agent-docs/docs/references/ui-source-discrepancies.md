# 화면(UI) ↔ 소스 불일치 카탈로그

> **화면에 보이는 표시가 실제 동작·명칭(코드/소스)과 어긋나는 케이스** 모음. spx-agent 제품 쪽 i18n·라벨 문제라 **문서 작성 시 UI 문구를 그대로 따라가면 안 되는** 지점들.
> 시작: 2026-06-16 (부서 모달 stale 부제 발견 계기). 발견 시 즉시 추가.
>
> **이 문서의 범위**: "화면 ≠ 실제(소스)" — UI 문자열 자체가 stale·오역·미등록·키 재활용인 경우. 반대로 "문서가 화면과 다름"(문서가 UI 라벨을 안 맞춘 번역 오류)은 [[references/translation-verification-report]] 소관이며 여기서 제외.

## 판단 기준

| 구분 | 권위 | 처리 |
|------|------|------|
| 화면 라벨이 **실제 코드 동작과 모순** | 코드 동작 | 문서는 코드 기준으로 작성. UI는 제품 수정 대상 |
| 화면 라벨이 **제품 내 다른 화면의 명칭과 다름**(용어 잔재) | 제품 표준 명칭(글로서리) | 문서는 표준 명칭. 필요 시 "(화면에는 ○○로 표시)" 병기 |
| i18n **미등록/오역** | 영문 원의도 | 문서는 올바른 의미. UI는 i18n 수정 대상 |

## A. 화면 표시가 실제 동작과 모순 (stale)

### A1. 부서/사용자 관리 — 멤버 관리 모달 부제 "한 부서에만"

- **화면**: "이 부서에 속한 구성원을 관리합니다. **한 명은 한 부서에만 속할 수 있어요.**" (EN: "Each member can belong to only one department.")
- **실제(소스)**: **가산형 다중 멤버십** — 한 명이 여러 부서에 속할 수 있고, 모달에서 추가해도 기존 부서에서 빠지지 않음
- **근거**: `members-modal.tsx` L40-43(현재 멤버가 타 부서에도 속할 수 있음 명시), L83-86(`action: 'assign'` = 추가), L225-229 주석 *"adding them here no longer 'moves' them (it's additive)"*, L250-257(다중 소속 배지). A1 §C1 다중 멤버십 마이그레이션(`a7b8c9d0e1f2`)
- **위치**: `web/i18n/{ko-KR,en-US}/common.json` `rbac.department.membersModal.description` 둘째 문장
- **문서 처리**: "한 사용자가 **여러 부서**에 속할 수 있습니다"로 작성 (정확). UI 문구 따라가지 말 것
- **제품 수정**: 둘째 문장 삭제 또는 "여러 부서에 속할 수 있습니다"로 교정 — **미반영**
- 박제: [[references/spx-departments-management]] §3.5

### A2. 워크플로우 통계 — 대화형 i18n 키 재활용 라벨

- **화면**: 모니터링(Analysis) 워크플로우 탭 일부 지표 라벨이 **대화형 앱 지표 라벨을 재활용**해 표시됨 → 워크플로우 실제 지표 의미와 어긋날 수 있음
- **실제(소스)**: 코드가 워크플로우 전용 i18n 키 대신 대화형 키를 끌어다 씀
- **문서 처리**: 문서는 **실제 의미로 서술**(라벨 그대로 옮기지 않음). UI 정정 시 재대조 필요
- **제품 수정**: 미반영. 박제: [[progress-archive]] 2026-06-09 Monitor 작업 deferred ③

## B. 화면 라벨이 제품 표준 명칭과 다름 (용어 잔재)

### B1. 감사로그 — "데이터셋" 라벨 (실제: 지식)

- **화면**: 감사 로그에 "**데이터셋** 생성/삭제" 등으로 표시 (`audit-meta.ts` 한국어 라벨 사전)
- **실제(소스)**: 대상은 **지식 베이스**. 제품의 다른 화면·글로서리는 "**지식**"으로 통일했으나 `audit-meta.ts`만 구 명칭 "데이터셋" 잔존 (DB 테이블명이 `datasets`라 라벨도 그대로 둔 것)
- **위치**: `dify-audit/src/lib/audit-meta.ts` 액션·카테고리 라벨
- **문서 처리**: **옵션 (가) 채택**(2026-06-04) — 글로서리 "지식" 유지 + 감사로그 챕터 본문에 "감사 로그에 '데이터셋'으로 표시되는 항목은 지식 베이스를 의미합니다" 한 줄 안내
- **제품 수정**: 옵션 (나)(`audit-meta.ts` "지식"으로 교체) → **보류(deferred)**
- 박제: [[references/spx-audit-log-analysis]] §10 용어 주의

## C. i18n 미등록·오역 (라벨 자체 부정확)

### C1. 헤더 부서 셀렉터 — i18n 미등록 (fallback)

- **화면**: 드롭다운 헤더 "부서", 필터 해제 "전체"
- **실제(소스)**: `common.departmentSelector.header`·`common.departmentSelector.all` **i18n 키 미등록** → 코드의 `defaultValue` fallback으로 표시 중
- **문서 처리**: "부서"/"전체"로 표기해도 무방(실 표시와 일치). 단 i18n 정식 라벨이 아니므로 추후 변동 가능
- **제품 수정**: en-US/ko-KR i18n 정식 등록 → **미반영**
- 박제: [[references/spx-department-filter-analysis]] §i18n

### C2. List 연산자 — `listFilter.desc` = "설명" (오역 의심)

- **화면**: 정렬 옵션 "설명"
- **실제(소스)**: `desc`는 **내림차순(descending)** 인데 i18n이 "설명(description)"으로 오역했을 가능성
- **문서 처리**: 정렬 맥락이면 "내림차순"이 맞음. UI 재확인 필요(미확정)
- **제품 수정**: i18n 확인 후 교정 대상 — **미확인**
- 박제: [[progress]] Nodes 배치 4 deferred

### C3. Delimiter — 툴팁 vs UI 라벨 내부 불일치

- **화면**: i18n 툴팁은 "구분 기호", 같은 대상 UI 라벨은 "세그먼트 식별자"
- **실제(소스)**: 제품 내부에서 두 표기 혼용
- **문서 처리**: 글로서리 "구분 기호"(i18n 툴팁 기준) 채택. [[conventions]] 글로서리 박제(2026-06-10)
- **제품 수정**: 미반영

### C4. 템플릿 "Customized" — `templates.customized` 오역

- **화면**: "주문을 받아서 만들어진" (Customized 오역)
- **실제(소스)**: 의미는 "사용자 지정"
- **문서 처리**: "사용자 지정"으로 통일 (지식 그룹 검수에서 적용)
- **제품 수정**: i18n 교정 대상 — 미반영. 박제: [[review/07-지식]]

## 운영 메모

- **문서 작성 원칙**: 본 카탈로그에 있는 화면 문구는 **권위가 아님**. UI 라벨 검증([[conventions]] §UI 라벨 검증 절차) 시 이 목록을 먼저 대조.
- **제품 수정 backlog**: A1·B1·C1~C4는 spx-agent 제품 리포 i18n/라벨 수정 대상 (docs 프로젝트 밖). 일괄 정리해 제품팀 전달 가능.
- 신규 발견 시 본 문서에 즉시 추가하고, 해당 분석본에도 교차 박제.

## 실행 방법 — fan-out 서브에이전트

> 핵심 제약: **메인 컨텍스트가 가장 중요한 자원**(Claude Code best-practices). 80여 파일을 메인에서 읽으면 오염 → 서브에이전트로 그룹 분할 위임, 요약만 회수.

### 1단계 — 분할 (fan-out)

그룹별 **읽기 전용** 서브에이전트를 한 메시지에서 병렬로 띄운다. 균형 잡힌 5분할 예시:

| 에이전트 | 담당 |
|---------|------|
| 1 | nodes (23p) |
| 2 | knowledge (18p) |
| 3 | tutorials (14p) |
| 4 | build + debug + getting-started (14p) |
| 5 | publish + monitor + analytics-audit (12p) |

(workspace는 검수 원본이라 보통 선처리.)

### 2단계 — 서브에이전트 프롬프트 템플릿 (grep 패스)

```
spx-agent-docs는 Dify→한국어 포팅 Docusaurus 프로젝트다. 너는 [그룹]만 담당한다.
⚠️ 읽기 전용 — 파일 수정 금지.
대상: <ko 절대경로 디렉토리들> 아래 모든 .mdx (Glob으로 목록 확보)

다음 3개만 찾는다 (i18n·#1~#5는 다른 세션 처리, 중복 금지):
- G3: 모달/다이얼로그/팝업/대화상자/현재 화면에서는 (오탐: 코드블록 내 불가피한 기술용어)
- G1: '제공하지 않습니다/지원하지 않습니다/~는 없습니다'식 기능 부재 명시
       (오탐: '지원하지 않는 파일 형식' 같은 정상 입력/동작 제약)
- #8: 키워드 없이 스민 SaaS 운영 맥락 (익명화·데이터 보호 규정·pricing page)
      부분 제거 원칙 — 제품 실재 정보(토큰 소비·기본값)는 보존, SaaS 맥락만 제거

각 위반: 파일(상대), 라인, 규칙, 현재 문구(짧게), 판정 이유, 수정안.
출력: 마크다운 표. 0건이면 "위반 없음". 확신 낮으면 [낮음]. 장황한 설명 금지.
```

정성 패스(결정11/G6)는 같은 골격에 규칙 정의를 교체 + **오탐 가드 강조**("명백히 빈약한 것만 / 과잉 보강·수정 금지").

### 3단계 — 종합 → 적용

서브에이전트 결과를 한 표로 종합. **확정(명확 위반)** vs **확인 필요(저신뢰·제품 사실 미확정)** 분리. 제품 사실이 걸리면 i18n·제품 코드로 직접 검증(메인에서).

### 4단계 — 빌드 게이트

수정 후 `npm run build` → broken link 0건. 통과해야 종료.

### 5단계 — 적대적 검토 (adversarial review)

수정분을 **새 컨텍스트 서브에이전트**가 `git diff`로 독립 검증:
- 규칙 부합 / 회귀(깨진 흐름·번호·문맥 단절) / 누락(같은 위반 잔존) 3축.
- 작업 에이전트가 자기 채점하지 않게 별도 모델로 반박 시도.

## 오탐·과잉보고 필터 (필수)

> Best-practices 경고: "누락 찾으라 하면 검토자가 과잉 보고 → 과도한 엔지니어링." 모든 발견을 적용하지 말 것.

- **G1 오탐**: 정상 입력/동작 제약("지원하지 않는 형식", "특정 노드는 단일 테스트 불가", deprecation+대안)은 위반 아님.
- **#8 오탐**: 제품 실재 정보(보존 기간·토큰 소비)는 보존, SaaS 수식어만 제거.
- **G3 오탐**: "멀티모달"의 '모달' 부분문자열, 코드블록 내 기술용어.
- **G6 과잉**: 소프트웨어 매뉴얼에서 주체(시스템)가 자명한 피동("저장됩니다", "자동 매핑됩니다")에 "시스템이"를 박는 건 **군더더기**(conventions §피해야 할 패턴 위반). 읽는 사람이 *실제로* 헷갈리는 것만.
- **결정11 과잉**: 이미 3단을 갖췄거나 의미가 자명한 요소에 억지 시나리오 추가 금지.
